Principles of Dynamic Programming

1. Concept

What is Dynamic Programming?

Imagine you're climbing stairs and you want to count how many ways you can reach the top. At each step, you can either take 1 or 2 steps. A naive recursive approach would recalculate the same sub-problems again and again — wasting enormous time. Dynamic Programming (DP) solves this by computing each sub-problem exactly once and storing the result in a table.

Dynamic Programming (DP): An algorithm design paradigm that solves a complex optimization problem by breaking it into overlapping subproblems, solving each subproblem only once, and storing the solutions (in a table) to avoid redundant computation. It applies when the problem has optimal substructure.

Why is it required? Many optimization problems have exponential brute-force solutions. DP reduces this to polynomial time by avoiding recomputation.

Where is it used? Shortest paths (Floyd-Warshall), string matching (LCS), resource allocation (Knapsack), scheduling, bioinformatics (DNA sequence alignment), and more.

2. Theory

Two Key Properties

PropertyMeaningExample
Optimal Substructure An optimal solution to the problem contains optimal solutions to its subproblems Shortest path from A→C via B must use shortest path A→B and shortest path B→C
Overlapping Subproblems The recursive algorithm revisits the same subproblems multiple times Fibonacci: F(5) needs F(4) and F(3); F(4) again needs F(3) — F(3) computed twice!
Theory

Two Approaches to DP

ApproachDirectionHow it worksSpace
Top-Down (Memoization) Recursive, starts from original problem Solve recursively but cache results in a hash map/array. Before computing, check if answer already exists. Uses recursion stack + table
Bottom-Up (Tabulation) Iterative, starts from smallest subproblem Fill a table from base cases upward. Each entry computed from already-solved smaller entries. Uses table only (no recursion stack)
Theory

DP vs Divide-and-Conquer

FeatureDivide-and-ConquerDynamic Programming
SubproblemsIndependent (no overlap)Overlapping (same subproblems recur)
ApproachRecursive — solve and combineTabulate — solve bottom-up or memoize top-down
ExamplesMerge Sort, Quick Sort, Binary SearchKnapsack, MCM, LCS, Floyd-Warshall
RedundancyNo recomputationWithout DP, massive recomputation; DP eliminates it
3. Solved Example

Fibonacci — DP vs Naive Recursion

✅ Classic DP Example: Fibonacci Numbers

Naive Recursive (Exponential):

function Fib(n):
    if n ≤ 1: return n
    return Fib(n-1) + Fib(n-2)
// Time: O(2ⁿ) — exponential! For n=40, this takes billions of operations

Bottom-Up DP (Linear):

function Fib_DP(n):
    F[0] = 0, F[1] = 1
    for i = 2 to n:
        F[i] = F[i-1] + F[i-2]
    return F[n]
// Time: O(n), Space: O(n)

The table stores previously computed values. F(5) needs F(4) and F(3), but both are already in the table — no recomputation!

4. Complexity

Why DP Works

The key insight: if a problem has n distinct subproblems, and each takes O(1) to solve given its sub-subproblems, then DP solves the entire problem in O(n). Without DP, the recursion tree may have O(2ⁿ) nodes because the same subproblems appear exponentially many times.

⚡ Quick Revision Box

  • ✔ DP = Optimal Substructure + Overlapping Subproblems
  • ✔ Two approaches: Top-Down (memoization) vs Bottom-Up (tabulation)
  • ✔ DP ≠ Divide-and-Conquer: D&C has independent subproblems, DP has overlapping
  • ✔ DP transforms exponential recursion into polynomial tabulation
  • ✔ Common mistake: Confusing DP with greedy — DP considers all choices; greedy picks one

Matrix Chain Multiplication (MCM)

1. Concept

What is the Matrix Chain Multiplication Problem?

When multiplying a chain of matrices, the order of multiplication (parenthesization) doesn't change the result but drastically changes the number of scalar multiplications. MCM finds the optimal parenthesization that minimizes the total number of scalar multiplications.

MCM Problem: Given a chain of n matrices <A₁, A₂, …, Aₙ> where matrix Aᵢ has dimensions pᵢ₋₁ × pᵢ, determine the parenthesization that minimizes the total number of scalar multiplications.

Real-world intuition: Think of matrix multiplication as a "cost" — multiplying a 10×30 matrix with a 30×5 matrix costs 10×30×5 = 1500 operations. If we have three matrices and choose the wrong order, we might do 10× more work!

2. Theory

Why Brute Force Fails

The number of different parenthesizations of n matrices is given by the Catalan number C(n-1), which grows exponentially: C(n) = Ω(4ⁿ/n^(3/2)). For n=10 matrices, there are 4862 parenthesizations. Checking all is infeasible.

Theory

The DP Recurrence

Let m[i,j] = minimum number of scalar multiplications needed to compute Aᵢ × Aᵢ₊₁ × … × Aⱼ.

m[i, j] = 0    if i = j (single matrix, no multiplication needed)

m[i, j] = mini≤k<j { m[i,k] + m[k+1,j] + pi-1 · pk · pj }    if i < j

Intuition: We try every possible split point k between i and j. Splitting at k means: multiply Aᵢ..Aₖ (cost m[i,k]), then multiply Aₖ₊₁..Aⱼ (cost m[k+1,j]), then multiply the two resulting matrices (cost pᵢ₋₁ · pₖ · pⱼ). We pick the k that gives minimum total cost.

We also maintain s[i,j] = k to record the optimal split point for backtracking the parenthesization.

3. Algorithm

MCM Pseudocode (Bottom-Up)

MATRIX-CHAIN-ORDER(p, n):
    // p[0..n] = dimensions array, n matrices
    let m[1..n, 1..n] and s[1..n-1, 2..n] be new tables
    
    for i = 1 to n:
        m[i, i] = 0          // base case: single matrix
    
    for l = 2 to n:        // l = chain length
        for i = 1 to n - l + 1:
            j = i + l - 1
            m[i, j] = ∞
            for k = i to j - 1:
                q = m[i, k] + m[k+1, j] + p[i-1] · p[k] · p[j]
                if q < m[i, j]:
                    m[i, j] = q
                    s[i, j] = k
    
    return m, s

Complete Worked Example

✅ Example: Matrices with dimensions p = {5, 4, 6, 2, 7}

This gives 4 matrices: A₁(5×4), A₂(4×6), A₃(6×2), A₄(2×7)

Longest Common Subsequence (LCS)

1. Concept

What is the LCS Problem?

A subsequence of a string is obtained by deleting zero or more characters from the string without changing the relative order of the remaining characters. For example, "ACE" is a subsequence of "ABCDE" (delete B and D), but "AEC" is not (order changed).

LCS Problem: Given two sequences X = <x₁, x₂, …, xₘ> and Y = <y₁, y₂, …, yₙ>, find the length of the longest subsequence that is common to both X and Y.

Real-world usage:

  • Bioinformatics: Comparing DNA/protein sequences to find evolutionary similarity
  • Version control: The diff tool uses LCS to show changes between file versions
  • Spell checking: Measuring string similarity
2. Theory

Optimal Substructure of LCS

Let X = <x₁, …, xₘ> and Y = <y₁, …, yₙ>, and let Z = <z₁, …, zₖ> be any LCS of X and Y.

  1. If xₘ = yₙ, then zₖ = xₘ = yₙ, and Z[1..k-1] is an LCS of X[1..m-1] and Y[1..n-1]
  2. If xₘ ≠ yₙ and zₖ ≠ xₘ, then Z is an LCS of X[1..m-1] and Y
  3. If xₘ ≠ yₙ and zₖ ≠ yₙ, then Z is an LCS of X and Y[1..n-1]
Theory

The DP Recurrence

Let c[i,j] = length of LCS of X[1..i] and Y[1..j]:

c[i, j] = 0    if i = 0 or j = 0

c[i, j] = c[i-1, j-1] + 1    if xi = yj

c[i, j] = max(c[i-1, j], c[i, j-1])    if xi ≠ yj

Intuition: If the last characters match, they must be part of the LCS — so add 1 and look at the remaining prefixes. If they don't match, the LCS either doesn't include xₘ or doesn't include yₙ — take the better of the two.

3. Algorithm

LCS Pseudocode (Bottom-Up)

LCS-LENGTH(X, Y):
    m = length(X), n = length(Y)
    let c[0..m, 0..n] be a new table
    
    for i = 0 to m: c[i, 0] = 0    // first column = 0
    for j = 0 to n: c[0, j] = 0    // first row = 0
    
    for i = 1 to m:
        for j = 1 to n:
            if X[i] == Y[j]:
                c[i, j] = c[i-1, j-1] + 1
                b[i, j] = "↖"           // diagonal arrow
            else if c[i-1, j] ≥ c[i, j-1]:
                c[i, j] = c[i-1, j]
                b[i, j] = "↑"           // up arrow
            else:
                c[i, j] = c[i, j-1]
                b[i, j] = "←"           // left arrow
    
    return c, b

PRINT-LCS(b, X, i, j):
    if i == 0 or j == 0: return
    if b[i, j] == "↖":
        PRINT-LCS(b, X, i-1, j-1)
        print X[i]
    else if b[i, j] == "↑":
        PRINT-LCS(b, X, i-1, j)
    else:
        PRINT-LCS(b, X, i, j-1)

Optimal Binary Search Trees (OBST)

1. Concept

What is an Optimal BST?

In a standard Binary Search Tree (BST), search time depends on the tree's shape. If some keys are searched more often than others, we want to arrange the tree so that frequently searched keys are near the root. An Optimal BST minimizes the expected search cost given known probabilities of searching for each key.

Optimal BST Problem: Given n sorted keys k₁ < k₂ < … < kₙ with search probabilities p₁, p₂, …, pₙ (and possibly dummy key probabilities q₀, q₁, …, qₙ for unsuccessful searches), construct the BST that minimizes the expected search cost:
E[search cost] = Σᵢ (depth(kᵢ) + 1) · pᵢ

Real-world intuition: Think of a dictionary app. The word "the" is searched millions of times more than "zephyr". An optimal BST puts "the" closer to the root and "zephyr" deep in the tree.

2. Theory

Why Greedy Doesn't Work Here

You might think: "Just put the most probable key at the root!" But this greedy approach fails because it doesn't account for how the remaining keys are distributed in the subtrees. DP considers ALL possible root choices and picks the best.

Theory

The DP Recurrence

Let e[i,j] = expected cost of an optimal BST containing keys kᵢ through kⱼ. Let w[i,j] = sum of probabilities from kᵢ to kⱼ (the "weight" of that subtree).

e[i, j] = 0    if j = i - 1 (empty tree)

w[i, j] = w[i, j-1] + pj (cumulative weight)

e[i, j] = mini≤r≤j { e[i, r-1] + e[r+1, j] + w[i, j] }    if i ≤ j

Intuition: Try every key kᵣ (i ≤ r ≤ j) as the root. The cost is: left subtree cost + right subtree cost + w[i,j] (because every node in this subtree has its depth increased by 1 when it becomes a subtree of r).

3. Algorithm

OBST Pseudocode

OPTIMAL-BST(p, n):
    let e[1..n+1, 0..n], w[1..n+1, 0..n], root[1..n, 1..n] be new tables
    
    // Base cases: empty trees
    for i = 1 to n+1:
        e[i, i-1] = 0
        w[i, i-1] = 0
    
    for l = 1 to n:          // l = number of keys
        for i = 1 to n - l + 1:
            j = i + l - 1
            e[i, j] = ∞
            w[i, j] = w[i, j-1] + p[j]
            for r = i to j:     // try each key as root
                t = e[i, r-1] + e[r+1, j] + w[i, j]
                if t < e[i, j]:
                    e[i, j] = t
                    root[i, j] = r
    
    return e, root
4. Solved Example

Complete Worked Example

✅ Example: Keys {k₁, k₂, k₃} with probabilities p = {0.3, 0.2, 0.5}

n = 3 keys: k₁ with probability 0.3, k₂ with 0.2, k₃ with 0.5.

Step 1: Base cases and weights:

e[1,0] = e[2,1] = e[3,2] = e[4,3] = 0

Step 2: l = 1 (single keys):

  • e[1,1]: w[1,1] = 0.3. Only r=1: e[1,0] + e[2,1] + 0.3 = 0 + 0 + 0.3 = 0.3. root[1,1] = 1
  • e[2,2]: w[2,2] = 0.2. Only r=2: 0 + 0 + 0.2 = 0.2. root[2,2] = 2
  • e[3,3]: w[3,3] = 0.5. Only r=3: 0 + 0 + 0.5 = 0.5. root[3,3] = 3

Step 3: l = 2 (two keys):

  • e[1,2]: w[1,2] = 0.3 + 0.2 = 0.5
    • r=1: e[1,0] + e[2,2] + 0.5 = 0 + 0.2 + 0.5 = 0.7 ✓ min
    • r=2: e[1,1] + e[3,2] + 0.5 = 0.3 + 0 + 0.5 = 0.8
    e[1,2] = 0.7, root[1,2] = 1
  • e[2,3]: w[2,3] = 0.2 + 0.5 = 0.7
    • r=2: e[2,1] + e[3,3] + 0.7 = 0 + 0.5 + 0.7 = 1.2
    • r=3: e[2,2] + e[4,3] + 0.7 = 0.2 + 0 + 0.7 = 0.9 ✓ min
    e[2,3] = 0.9, root[2,3] = 3

Step 4: l = 3 (all three keys):

  • e[1,3]: w[1,3] = 0.3 + 0.2 + 0.5 = 1.0
    • r=1: e[1,0] + e[2,3] + 1.0 = 0 + 0.9 + 1.0 = 1.9
    • r=2: e[1,1] + e[3,3] + 1.0 = 0.3 + 0.5 + 1.0 = 1.8
    • r=3: e[1,2] + e[4,3] + 1.0 = 0.7 + 0 + 1.0 = 1.7 ✓ min
    e[1,3] = 1.7, root[1,3] = 3

Optimal Tree Structure: root[1,3]=3 means k₃ is the root. Its left subtree has keys {k₁, k₂} with root[1,2]=1, so k₁ is left child of k₃. k₂ is right child of k₁.

        k₃ (0.5)
       /
      k₁ (0.3)
        \
         k₂ (0.2)

Expected cost = 0.5×1 + 0.3×2 + 0.2×3 = 0.5 + 0.6 + 0.6 = 1.7 ✓

Time & Space Analysis

Time
O(n³)
Space
O(n²)

Three nested loops give O(n³). Knuth's optimization uses the monotonicity of root[i,j] to reduce to O(n²).

⚡ Quick Revision Box

  • ✔ OBST minimizes expected search cost, not worst-case search cost
  • ✔ Recurrence: e[i,j] = min over r of {e[i,r-1] + e[r+1,j] + w[i,j]}

  • ✔ Time: O(n³), Space: O(n²)
  • ✔ Greedy (highest probability = root) DOES NOT work for OBST
  • ✔ Common mistake: Forgetting to add w[i,j] to the cost formula

Greedy Technique — Principles & Comparison with DP

1. Concept

What is the Greedy Technique?

Imagine you're at a buffet and you want to maximize the total tastiness of food on your plate. A greedy person would always pick the tastiest item available right now, without thinking about whether saving space for a later dish might give a better overall result. Sometimes this works perfectly (activity selection), and sometimes it doesn't (0/1 knapsack).

Greedy Algorithm: An algorithm design paradigm that builds a solution piece-by-piece, always choosing the option that looks best at the current moment (locally optimal), hoping this leads to a globally optimal solution. It never reconsiders past choices.
2. Theory

Two Properties Required for Greedy to Work

PropertyMeaning
Greedy Choice Property A globally optimal solution can be arrived at by making locally optimal (greedy) choices. You don't need to look at all possibilities — the local best IS part of the global best.
Optimal Substructure Same as DP — an optimal solution contains optimal solutions to subproblems.
Theory

Greedy vs Dynamic Programming

⚠ IMPORTANT — This comparison is frequently asked (5–7 marks)!
FeatureGreedyDynamic Programming
ChoiceMakes ONE locally optimal choice at each stepConsiders ALL possible choices at each step
DirectionTop-down (makes choice, then solves subproblem)Bottom-up (solves all subproblems first)
BacktrackingNever revisits decisionsConsiders all options before deciding
OptimalityNot always optimal — only when greedy-choice property holdsAlways optimal (when applicable)
SpeedGenerally faster (fewer choices to consider)Generally slower (examines all subproblems)
ExamplesHuffman, Kruskal, Prim, Dijkstra, Activity SelectionMCM, LCS, OBST, 0/1 Knapsack, Floyd-Warshall

⚡ Quick Revision Box

  • ✔ Greedy = locally optimal choices → globally optimal (when greedy-choice property holds)
  • ✔ Greedy is FASTER but LESS GENERAL than DP
  • ✔ Greedy WORKS for: fractional knapsack, Huffman, MST, shortest paths (non-negative weights)
  • ✔ Greedy FAILS for: 0/1 knapsack, MCM, general shortest paths (negative weights)
  • ✔ Common mistake: Assuming greedy always gives optimal — it doesn't!

Activity Selection Problem

1. Concept

What is the Activity Selection Problem?

You have a single room (or a single machine) and multiple activities (classes, meetings, jobs) each with a start time and finish time. Two activities conflict if they overlap in time. The goal: select the maximum number of non-overlapping activities.

Activity Selection Problem: Given n activities with start times s₁, s₂, …, sₙ and finish times f₁, f₂, …, fₙ, select the largest set of mutually compatible (non-overlapping) activities.

Real-world usage: Scheduling classes in a single classroom, scheduling jobs on a machine, booking meeting rooms.

2. Theory

The Greedy Strategy

The key insight: always select the activity that finishes earliest (among remaining compatible activities). This leaves the most room for future activities.

Why "earliest finish time" works: By finishing as early as possible, you maximize the remaining time available for other activities. This is provably optimal (can be shown by exchange argument / greedy stays ahead proof).
3. Algorithm

Activity Selection Pseudocode

Huffman Codes

🔥 VERY IMPORTANT — ASKED IN 3 PAPERS!

SEE 2024 Q6(b) — Huffman Coding construction and encoding/decoding [10 marks]

SEE 2023(O) Q5(c) — Huffman Coding construction [10 marks]

Exact PYQ Data: A=0.4, B=0.1, C=0.2, D=0.14, E=0.16

Encode: ABACABAD, Decode: 100010111001010

1. Concept

What is Huffman Coding?

Huffman coding is a lossless data compression technique that assigns variable-length binary codes to characters based on their frequencies. More frequent characters get shorter codes, less frequent characters get longer codes — resulting in optimal compression.

Huffman Coding: A greedy algorithm that constructs an optimal prefix-free binary code, where no code is a prefix of another code. It builds a binary tree bottom-up by repeatedly combining the two least-frequent nodes.

Why prefix-free? If 'A' = "01" and 'B' = "010", then the encoded string "010" is ambiguous — is it "AB" or "B"? Prefix-free codes prevent this ambiguity.

2. Theory

Huffman Algorithm Steps

1
Create leaf nodes for each character with its frequency/probability. Put all nodes in a min-priority queue (sorted by frequency).
2
Extract two minimum frequency nodes from the queue.
3
Create a new internal node with frequency = sum of the two extracted nodes. Make the two extracted nodes its left and right children.
4
Insert the new node back into the priority queue.
5
Repeat steps 2–4 until only one node remains (the root).
6
Assign codes: Traverse the tree. Left edge = 0, Right edge = 1. The code for each character is the sequence of 0s and 1s from root to that leaf.
3. Algorithm

Huffman Pseudocode

HUFFMAN(C):
    // C = set of characters with frequencies
    n = |C|
    Q = min-priority queue of C     // sorted by frequency
    
    for i = 1 to n - 1:
        z = new internal node
        z.left = x = EXTRACT-MIN(Q)
        z.right = y = EXTRACT-MIN(Q)
        z.freq = x.freq + y.freq
        INSERT(Q, z)
    
    return EXTRACT-MIN(Q)           // root of Huffman tree

🔥 MOST IMPORTANT — ASKED IN ALL 5 PAPERS!

1. Concept

What is a Minimum Spanning Tree (MST)?

Spanning Tree: A subgraph of an undirected connected graph that connects all vertices with the minimum possible number of edges (exactly V-1 edges) and no cycles.

Minimum Spanning Tree (MST): A spanning tree whose total edge weight is the smallest among all possible spanning trees.

Real-world usage: Network design (connect all cities with minimum cable), circuit design, clustering, and approximation algorithms for TSP.

2. Theory

Kruskal's Strategy

Kruskal's algorithm is edge-based. It processes edges in order of increasing weight and adds each edge to the MST if it doesn't create a cycle.

1
Sort all edges by weight in ascending order.
2
Initialize: Each vertex is its own component (forest of single-node trees). Use Disjoint Set / Union-Find data structure.
3
For each edge (u, v) in sorted order: If FIND-SET(u) ≠ FIND-SET(v), add edge to MST and UNION(u, v). Otherwise, skip (would create cycle).
4
Stop when MST has exactly V-1 edges.
3. Algorithm

Kruskal's Pseudocode

KRUSKAL-MST(G):
    A = ∅                          // MST edges
    for each vertex v ∈ G.V:
        MAKE-SET(v)                // each vertex is its own set
    
    Sort edges of G by weight in ascending order
    
    for each edge (u, v) in sorted order:
        if FIND-SET(u) ≠ FIND-SET(v):
            A = A ∪ {(u, v)}       // add edge to MST
            UNION(u, v)            // merge components
    
    return A

Minimum Spanning Trees — Prim's Algorithm

1. Concept

What is Prim's Algorithm?

While Kruskal's is edge-based (globally sorted), Prim's is vertex-based. It grows a single tree from a starting vertex by always adding the cheapest edge that connects a tree vertex to a non-tree vertex.

Prim's Algorithm: Start from any vertex. Maintain a "tree set" and repeatedly add the minimum-weight edge crossing the boundary between tree vertices and non-tree vertices until all vertices are included.

Analogy: Think of Prim's as growing a crystal — you start with a seed and keep adding the nearest atom. Kruskal's is like picking up scattered puzzle pieces from lightest to heaviest.

2. Theory

Prim's Pseudocode

PRIM-MST(G, w, r):
    // r = starting vertex
    for each vertex u ∈ G.V:
        u.key = ∞              // minimum weight edge to tree
        u.π = NIL              // parent in MST
    r.key = 0
    Q = min-priority queue of all V vertices (keyed by u.key)

                v.π = u        // update parent
                v.key = w(u,v) // update key (DECREASE-KEY)
    
    return {(v, v.π) : v ∈ V - {r}}  // MST edges

1. Concept

What is Dijkstra's Algorithm?

Dijkstra's algorithm finds the shortest path from a single source vertex to all other vertices in a weighted graph with non-negative edge weights.

Dijkstra's Algorithm: A greedy algorithm that maintains a set S of vertices whose final shortest-path weights have been determined. It repeatedly selects the vertex u ∉ S with the minimum distance estimate, adds it to S, and relaxes all edges leaving u.

Real-world usage: GPS navigation (shortest route), network routing protocols (OSPF), and any problem requiring shortest distances in non-negative weighted graphs.

⚠ Dijkstra does NOT work with negative edge weights! For graphs with negative weights, use Bellman-Ford algorithm instead.
2. Theory

Key Concept: Edge Relaxation

Relaxation is the fundamental operation. For edge (u, v) with weight w(u, v):

if d[v] > d[u] + w(u, v):
    d[v] = d[u] + w(u, v)    // update shortest distance
    π[v] = u               // update predecessor

Intuition: If going through u gives a shorter path to v than what we currently know, update v's distance.

Theory

Dijkstra's vs Prim's — They Look Similar!

3. Algorithm

Dijkstra's Pseudocode

DIJKSTRA(G, w, s):
    // Initialize
    for each vertex v ∈ G.V:
        d[v] = ∞
        π[v] = NIL
    d[s] = 0
    
    S = ∅                          // set of processed vertices
    Q = G.V                        // min-priority queue
    
    while Q ≠ ∅:
        u = EXTRACT-MIN(Q)         // vertex with smallest d[u]
        S = S ∪ {u}
        for each vertex v adjacent to u:
            if d[v] > d[u] + w(u, v):  // RELAX
                d[v] = d[u] + w(u, v)
                π[v] = u
                DECREASE-KEY(Q, v, d[v])
    
    return d, π
