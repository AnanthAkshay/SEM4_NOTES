TOPIC 1 The Heap Data Structure

Foundation of HeapSort and Priority Queues · O(log n) operations
1. Concept Introduction

A heap is a clever data structure that answers the question: "Give me the largest (or smallest) element instantly, while still being able to maintain a large collection efficiently."


Think of it like a tournament bracket — the winner (root) is always the best. When you remove the winner, the bracket reorganizes quickly to find the next winner. This is why heaps are used in:

  • HeapSort — efficient O(n log n) sorting
  • Priority Queues — OS scheduling, Dijkstra's, Prim's algorithms
  • Selection algorithms — finding k-th largest element
2. Detailed Theory

Definition: A (binary) heap is a nearly-complete binary tree stored as an array such that a specific ordering property holds.

MAX-HEAP Property

For every node i other than the root:

A[PARENT(i)] ≥ A[i]

The largest element is at the root. Used in HeapSort and Max-Priority Queue.

MIN-HEAP Property

For every node i other than the root:

A[PARENT(i)] ≤ A[i]

The smallest element is at the root. Used in Min-Priority Queue, Dijkstra's.

Array Representation

The heap is stored as a 1D array. For a node at index i (1-indexed):

Operation1-Indexed Formula0-Indexed Formula

📝 Important Property
In an n-element heap, the leaves are at nodes ⌊n/2⌋+1, ⌊n/2⌋+2, ..., n. The non-leaf nodes (which need heapifying) are indices 1 to ⌊n/2⌋ (1-indexed) or 0 to ⌊n/2⌋−1 (0-indexed).
3. Algorithms & Pseudocode
ALGORITHM 1 — MAX-HEAPIFY(A, i, n)
// Maintains the max-heap property for subtree rooted at node i // Assumes LEFT(i) and RIGHT(i) sub-trees are valid max-heaps // Time: O(log n) MAX-HEAPIFY(A, i, n): l ← LEFT(i) // 2i (1-indexed) or 2i+1 (0-indexed) r ← RIGHT(i) // 2i+1 (1-indexed) or 2i+2 (0-indexed) // Find largest among A[i], A[l], A[r] if l ≤ n and A[l] > A[i] largest ← l else largest ← i if r ≤ n and A[r] > A[largest] largest ← r if largest ≠ i // If root is NOT the largest swap A[i] ↔ A[largest] // Move largest up MAX-HEAPIFY(A, largest, n) // Fix the affected sub-tree
ALGORITHM 2 — BUILD-MAX-HEAP(A, n)
// Builds a max-heap from an arbitrary array A[1..n] // Key insight: Start from last non-leaf and heapify upward // Time: O(n) — not O(n log n)! (tighter analysis shows sum of heights) BUILD-MAX-HEAP(A, n): for i ← ⌊n/2⌋ downto 1 // From last non-leaf to root MAX-HEAPIFY(A, i, n) // For 0-indexed: loop from i = ⌊n/2⌋-1 downto 0

5. Complexity Analysis
MAX-HEAPIFY
O(log n)
Height of tree
BUILD-MAX-HEAP Time
O(n)
Tight analysis (not O(n log n))
Space
O(1)
In-place
Why BUILD-MAX-HEAP is O(n) not O(n log n)
Most nodes are near the bottom. Leaves do O(1) work. Nodes at height h do O(h) work. The sum Σ (n/2^h · h) for h=0 to log n converges to O(n). This is the mathematical reason we call BUILD-MAX-HEAP O(n).

⚡ Quick Revision — Heap

  • MAX-HEAP: every parent ≥ children; root = maximum element
  • Array rep: PARENT=⌊i/2⌋, LEFT=2i, RIGHT=2i+1 (1-indexed)
  • Last non-leaf (0-indexed) = ⌊n/2⌋ − 1
  • MAX-HEAPIFY: O(log n) · BUILD-MAX-HEAP: O(n)
  • Build-Heap loops from ⌊n/2⌋ DOWN to 1 (not 1 up to n)
  • Common mistake: confusing 0-indexed vs 1-indexed formulas — be consistent!

TOPIC 2 HeapSort

O(n log n) worst-case · In-place · Not stable
1. Concept Introduction

HeapSort combines the best of both worlds: the O(n log n) worst-case guarantee of MergeSort with the in-place space efficiency of QuickSort. The idea is elegant:

1
Build a Max-Heap from the input array — O(n)
2
The root A[0] is now the maximum. Swap it with the last element.
3
Reduce heap size by 1 (the last element is now in its sorted position).
4
Call MAX-HEAPIFY on the new root to restore heap property — O(log n)
5
Repeat steps 2–4 for n−1 iterations. Total: O(n log n)
3. Algorithm & Pseudocode
ALGORITHM — HEAPSORT(A, n)
HEAPSORT(A, n): BUILD-MAX-HEAP(A, n) // Step 1: Build heap — O(n) for i ← n downto 2 // n-1 iterations swap A[1] ↔ A[i] // Move max to sorted position heap_size ← heap_size − 1 // Shrink heap MAX-HEAPIFY(A, 1, heap_size) // Restore heap — O(log i) // For 0-indexed: swap A[0] with A[i], call MAX-HEAPIFY(A, 0, heap_size)

⚠️ HeapSort vs QuickSort
HeapSort guarantees O(n log n) worst-case. QuickSort averages O(n log n) but can degrade to O(n²). However, QuickSort has better cache performance in practice, so it's often faster on real systems despite the theoretical guarantee.

⚡ Quick Revision — HeapSort

  • Phase 1: Build Max-Heap O(n) · Phase 2: n−1 extractions × O(log n) each
  • Total: O(n log n) — Best, Average AND Worst case
  • In-place (O(1) extra space) · NOT stable
  • In Phase 2, always swap root (max) with LAST element of current heap
  • Common mistake: forgetting to reduce heap_size after each swap
  • Result: elements sorted in ASCENDING order (max is placed at end first)

TOPIC 3 Priority Queue

Heap-based · O(log n) insert and extract · Used in Dijkstra, scheduling
1. Concept Introduction

A Priority Queue is an ADT (Abstract Data Type) where each element has a priority and the element with the highest (or lowest) priority is always served first — regardless of insertion order. Think of an emergency room: a critical patient is treated before a regular check-up, regardless of who arrived first.

MAX Priority Queue

Extracts the maximum element. Built on Max-Heap. Operations:
EXTRACT-MAX, INSERT, MAXIMUM, INCREASE-KEY

MIN Priority Queue

Extracts the minimum element. Built on Min-Heap. Used in Dijkstra's shortest path, Prim's MST, Huffman coding.

3. Algorithms — Max-Priority Queue Operations
MAX-PRIORITY QUEUE — FOUR KEY OPERATIONS
// 1. HEAP-MAXIMUM — Return max without removing HEAP-MAXIMUM(A): return A[1] // Just read root — O(1) // 2. HEAP-EXTRACT-MAX — Remove and return max HEAP-EXTRACT-MAX(A, n): if n < 1: error "heap underflow" max ← A[1] // Save the max A[1] ← A[n] // Move last to root n ← n − 1 // Shrink heap MAX-HEAPIFY(A, 1, n) // Restore heap — O(log n) return max // 3. HEAP-INCREASE-KEY — Increase priority of element at index i HEAP-INCREASE-KEY(A, i, key): if key < A[i]: error "new key smaller than current" A[i] ← key while i > 1 and A[PARENT(i)] < A[i] swap A[i] ↔ A[PARENT(i)] // Bubble up i ← PARENT(i) // Move up — O(log n) // 4. MAX-HEAP-INSERT — Insert new element MAX-HEAP-INSERT(A, key, n): n ← n + 1 A[n] ← −∞ // Place -infinity at new leaf HEAP-INCREASE-KEY(A, n, key) // Increase to actual key — O(log n)
5. Complexity Analysis
HEAP-MAXIMUM
O(1)
EXTRACT-MAX
O(log n)

O(log n)

O(log n)

⚡ Quick Revision — Priority Queue

  • PQ is an ADT; Heap is the implementation
  • EXTRACT-MAX: move last element to root → HEAPIFY down
  • INSERT: add at leaf → BUBBLE UP (INCREASE-KEY)
  • All operations: O(log n) except MAXIMUM → O(1)
  • Applications: Dijkstra (min-PQ), HeapSort, OS Scheduling, Huffman

TOPIC 4 QuickSort

🔥 Appears in EVERY paper · Divide & Conquer · Average O(n log n)
1. Concept Introduction

QuickSort is the fastest sorting algorithm in practice for general-purpose sorting. It works on the divide-and-conquer paradigm with one brilliant insight:

💡 Core Idea
Pick one element as the pivot. Rearrange the array so that all elements smaller than pivot come before it, and all elements greater than pivot come after it. The pivot is now in its final sorted position. Recursively sort the two subarrays.

Why is it used everywhere?

  • In-place sorting (O(log n) stack space on average)
  • Excellent cache performance (accesses contiguous memory)
  • Average case O(n log n) which beats MergeSort's constants in practice
  • Used in Java Arrays.sort(), C++ std::sort(), Python's Timsort (hybrid)
2. Detailed Theory — Partition Algorithm

The heart of QuickSort is the PARTITION function. Lomuto partition (textbook) uses the last element as pivot:

LOMUTO PARTITION(A, p, r)
// Partitions A[p..r] around pivot x = A[r] // Returns final position of pivot // Time: O(r-p+1) = O(n) for subarray of size n PARTITION(A, p, r): x ← A[r] // pivot = last element i ← p − 1 // i = boundary of "≤ pivot" zone for j ← p to r − 1 // scan left portion if A[j] ≤ x // element belongs in "≤ pivot" zone i ← i + 1 swap A[i] ↔ A[j] swap A[i+1] ↔ A[r] // Place pivot in correct position return i + 1 // Return pivot index QUICKSORT(A, p, r): if p < r q ← PARTITION(A, p, r) // q = pivot's final position QUICKSORT(A, p, q−1) // Sort left of pivot QUICKSORT(A, q+1, r) // Sort right of pivot
📘 Hoare Partition (First Element as Pivot)
Many MSRIT questions use the first element as pivot. In this case: pivot = A[p], use two pointers i=p+1 and j=r scanning inward, swap when A[i]>pivot and A[j]≤pivot, stop when i>j, swap pivot with A[j]. This is the Hoare-style partition shown in the examples below.

TOPIC 5 Counting Sort

Linear Time O(n+k) · Non-comparison · Stable · Integer keys only
1. Concept Introduction

All comparison-based sorting algorithms (QuickSort, MergeSort, HeapSort) have a theoretical lower bound of Ω(n log n). But what if we cheat? What if we exploit extra information about the input?

Counting Sort breaks the O(n log n) barrier by assuming integer keys in range [0, k]. Instead of comparing elements, it counts how many times each value appears, then places each element directly into its sorted position.

📝 Key Assumption
Input: n integers where each element is in range [0..k]. If k = O(n), then Counting Sort runs in O(n) time. It is the building block for Radix Sort.
3. Algorithm & Pseudocode
ALGORITHM — COUNTING-SORT(A, B, n, k)
// A[0..n-1] = input, B[0..n-1] = output, k = max value // C[0..k] = counting array COUNTING-SORT(A, B, n, k): // Step 1: Initialize count array to 0 let C[0..k] be a new array for i ← 0 to k C[i] ← 0 // Step 2: Count occurrences of each value for j ← 0 to n−1 C[A[j]] ← C[A[j]] + 1 // C[i] now = number of elements equal to i // Step 3: Compute prefix sums (cumulative counts) for i ← 1 to k C[i] ← C[i] + C[i−1] // C[i] now = number of elements ≤ i (= position of last i in output) // Step 4: Place elements into output (reverse for stability) for j ← n−1 downto 0 B[C[A[j]] − 1] ← A[j] C[A[j]] ← C[A[j]] − 1 // (iterating in reverse maintains stability)

TOPIC 6 Radix Sort

O(d·(n+k)) · Digit-by-digit sorting · Stable · Used in card sorting
1. Concept Introduction

Imagine sorting a deck of punched cards by multiple columns. A human card sorter would sort on the least significant digit first, then the next digit, and so on. Radix Sort does exactly this algorithmically.

💡 Key Idea
Sort by digits from Least Significant Digit (LSD) to Most Significant Digit (MSD), using a stable sort (Counting Sort) at each digit position. After all d passes, the array is sorted.
3. Algorithm & Pseudocode
ALGORITHM — RADIX-SORT(A, n, d)
// A = array of n d-digit integers // Each digit in range [0..k], typically k=9 for decimal RADIX-SORT(A, n, d): for i ← 1 to d // For each digit position (LSD first) Use a stable sort to sort A on digit i // Stable sort = Counting Sort on digit i // Extract digit i of A[j] = (A[j] / 10^(i-1)) mod 10
4. Solved Example

TOPIC 7 Bucket Sort

Bucket Sort assumes input is drawn from a uniform distribution over [0, 1). The idea: divide [0,1) into n equal-sized buckets, throw each element into the corresponding bucket, sort each bucket, then concatenate.

3. Algorithm & Pseudocode

// Input: A[0..n-1] where 0 ≤ A[i] < 1 // Each bucket = linked list BUCKET-SORT(A, n): let B[0..n−1] be new array of empty lists (buckets) // Step 1: Distribute elements into buckets for i ← 0 to n−1 insert A[i] into bucket B[⌊n · A[i]⌋] // Step 2: Sort each bucket (insertion sort) for i ← 0 to n−1 sort list B[i] with INSERTION-SORT // Step 3: Concatenate all buckets concatenate lists B[0], B[1], ..., B[n−1] in order

TOPIC 8 Order Statistics & Selection Algorithms

Finding k-th smallest element · Randomized Select O(n) avg · Median-of-Medians O(n) worst
1. Concept Introduction

The i-th order statistic of a set of n numbers is the i-th smallest number. Special cases:

  • Minimum = 1st order statistic (i=1)
  • Maximum = n-th order statistic (i=n)
  • Median = ⌊(n+1)/2⌋-th order statistic
📝 The Selection Problem
Input: A set of n numbers and an integer i (1 ≤ i ≤ n)
Output: The element x that is larger than exactly i−1 other elements
Naive approach: Sort (O(n log n)) and return the i-th element. Can we do better?

YES! Using a partition-based approach (like QuickSort's partition), we can solve this in O(n) average time.

2. Finding Min and Max
MINIMUM(A, n) — O(n)
MINIMUM(A, n): min ← A[0] for i ← 1 to n−1 if A[i] < min min ← A[i] return min // Comparisons: n-1 (optimal for finding just min or max) // SIMULTANEOUS MIN & MAX — uses only ~3n/2 comparisons instead of 2n MIN-MAX(A, n): Process elements in pairs: compare A[i] vs A[i+1] first → larger goes to "potential max" candidates → smaller goes to "potential min" candidates Then find max among max-candidates and min among min-candidates // Total: 3⌊n/2⌋ comparisons
3. Randomized Selection (RANDOMIZED-SELECT)
ALGORITHM — RANDOMIZED-SELECT(A, p, r, i)
// Returns the i-th smallest element of A[p..r] // Uses random pivot for partition RANDOMIZED-SELECT(A, p, r, i): if p == r // Only one element return A[p] q ← RANDOMIZED-PARTITION(A, p, r) k ← q − p + 1 // k = pivot's rank within A[p..r] if i == k // Pivot IS the i-th smallest return A[q] elseif i < k // i-th smallest is in LEFT subarray return RANDOMIZED-SELECT(A, p, q−1, i) else // i-th smallest is in RIGHT subarray return RANDOMIZED-SELECT(A, q+1, r, i−k)

5. Worst-Case Linear Selection — Median of Medians
📘 SELECT Algorithm — O(n) Worst Case
RANDOMIZED-SELECT is O(n) on average but can be O(n²) in the worst case. The deterministic SELECT algorithm (Median of Medians) guarantees O(n) worst case.
SELECT ALGORITHM — Steps (Median of Medians)
Step 1: Divide the n elements into groups of 5 (last group may be < 5). → ⌈n/5⌉ groups total. Step 2: Find the median of each group by sorting (5 elements → O(1)). → ⌈n/5⌉ medians. Step 3: Recursively call SELECT to find the median x of the ⌈n/5⌉ medians. → x is a good pivot (guarantees ≥ 3n/10 elements below & above). Step 4: Partition the array around x. Step 5: Recurse on the appropriate subarray. // Recurrence: T(n) ≤ T(n/5) + T(7n/10) + O(n) // Solution: T(n) = O(n)
4b. Solved Example — Order Statistics

Group 1: [12, 3, 7, 19, 5] → sorted [3,5,7,12,19] → median = 7
Group 2: [1, 14, 8, 11, 2] → sorted [1,2,8,11,14] → median = 8
Group 3: [15, 9, 6, 4, 10] → sorted [4,6,9,10,15] → median = 9

Medians of medians: {7, 8, 9} → median = 8
Use 8 as pivot. Partition around 8 and recurse as needed.

⚡ Quick Revision — Order Statistics & Selection

  • i-th order statistic = i-th smallest element in a set
  • Minimum needs n−1 comparisons; Max also n−1; Both simultaneously: ≈3n/2
  • RANDOMIZED-SELECT: uses QuickSort partition, recurses on ONE side only → O(n) avg
  • After partition: if pivot rank k == i, done; if i<k go left; if i>k go right (find i−k th)
  • SELECT (Median of Medians): groups of 5 → median of medians → guaranteed O(n) worst case

Merge Sort Complexity — Derivation

Recurrence: T(n) = 2T(n/2) + Θ(n), T(1) = 1


Method 1 — Master Theorem:
a=2, b=2, f(n)=n
n^(log_b a) = n^(log_2 2) = n^1 = n
f(n) = Θ(n) = Θ(n^1) → Case 2: T(n) = Θ(n log n)

Method 2 — Backward Substitution (for exam): 
T(n) = 2T(n/2) + cn
     = 2[2T(n/4) + c(n/2)] + cn
     = 4T(n/4) + cn + cn
     = 4T(n/4) + 2cn
     = 4[2T(n/8) + c(n/4)] + 2cn
     = 8T(n/8) + 3cn
     ...
     = 2^k T(n/2^k) + k·cn

When n/2^k = 1 → k = log₂n, 2^k = n

T(n) = n·T(1) + log₂n · cn
     = n·1 + cn log₂n
     = Θ(n log n)   ✅

⚡ Quick Revision — Merge Sort

  • Divide: split at midpoint ⌊(p+r)/2⌋ · Conquer: recursively sort halves · Combine: MERGE
  • O(n log n) in ALL cases — best, average, worst
  • Stable sort · NOT in-place (requires O(n) auxiliary space)
  • Preferred for sorting linked lists (no random access needed)
  • Space = O(n) is a disadvantage vs HeapSort (O(1)) and QuickSort (O(log n) stack)
  • Recurrence T(n)=2T(n/2)+n → solved by Master Theorem Case 2 → Θ(n log n)
