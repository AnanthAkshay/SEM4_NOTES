BFS — Breadth First Search

🔥 REPEATED IN EVERY PAPER

SEE 2024 Q7(b) — "Design an algorithm for BFS. Determine the BFS for the given graph and write topological sorting using source removal." [12 marks]

SEE 2023 Q7(a) — "Discuss the working of BFS approach with an example." [06 marks]

SEE 2025 Q7(b) — "Perform DFS and BFS on the following graph starting from vertex 1." [06 marks]

1. Concept

What is BFS and Why Use It?

BFS explores a graph level by level — first visiting all neighbors of the source, then neighbors of neighbors, and so on. Think of it like ripples in water: the source is the stone, and BFS visits all nodes at distance 1 before visiting distance 2.

Real-world uses: Shortest path in unweighted graphs, social network friend suggestions (degrees of separation), web crawling, broadcasting in networks, GPS navigation (unweighted).

2. Theory

BFS Algorithm

BFS uses a Queue (FIFO) to track nodes to visit. Each node is colored: WHITE (undiscovered), GRAY (discovered, in queue), BLACK (fully processed).

3. Algorithm

Pseudocode

ALGORITHM BFS(G, s)
// G = graph, s = source vertex
for each vertex u ∈ G.V - {s}
    color[u] = WHITE
    d[u] = ∞             // distance from source
    π[u] = NIL           // parent pointer
color[s] = GRAY
d[s] = 0
π[s] = NIL
Q = empty queue
ENQUEUE(Q, s)
while Q ≠ empty
    u = DEQUEUE(Q)
    for each v ∈ Adj[u]
        if color[v] == WHITE
            color[v] = GRAY
            d[v] = d[u] + 1
            π[v] = u
            ENQUEUE(Q, v)
    color[u] = BLACK      // done processing u

DFS — Depth First Search

🔥 VERY IMPORTANT — REPEATED EVERY PAPER

SEE 2023 Q8(b) + Q8(c) — DFS algorithm + DFS traversal with topological order [06+09 marks]

SEE 2024 Q8(a) — "Differentiate between DFS and BFS." [05 marks]

1. Concept

What is DFS?

DFS explores as deep as possible along each branch before backtracking. Think of it like exploring a maze: always go forward until you hit a dead end, then backtrack to the last junction and try another path.

Real-world uses: Cycle detection, topological sorting, finding strongly connected components, solving puzzles/mazes, scheduling problems, compiler dependency resolution.

2. Theory

Key DFS Concepts

DFS maintains two timestamps for each vertex:

  • d[v] — Discovery time: when v is first encountered (colored GRAY)
  • f[v] — Finish time: when all of v's adjacency list is processed (colored BLACK)

Parenthesis Theorem: For any two vertices u, v, their intervals [d[u], f[u]] and [d[v], f[v]] are either completely disjoint, or one is entirely nested inside the other. They never partially overlap.

Edge Classification in DFS:

Edge TypeDefinitionSignificance
Tree EdgeEdge (u,v) where v was WHITE when discoveredForms the DFS tree
Back EdgeEdge (u,v) where v is an ancestor of u in DFS treeIndicates a cycle!
Forward EdgeEdge (u,v) where v is a non-tree descendantOnly in directed graphs
Cross EdgeAll other edges (between different subtrees)Only in directed graphs
Key Theorem: A directed graph G is acyclic (DAG) if and only if DFS produces NO back edges.
3. Algorithm

Pseudocode

ALGORITHM DFS(G)
    for each vertex u ∈ G.V
        color[u] = WHITE
        π[u] = NIL
    time = 0
    for each vertex u ∈ G.V
        if color[u] == WHITE
            DFS-VISIT(G, u)

ALGORITHM DFS-VISIT(G, u)
    time = time + 1
    d[u] = time          // u is discovered
    color[u] = GRAY
    for each v ∈ Adj[u]
        if color[v] == WHITE
            π[v] = u
            DFS-VISIT(G, v)
    color[u] = BLACK
    time = time + 1
    f[u] = time          // u is finished

Topological Sorting

🔥 REPEATED IN EVERY PAPER

SEE 2023 Q8(a) — "What is topological sorting? Explain any one method with example." [06 marks]

1. Concept

What is Topological Sort?

Topological Sort: A linear ordering of vertices of a Directed Acyclic Graph (DAG) such that for every directed edge (u, v), vertex u appears before vertex v in the ordering.

Real-world intuition: Course prerequisites — if CS101 must be taken before CS201, a topological order lists CS101 before CS201. Task scheduling, build systems (Makefile), package dependencies (npm/pip) all use topological sort.

Key restriction: Topological sort is only defined for DAGs (no cycles). If a cycle exists, no valid ordering is possible.

2. Theory

Method 1: DFS-Based Topological Sort

Run DFS. When a vertex is finished (f[v] assigned), add it to the front of a linked list. The list gives topological order.

Theorem: For every directed edge (u,v) in a DAG, f[u] > f[v]. So decreasing finish times give topological order.

ALGORITHM TopologicalSort-DFS(G)
    Run DFS on G, computing finish times f[v]
    When each vertex is finished, push it onto a Stack
    Output vertices by popping the Stack
    // Result: vertices in decreasing order of finish time = topological order
2. Theory

Method 2: Kahn's Algorithm (Source Removal / In-degree)

Repeatedly remove vertices with in-degree 0 (sources). Each removed vertex goes into the topological order.

ALGORITHM KahnTopologicalSort(G)
    Compute in-degree for all vertices
    Enqueue all vertices with in-degree = 0 into queue Q
    while Q is not empty
        u = DEQUEUE(Q)
        Add u to result
        for each v ∈ Adj[u]
            in-degree[v] = in-degree[v] - 1
            if in-degree[v] == 0
                ENQUEUE(Q, v)
    if result contains all vertices: valid topological order
    else: graph has a cycle (no valid ordering exists)

Strongly Connected Components (Kosaraju's Algorithm)

1. Concept

What is a Strongly Connected Component?

Strongly Connected Component (SCC): A maximal set of vertices C ⊆ V such that for every pair of vertices u, v ∈ C, there exist paths u ⇝ v and v ⇝ u (mutually reachable).

Real-world: Web pages linking to each other (mutual linking communities), road networks (areas where you can drive anywhere from anywhere), social networks (mutual follower clusters).

2. Theory

Kosaraju's Algorithm — 3 Steps

ALGORITHM Kosaraju_SCC(G)
// Step 1: DFS on original graph G, record finish order
Run DFS on G; push each vertex onto Stack when it finishes

// Step 2: Compute transpose G^T (reverse all edges)
G^T = TRANSPOSE(G)

// Step 3: DFS on G^T in decreasing finish time order
while Stack is not empty
    u = Stack.pop()
    if color[u] == WHITE (in G^T DFS)
        DFS-VISIT(G^T, u)
        // All vertices visited in this DFS call form one SCC
4. Solved Example

Finding SCCs

✅ Kosaraju's Algorithm Trace
Directed Graph: a → b → c ↑ ↓ d ←——— e ← f Edges: a→b, b→c, c→e, e→d, d→a, b→d, e→f (Note: a,b,c,d,e form a cycle; f is isolated)

Step 1 — DFS on G, finish order (stack top = last finished):

Start from a: a→b→c→e→d (finishes d), back to e→f (finishes f), back to e (finish), c (finish), b (finish), a (finish)

Stack (bottom→top): d, f, e, c, b, a   (or similar — a finishes last)

Step 2 — Transpose G^T: Reverse all edges.

Step 3 — DFS on G^T in order a, b, c, e, f, d:

Start DFS from a in G^T → reaches {a, b, c, d, e} → SCC 1: {a,b,c,d,e}

Next unvisited from stack: f → DFS from f → only f → SCC 2: {f}

SCCs: {a,b,c,d,e} and {f}

Bellman-Ford Algorithm — Single Source Shortest Path

1. Concept

Why Bellman-Ford?

Dijkstra's algorithm fails when a graph has negative-weight edges. Bellman-Ford handles negative weights and can even detect negative-weight cycles (cycles where the total weight is negative — these make the shortest path undefined because you can loop forever reducing the distance).

Real-world uses: Currency exchange arbitrage detection (negative cycles = profit loop), network routing protocols (RIP — Routing Information Protocol), detecting pricing inconsistencies.

2. Theory

Key Idea — Relaxation

Relaxation of edge (u,v,w): If d[v] > d[u] + w(u,v), update d[v] = d[u] + w(u,v) and π[v] = u.

Bellman-Ford performs |V|-1 rounds of relaxing ALL edges. After round k, it guarantees shortest paths using at most k edges are correct. Since shortest paths in a graph with no negative cycles have at most |V|-1 edges, |V|-1 rounds suffice.

Negative cycle detection: After |V|-1 rounds, if any edge can still be relaxed → a negative cycle exists.

3. Algorithm

Pseudocode

ALGORITHM BellmanFord(G, w, s)
// G=graph, w=weight function, s=source
for each vertex v ∈ G.V
    d[v] = ∞
    π[v] = NIL
d[s] = 0

// |V|-1 rounds of relaxation
for i = 1 to |V| - 1
    for each edge (u, v) ∈ G.E
        if d[v] > d[u] + w(u,v)       // Relax
            d[v] = d[u] + w(u,v)
            π[v] = u

// Check for negative-weight cycles
for each edge (u, v) ∈ G.E
    if d[v] > d[u] + w(u,v)
        return FALSE   // Negative cycle detected!
return TRUE

Dijkstra's Algorithm — Single Source Shortest Path

🔥 EXTREMELY REPEATED — IN EVERY PAPER UNDER UNIT 3

SEE 2023(O) Q5(b) — "State and explain Dijkstra's. Apply for given graph, source = a." [07 marks]

SEE 2023 Q6(b) — "Apply Dijkstra's, source B, for given graph." [10 marks]

SEE 2025 Q6(a) — "Write Dijkstra's algorithm. Apply for given graph, source = a." [10 marks]

1. Concept

Dijkstra's — Greedy Shortest Path

Dijkstra's finds the shortest path from a single source to all other vertices in a weighted graph with non-negative edge weights. It uses a greedy approach: always extend the shortest known path first.

Intuition: Like water spreading from a source — water always finds the shortest path to any point because it flows outward uniformly.

3. Algorithm

Pseudocode

ALGORITHM Dijkstra(G, w, s)
    for each vertex v ∈ G.V
        d[v] = ∞
        π[v] = NIL
    d[s] = 0
    S = ∅                    // Set of finalized vertices
    Q = G.V                  // Min-priority queue by d value
    while Q ≠ ∅
        u = EXTRACT-MIN(Q)   // Vertex with smallest d[u]
        S = S ∪ {u}
        for each v ∈ Adj[u]
            if d[v] > d[u] + w(u,v)   // Relax edge
                d[v] = d[u] + w(u,v)
                π[v] = u
                DECREASE-KEY(Q, v, d[v])

Floyd-Warshall — All-Pairs Shortest Paths

🔥 REPEATED IN EVERY PAPER

SEE 2023 Q6(a) — "Define transitive closure. Apply Floyd's algorithm for given graph." [10 marks]

SEE 2024 Q6(a) — "Explain Floyd-Warshall for all-pair shortest paths. Apply for given graph." [08 marks]

SEE 2025 Q6(b) — "Describe dynamic programming. Write Warshall's algorithm. Apply for given adjacency matrix." [10 marks]

Makeup 2023 Q5(a) — "Trace Warshall's algorithm on given graph. Why is it dynamic programming?" [08 marks]

SEE 2023(O) Q6(a) — "Floyd's algorithm for all-pair shortest paths." [10 marks]

1. Concept

What is Floyd-Warshall?

Floyd-Warshall computes shortest paths between ALL pairs of vertices simultaneously. While Dijkstra solves single-source, Floyd-Warshall solves all-pairs in one pass using dynamic programming.

Key insight: The shortest path from i to j either goes through intermediate vertex k or it doesn't. Build up the solution by considering all possible intermediate vertices k = 1, 2, …, n.

2. Theory

Recurrence Relation

D⁽ᵏ⁾[i][j] = shortest path from i to j using only vertices {1, 2, …, k} as intermediate vertices.
D⁽⁰⁾[i][j] = w[i][j]   (direct edge weight, ∞ if no edge, 0 if i=j)
D⁽ᵏ⁾[i][j] = min( D⁽ᵏ⁻¹⁾[i][j],   D⁽ᵏ⁻¹⁾[i][k] + D⁽ᵏ⁻¹⁾[k][j] )

"Either don't use k as intermediate, or go through k."

3. Algorithm

Pseudocode

ALGORITHM FloydWarshall(W, n)
// W is n×n weight matrix; W[i][j] = edge weight (∞ if none, 0 if i=j)
D = W                   // D⁽⁰⁾ = W
for k = 1 to n         // Consider each vertex as intermediate
    for i = 1 to n
        for j = 1 to n
            D[i][j] = min(D[i][j], D[i][k] + D[k][j])
return D                // D[i][j] = shortest path i to j
4. Solved Example

🔥 PYQ Full Trace — Warshall/Floyd

🔥 SEE 2025 Q6(b) — 10 Marks | Warshall's Algorithm on Adjacency Matrix

Given adjacency matrix (4×4):

      1  2  3  4
  1 [ 0  1  0  0 ]
  2 [ 0  0  1  0 ]
  3 [ 0  0  0  1 ]
  4 [ 0  1  0  0 ]

(This is Warshall's for transitive closure — uses OR instead of min)

Warshall's Algorithm (Transitive Closure):

for k = 1 to n
    for i = 1 to n
        for j = 1 to n
            R[i][j] = R[i][j] OR (R[i][k] AND R[k][j])

Initial R⁽⁰⁾ = given matrix

k=1 (vertex 1 as intermediate):

R[i][j] = R[i][j] OR (R[i][1] AND R[1][j])
Check if going through vertex 1 creates new paths.
R[1][1]=0, so col-1 of R[i][1] must be 1 to create new paths.
No vertex has R[i][1]=1 except i=4: R[4][1]=0. → No changes.

k=2 (vertex 2 as intermediate):

R[i][2]=1 for i∈{1,4}: meaning vertices 1 and 4 can reach vertex 2.
Via 2, they can reach j where R[2][j]=1: j=3.
So R[1][3] = 0 OR (1 AND 1) = 1 (new!) — vertex 1 can reach 3 via 2
R[4][3] = 0 OR (1 AND 1) = 1 (new!) — vertex 4 can reach 3 via 2

k=3 (vertex 3 as intermediate):

Via 3, reach j where R[3][j]=1: j=4.
R[i][3]=1 for i∈{1,2,4}: → R[1][4]=1, R[2][4]=1, R[4][4]=1 (new paths)

k=4 (vertex 4 as intermediate):

Via 4, reach j where R[4][j]=1: j=2,3,4.
R[i][4]=1 for i∈{1,2,3,4}: → R[1][2] already 1; R[2][2]=1, R[3][2]=1 (new!), R[3][3]=1, R[4][2] already 1...

Final Transitive Closure R:

      1  2  3  4
  1 [ 0  1  1  1 ]  (1 can reach 2,3,4)
  2 [ 0  1  1  1 ]  (2 can reach itself via cycle, 3, 4)
  3 [ 0  1  1  1 ]  (3 can reach 2,3,4 via cycle)
  4 [ 0  1  1  1 ]  (4 can reach 2,3,4)

Why is this Dynamic Programming?

  • Overlapping subproblems: D⁽ᵏ⁾[i][j] is built from D⁽ᵏ⁻¹⁾ subproblems
  • Optimal substructure: shortest path through k uses shortest paths to/from k
  • Results stored in a table → no recomputation

Johnson's Algorithm

1. Concept

Why Johnson's Algorithm?

Floyd-Warshall runs in Θ(V³) — fine for dense graphs. But for sparse graphs (few edges), we can do better. Johnson's combines Bellman-Ford and Dijkstra:

  • Uses Bellman-Ford to reweight all edges to be non-negative (eliminating negative weights)
  • Then runs Dijkstra from every vertex on the reweighted graph

Result: All-pairs shortest paths in O(V² log V + VE) — much faster than Floyd-Warshall for sparse graphs.

2. Theory

Reweighting: The Key Idea

The trick is to add a new vertex s connected to every vertex with weight 0, then run Bellman-Ford from s to compute h[v] for each vertex. The reweighted edge weight is:

ŵ(u,v) = w(u,v) + h[u] − h[v]

This guarantees ŵ(u,v) ≥ 0 for all edges, without changing shortest paths.

Why ŵ ≥ 0? By triangle inequality on shortest paths: h[v] ≤ h[u] + w(u,v) → w(u,v) + h[u] - h[v] ≥ 0.

3. Algorithm

Pseudocode

ALGORITHM Johnson(G, w)
    // Step 1: Add new source s with zero-weight edges to all vertices
    G' = G with new vertex s; add edge (s,v,0) for all v ∈ V

    // Step 2: Run Bellman-Ford from s
    if BellmanFord(G', w, s) == FALSE
        return "Negative cycle detected"
    h[v] = δ(s,v)  // shortest distance from s to v

    // Step 3: Reweight edges
    for each edge (u,v) ∈ G.E
        ŵ(u,v) = w(u,v) + h[u] − h[v]

    // Step 4: Run Dijkstra from every vertex on reweighted graph
    for each vertex u ∈ G.V
        Run Dijkstra(G, ŵ, u) → get d̂[u][v] for all v
        // Convert back to original weights:
        D[u][v] = d̂[u][v] − h[u] + h[v]
    return D

Ford-Fulkerson Algorithm — Maximum Flow

1. Concept

What is Maximum Flow?

Maximum Flow Problem: Given a directed graph (flow network) with a source s, a sink t, and edge capacities c(u,v), find the maximum amount of flow that can be sent from s to t without exceeding edge capacities.

Real-world applications: Water/oil pipeline networks, Internet traffic routing, airline scheduling, bipartite matching, supply chain optimization, electrical circuit analysis.

2. Theory

Key Concepts

ConceptDefinition
Flow f(u,v)Amount flowing through edge (u,v); 0 ≤ f(u,v) ≤ c(u,v)
Capacity constraintf(u,v) ≤ c(u,v) for all edges
Skew symmetryf(u,v) = −f(v,u)
Flow conservation∑ f(u,v) = 0 for all u ≠ s,t (in = out)
Residual graph GfShows remaining capacity: cf(u,v) = c(u,v) − f(u,v)
Augmenting pathA path from s to t in residual graph with positive capacity
BottleneckMin capacity edge on an augmenting path
Max-Flow Min-Cut Theorem: The maximum flow from s to t equals the minimum capacity of an s-t cut (partition of vertices into two sets S ∋ s and T ∋ t).
3. Algorithm

Ford-Fulkerson Pseudocode

ALGORITHM FordFulkerson(G, s, t)
// Initialize flow on all edges to 0
for each edge (u,v) ∈ G.E
    f(u,v) = 0

while there exists an augmenting path p from s to t in residual graph Gf
    cf(p) = min{ cf(u,v) : (u,v) on path p }   // bottleneck capacity
    for each edge (u,v) on path p
        f(u,v) = f(u,v) + cf(p)   // forward edge: add flow
        f(v,u) = f(v,u) − cf(p)   // backward edge: reduce flow

return |f| = ∑ f(s,v) for v ∈ Adj[s]  // total flow out of source

Edmonds-Karp Algorithm

1. Concept

Edmonds-Karp: BFS-based Ford-Fulkerson

Edmonds-Karp is Ford-Fulkerson but with one crucial change: always find the shortest augmenting path (fewest edges) using BFS in the residual graph. This guarantees polynomial time — O(VE²) — independent of the max flow value.

2. Theory

Why BFS Makes it Polynomial?

  • BFS finds shortest augmenting paths (in terms of number of edges)
  • Each edge can become critical (bottleneck) at most O(V) times
  • Total augmenting paths: O(V·E)
  • Each BFS: O(E)
  • Total: O(V·E²)
3. Algorithm

Pseudocode

ALGORITHM EdmondsKarp(G, s, t)
    Initialize all flows to 0
    while true
        // Find shortest path using BFS in residual graph
        p = BFS(Gf, s, t)
        if no path found: break
        // Augment along p
        cf(p) = min capacity on p
        for each edge (u,v) on p
            f(u,v) += cf(p)
            f(v,u) -= cf(p)
    return total flow

  • ✔ BFS ensures shortest path → polynomial bound O(VE²)
  • ✔ Ford-Fulkerson (DFS) can be O(E·f*) — exponential in worst case
  • ✔ Edmonds-Karp is the standard practical max-flow algorithm

1. Concept

Why Do We Need Complexity Classes?

Not all problems are equally hard. Some have efficient algorithms (sorting, shortest path). Others seem to require examining every possible solution (n-Queens, TSP, Subset Sum). Complexity classes group problems by how hard they fundamentally are.

The central question of CS: Does P = NP? — Are all problems whose solutions can be verified quickly, also solvable quickly? This is the most famous unsolved problem in mathematics.

2. Theory

Class P — Polynomial Time

P (Polynomial time): The class of decision problems that can be solved by a deterministic algorithm in O(nᵏ) time for some constant k.

"Efficiently solvable" problems. We can find the answer in polynomial time.

ProblemAlgorithmTime
SortingMerge SortO(n log n)
Shortest Path (no neg. cycles)Dijkstra / Bellman-FordO(V² or VE)
Primality TestingAKS AlgorithmO(log⁶ n)
MSTKruskal / PrimO(E log V)
GCDEuclidean AlgorithmO(log n)
2. Theory

Class NP — Nondeterministic Polynomial

NP (Nondeterministic Polynomial): The class of decision problems where a proposed solution (certificate) can be verified in polynomial time by a deterministic algorithm.

Intuition: Given a correct answer, you can quickly check it's right — but finding the answer might take exponential time.

✅ Example: Hamiltonian Cycle

Finding a Hamiltonian cycle (visit every vertex exactly once) in a graph is NP.

Verification (easy, polynomial): Given a proposed cycle, check that it visits every vertex exactly once and all edges exist → O(V) time.

Finding (hard): No known polynomial algorithm. Brute force: O(V!) time.

Note: P ⊆ NP (any problem solvable in polynomial time can also be verified in polynomial time). Whether P = NP or P ≠ NP is unsolved.

2. Theory

Polynomial Reduction

Polynomial Reducibility (A ≤_P B): Problem A is polynomial-time reducible to B if any instance of A can be transformed into an instance of B in polynomial time, such that solving B also solves A.

Intuition: "If we can solve B, we can solve A." So B is at least as hard as A.

2. Theory

Class NP-Complete

NP-Complete: A problem X is NP-Complete if:
(1) X ∈ NP (can be verified in polynomial time), AND
(2) Every problem in NP is polynomial-time reducible to X (X is NP-Hard)

NP-Complete problems are the hardest problems in NP. If any NP-Complete problem has a polynomial-time algorithm, then P = NP (all NP problems become polynomial).

✅ NP-Complete Problem Examples (Must Memorize)

2. Theory

Class NP-Hard

NP-Hard: A problem X is NP-Hard if every NP problem is polynomial-time reducible to X — but X itself may not be in NP (may not even be a decision problem or may be harder than NP).

NP-Hard = "at least as hard as NP-Complete" — but not necessarily verifiable in polynomial time.

✅ NP-Hard Examples
  • TSP (optimization version — find the shortest tour): NP-Hard but not in NP (since output is a number, not a yes/no)
  • Halting problem: NP-Hard and undecidable (not even in NP)
  • Optimal scheduling: NP-Hard

Assuming P ≠ NP (most likely scenario): ┌─────────────────────────────────────────────────┐ │ NP-HARD │ │ ┌──────────────────────────────────────────┐ │ │ │ NP │ │ │ │ ┌─────────────────────────────────┐ │ │ │ │ │ NP-COMPLETE │ │ │ │ │ │ (boundary of NP and NP-Hard) │ │ │ │ │ └─────────────────────────────────┘ │ │ │ │ ┌──────────────┐ │ │ │ │ │ P │ (P ⊆ NP) │ │ │ │ │ (Polynomial)│ │ │ │ │ └──────────────┘ │ │ │ └──────────────────────────────────────────┘ │ └─────────────────────────────────────────────────┘ If P = NP: all three inner boxes collapse into one. 2. Theory

Why Are NP-Complete Problems Hard? (SEE 2025 Q10c)

  • No known polynomial algorithm: All known algorithms for NP-Complete problems have exponential worst-case time
  • All of NP reduces to them: Solving one NP-Complete problem polynomially would solve ALL of NP
  • Consequences for algorithm design:
    • Use approximation algorithms (get near-optimal in polynomial time)
    • Use heuristics (genetic algorithms, simulated annealing — no guarantee)
    • Use exact algorithms for small inputs (backtracking, branch & bound)
    • Exploit problem structure (special cases that are polynomial)

Approximation Algorithms

🔥 REPEATED IN MULTIPLE PAPERS

SEE 2023 Q10(c) — "Explain with examples, the need of approximation problems." [05 marks]

1. Concept

Why Approximation Algorithms?

For NP-Hard optimization problems, finding the exact optimal solution may take exponential time. Approximation algorithms find a solution that is guaranteed to be close to optimal in polynomial time.

Trade-off: We sacrifice a little optimality to gain massive speed improvements. In practice, a solution 5% above optimal found in seconds beats an exact solution found in days.

2. Theory

Approximation Ratio

Approximation Ratio ρ(n): An algorithm has approximation ratio ρ(n) if for every input of size n, the cost C of the algorithm's solution and the optimal cost C* satisfy:
max(C/C*, C*/C) ≤ ρ(n)
  • ρ(n) = 1 means exact optimal solution
  • ρ(n) = 2 means solution is at most twice the optimal
  • ρ(n) = 1.5 means solution is at most 50% above optimal

A ρ(n)-approximation algorithm is called a ρ-approximation (or has approximation ratio ρ).

2. Theory + Examples

Key Approximation Algorithms

1. Vertex Cover (2-Approximation)

Problem: Find the minimum set of vertices that covers all edges (every edge has at least one endpoint in the set). 
ALGORITHM ApproxVertexCover(G)
    C = ∅
    E' = G.E
    while E' ≠ ∅
        Pick any edge (u,v) from E'
        C = C ∪ {u, v}           // add BOTH endpoints
        Remove all edges incident to u or v from E'
    return C                      // guaranteed ≤ 2 × optimal

Approximation ratio: 2 — The selected edges form a matching; optimal cover needs at least one endpoint per matching edge. We pick 2 endpoints → at most 2× optimal.

Time complexity: O(V + E)

2. TSP with Triangle Inequality (1.5-Approximation — Christofides)

Problem: Find shortest tour through all cities (each visited once). Assumes triangle inequality: dist(a,c) ≤ dist(a,b) + dist(b,c).

Simpler 2-approximation using MST:

ALGORITHM Approx-TSP-Tour(G, c)
    Compute MST T of G              // using Prim/Kruskal
    List L = preorder DFS traversal of T
    return Hamiltonian cycle from L (skip repeated vertices)

Why ≤ 2-approximation: Optimal TSP tour ≥ cost of MST. Full walk of MST = 2×MST. Shortcutting (triangle inequality) only reduces cost → tour ≤ 2×optimal.

3. Set Cover (O(log n)-Approximation)

Greedy: repeatedly pick the set that covers the most uncovered elements. Achieves O(log n)-approximation — best possible unless P=NP.

4. Bin Packing (First-Fit Decreasing)

Sort items by decreasing size, assign each to first bin that fits. Achieves ≤ (11/9)OPT + 6/9 approximation.

1. Concept

What is Backtracking?

Backtracking: A systematic method for solving problems by exploring all possible configurations and abandoning (pruning) configurations that cannot lead to a valid solution.

Strategy: Build the solution incrementally. At each step, try all possible choices. If a choice violates constraints, backtrack — undo it and try the next choice. Continue until a complete valid solution is found or all possibilities are exhausted.

Think of it as: DFS on a state-space tree where we prune branches that are clearly invalid.

2. Theory

N-Queens Problem

Problem: Place N queens on an N×N chessboard such that no two queens attack each other. Queens attack along the same row, column, or diagonal.

Constraints (for queen at row i, column j):

  • No two queens in the same column: col[i] ≠ col[k] for all k ≠ i
  • No two queens on same diagonal: |col[i] - col[k]| ≠ |i - k|
  • (Row constraint is automatically satisfied by placing one queen per row)
3. Algorithm

Pseudocode

ALGORITHM NQueens(k, n)
// Place queens in rows k to n; queens already placed in rows 1..k-1
for col = 1 to n
    if Place(k, col) is valid   // No conflicts
        x[k] = col              // Place queen at row k, column col
        if k == n
            Print solution x[]  // All n queens placed
        else
            NQueens(k+1, n)     // Recurse for next row

FUNCTION Place(k, col)
for i = 1 to k-1
    if x[i] == col           // Same column
        return false
    if |x[i] - col| == |i - k|  // Same diagonal
        return false
return true

Complexity of N-Queens

O(n!)
With Backtracking
Much less in practice
Space
O(n)

Without pruning: n×(n-1)×(n-2)×…×1 = n! states. Backtracking prunes most branches early, making it feasible for moderate n.
