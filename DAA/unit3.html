Topic 01
What is Amortized Analysis?
1
Concept Introduction & Motivation
What is it?

Amortized analysis is a method for analyzing the average performance of a sequence of operations on a data structure, guaranteeing the average cost per operation over the worst case.


It is different from average-case analysis: there is no probability involved — it analyses the worst-case performance of a sequence of operations, not a single operation in isolation.

Why do we need it?
The Core Problem
Consider a dynamic array (like Java's ArrayList). Normally, push is O(1). But occasionally (when the array is full), it costs O(n) to resize. If you only look at the worst-case per operation, you'd say push is O(n) — which is misleading!

Amortized analysis shows the true average cost across many operations is O(1) per push, even accounting for occasional O(n) resizes.
Key Intuition — The "Amortization" Analogy

Think of it like a gym membership: you pay ₹5000 upfront but visit 100 times. The amortized cost per visit = ₹50/visit. Some visits "cost" more (first visit: registration paperwork) but averaged out, each visit is cheap.


In algorithms: expensive operations happen rarely, but you "spread" their cost over many cheap operations.

Formal Definition
Definition
Let T(n) = total actual cost of n operations on a data structure.
The amortized cost per operation = T(n) / n.

If the amortized cost per operation is O(f(n)), then the total cost of n operations is O(n · f(n)).
Amortized Cost = Total Cost of n operations / n

Topic 02
The Aggregate Method
2
Aggregate Method — Theory & Examples
Core Idea

In the aggregate method, you compute the total cost T(n) of n operations, then divide by n to get the amortized cost per operation.

Amortized cost per op = T(n) / n

If T(n) = O(n·g(n)), then each operation has amortized cost O(g(n)).

Example 1: Stack with MULTIPOP

Consider a stack that supports three operations:

OperationActual CostDescription
PUSH(S, x)1Push element onto stack
POP(S)1Pop top element
MULTIPOP(S, k)min(s, k)Pop min(stack_size, k) elements

Worst case naively: MULTIPOP costs O(n), so n operations → O(n²) — but this is too pessimistic!

Aggregate Argument
Each element can be pushed at most once and popped at most once.
Total number of PUSH operations ≤ n (out of all n operations).
Total number of POP operations (including via MULTIPOP) ≤ Total PUSH operations ≤ n.

Therefore: T(n) ≤ 2n = O(n)
Amortized cost per operation = O(n)/n = O(1)
T(n) ≤ 2n ⟹ Amortized cost per op = O(1)
Example 2: Binary Counter Increment

Consider a k-bit binary counter starting at 0. The INCREMENT operation adds 1 to the counter. Cost = number of bits flipped.

Observation
If bit i flips, bit i+1 might also flip (carry propagation). In the worst case (e.g., counter = 0111...1), INCREMENT flips all k bits → O(k). But is every INCREMENT that expensive? No!

How often does each bit flip?

Bit PositionFlips per n Increments
Bit 0 (LSB)⌊n/1⌋ = n
Bit 1⌊n/2⌋
Bit 2⌊n/4⌋
Bit i⌊n/2ⁱ⌋
Bit k-1 (MSB)⌊n/2^(k-1)⌋

Total flips across n increments:

T(n) = Σᵢ₌₀ᵏ⁻¹ ⌊n/2ⁱ⌋ < n · Σᵢ₌₀^∞ 1/2ⁱ = n · 2 = 2n = O(n)

Therefore: Amortized cost per INCREMENT = O(n)/n = O(1)

Topic 03
The Accounting Method
3
Accounting Method — Theory & Examples
Core Idea

In the accounting method, we assign different "charges" (amortized costs) to different operations. Some operations are charged more than their actual cost (saving "credit"); others are charged less (spending saved credit).


Let:

SymbolMeaning
cᵢActual cost of operation i
ĉᵢAmortized (charged) cost of operation i
Creditĉᵢ − cᵢ ≥ 0 (stored on data structure)
Key Constraint
For all n operations, the total stored credit must be ≥ 0 at all times: Σᵢ₌₁ⁿ ĉᵢ ≥ Σᵢ₌₁ⁿ cᵢ This ensures we never "overdraw" the credit account.
Stack with MULTIPOP — Accounting Method

Assign amortized costs:

OperationActual CostAmortized (Charged) CostCredit Stored
PUSH(S, x)12+1 (stored on element x)
POP(S)10Use 1 credit from popped element
MULTIPOP(S,k)min(s,k)0Each pop uses 1 stored credit
Proof of Validity
When an element is PUSHed, we charge 2 instead of 1 → extra 1 credit stored on the element.
When it is POPped (directly or via MULTIPOP), we charge 0 → pay using the stored credit.
Since each element pays for its own removal, credit never goes negative. ✔

Total amortized cost for n ops = O(n) → Amortized O(1) per operation.
Binary Counter — Accounting Method

Assign amortized costs:

Bit Flip TypeActual CostAmortized CostCredit Effect
0 → 1 (set to 1)12+1 credit stored on this bit
1 → 0 (reset to 0)10Use stored credit to pay

Each INCREMENT sets exactly one bit from 0→1 (amortized cost 2) and resets some bits from 1→0 (amortized cost 0 each, paid by stored credits).

Total amortized cost per INCREMENT = 2 = O(1).

Insight
The "2" charge works because: 1 unit pays for the actual 0→1 flip, and 1 unit is saved as credit on that bit to pay for the future 1→0 flip when the bit gets reset.
📝 Exam Writing Guide
  • For 5 marks: Definition + table of amortized charges + constraint statement.
  • For 8–10 marks: Both examples, clearly show credit stored on objects, prove credit ≥ 0 always.
  • Key phrase: "The amortized cost charged is always sufficient to cover the actual cost, and the total credit (ĉ − c) never goes negative."
Quick Revision — Accounting Method
Charge ĉᵢ ≥ actual cost → save credit
Charge ĉᵢ < actual cost → spend stored credit
Total stored credit must always be ≥ 0
PUSH: charge 2 (1 for push + 1 stored for future pop)
POP / MULTIPOP: charge 0, use stored credit
Bit 0→1: charge 2; Bit 1→0: charge 0
Topic 04
The Potential Method
4
Potential Method — Theory & Examples
Core Idea

Instead of associating credit with individual objects, the potential method defines a potential function Φ over the entire data structure state. Think of Φ as a "bank balance" of stored energy.

Potential Method Formula
Let Dᵢ = state of data structure after operation i, and Φ(Dᵢ) = potential at that state.

Amortized cost: ĉᵢ = cᵢ + Φ(Dᵢ) − Φ(Dᵢ₋₁) Where:
  • ĉᵢ = amortized cost of operation i
  • cᵢ = actual cost of operation i
  • Φ(Dᵢ) − Φ(Dᵢ₋₁) = change in potential (positive = energy stored, negative = energy released)

Summing over n operations:

Σĉᵢ = Σcᵢ + Φ(Dₙ) − Φ(D₀)

If Φ(Dₙ) ≥ Φ(D₀) always, then Σcᵢ ≤ Σĉᵢ, proving the amortized bound.

Stack with MULTIPOP — Potential Method

Define: Φ(D) = number of elements currently on the stack (stack size s).


Initial state: Φ(D₀) = 0 (empty stack). Always Φ ≥ 0, so Φ(Dₙ) ≥ Φ(D₀). ✔

OperationActual cost cᵢΔΦ = Φ(Dᵢ)−Φ(Dᵢ₋₁)Amortized ĉᵢ = cᵢ + ΔΦ
PUSH 1 +1 (size increases) 1 + 1 = 2 = O(1)
POP 1 −1 (size decreases) 1 + (−1) = 0 ... wait, 0?
MULTIPOP(k) k' = min(s,k) −k' (size decreases) k' + (−k') = 0 = O(1)
Result
All three operations have amortized cost O(1).
Total cost of n operations ≤ Σĉᵢ + Φ(D₀) − Φ(Dₙ) ≤ O(n) + 0 − 0 = O(n)
Amortized cost per operation = O(1)
Binary Counter — Potential Method

Define: Φ(D) = number of 1-bits in the counter = b₁ (number of ones).


Suppose at some point there are b₁ ones, and INCREMENT resets the last t consecutive 1-bits to 0 and sets the next bit from 0 to 1.


Actual cost: cᵢ = t + 1 (flip t zeros→ones + 1 one→zero)

ΔΦ = (b₁ − t + 1) − b₁ = 1 − t

ĉᵢ = (t + 1) + (1 − t) = 2 = O(1)

Again, amortized cost per INCREMENT = O(1).

Choosing a Good Potential Function Φ
Property of ΦWhy It Matters
Φ(D₀) = 0 (initial state)Simplifies calculation
Φ(Dᵢ) ≥ 0 for all iEnsures total amortized ≥ actual total
Rises slowly for cheap opsStores potential for later release
Falls sharply for expensive opsReleases potential to pay for the expensive op

  • For 5 marks: Define Φ, write formula ĉᵢ = cᵢ + ΔΦ, one worked example.
  • For 10 marks: Full derivation for stack or binary counter — define Φ, compute cᵢ, ΔΦ, ĉᵢ for each operation, show Φ(Dₙ) ≥ Φ(D₀), conclude amortized bound.
Quick Revision — Potential Method
Φ = "potential energy" of data structure
Formula: ĉᵢ = cᵢ + Φ(Dᵢ) − Φ(Dᵢ₋₁)
Requires: Φ ≥ 0 and Φ(D₀) = 0
Stack: Φ = stack size s
Binary counter: Φ = number of 1-bits
Expensive op: ΔΦ drops sharply → amortized cheap

Topic 05
Disjoint Sets — Union-Find Data Structure
5
Introduction to Disjoint-Set / Union-Find
What is a Disjoint-Set Data Structure?

A Disjoint-Set (also called Union-Find) maintains a collection of disjoint (non-overlapping) sets. It supports three operations:

OperationDescriptionReal-world use
MAKE-SET(x) Create a new set containing only x Initialize each element as its own component
FIND-SET(x) Return the representative (root) of x's set Check if two elements are in the same set
UNION(x, y) Merge the sets containing x and y Connect two components/elements
Real-World Applications
Where is Disjoint-Set Used?
  • Kruskal's MST Algorithm: Check if adding an edge creates a cycle (are u and v in the same set?)
  • Network connectivity: Are computers A and B connected?
  • Image segmentation: Group pixels of the same region
  • Percolation: Physical grid connectivity problems
  • Maze generation: Remove walls while ensuring connectivity
Representation 1: Linked List (Simple)

Each set is represented as a linked list. The first element (head) is the representative.


UNION: Append one list to the end of another and update representative pointers for all elements in the appended list.

OperationLinked List Cost
MAKE-SETO(1)
FIND-SETO(1) — follow rep pointer
UNIONO(n) worst case — update all pointers in shorter list
Problem with Naive Union
Worst case: always UNION the larger set into smaller → pointers of n/2 elements updated each time → O(n²) for n-1 unions. Too slow!

Weighted-union heuristic: Always append shorter list onto longer. Each element's representative pointer can be updated at most O(log n) times → total cost O(n log n) for n UNIONs.

Representation 2: Rooted Forest (Preferred)

Each set is represented as a rooted tree. The root is the representative. Each node stores only its parent pointer.

// Initial state: MAKE-SET(1), MAKE-SET(2), ..., MAKE-SET(n)
// Each node is root of its own tree: parent[x] = x

parent[1]=1, parent[2]=2, parent[3]=3 ...

// FIND-SET: chase parent pointers to root
FIND-SET(x):
  while parent[x] ≠ x:
    x = parent[x]
  return x

// UNION: attach root of one tree under root of other
UNION(x, y):
  rootX = FIND-SET(x)
  rootY = FIND-SET(y)
  if rootX ≠ rootY:
    parent[rootX] = rootY
Problem with Naive Forest
Without any heuristic, the tree can become a long chain (O(n) height) → FIND-SET costs O(n) → n operations cost O(n²).
Quick Revision — Disjoint Sets Basics
3 operations: MAKE-SET, FIND-SET, UNION
Linked list: FIND O(1), UNION O(n) naive
Forest: each node stores parent pointer only
Root = representative of the set
Naïve forest: can degenerate to O(n) chain
Two heuristics fix this: Union by Rank + Path Compression
Topic 06
Union by Rank
6
Union by Rank — Heuristic 1
The Idea

Maintain a rank for each node — an upper bound on the height of the subtree rooted at that node. When performing UNION, always make the root of the shorter tree (lower rank) point to the root of the taller tree (higher rank).

Why "Rank"?
We use "rank" not "height" because after applying path compression, the actual tree height may be less than the rank. Rank tracks an upper bound.
Algorithm
// MAKE-SET: initially rank = 0
MAKE-SET(x):
  parent[x] = x
  rank[x] = 0

FIND-SET(x):
  if x ≠ parent[x]:
    return FIND-SET(parent[x])
  return x

UNION(x, y):
  LINK(FIND-SET(x), FIND-SET(y))

LINK(x, y):   // x, y are roots
  if rank[x] > rank[y]:
    parent[y] = x            // y becomes child of x
  else:
    parent[x] = y            // x becomes child of y
    if rank[x] == rank[y]:
      rank[y] = rank[y] + 1 // only increment if ranks equal

Rank only increases when two trees of equal rank are merged.

Key Property
Lemma (CLRS)
With union by rank only (no path compression), any root with rank r has at least 2ʳ nodes in its tree. |tree(x)| ≥ 2^rank(x) Since the tree has at most n nodes: rank ≤ ⌊log₂ n⌋, so tree height ≤ log₂ n.

This gives FIND-SET: O(log n) and total for n operations: O(n log n).

Topic 07
Path Compression & Combined Analysis
7
Path Compression — Heuristic 2
The Idea

During FIND-SET, after finding the root, make every node on the path point directly to the root. This "flattens" the tree so future FIND-SET operations are faster.

Two-Pass Technique
Pass 1 (going up): Follow parent pointers to find the root.
Pass 2 (coming back): Set every node's parent directly to the root.
Algorithm
// Recursive version (two-pass)
FIND-SET(x):
  if x ≠ parent[x]:
    parent[x] = FIND-SET(parent[x])  // recursively set parent to root
  return parent[x]

// Iterative version (one-pass, "path splitting")
FIND-SET-ITER(x):
  root = x
  while parent[root] ≠ root:
    root = parent[root]          // find root
  while parent[x] ≠ root:      // path compression
    next = parent[x]
    parent[x] = root
    x = next
  return root
Solved Trace: Path Compression

Suppose we have a chain: 1 → 2 → 3 → 4 → 5 (5 is root).


Before FIND-SET(1):

parent[1]=2, parent[2]=3, parent[3]=4, parent[4]=5, parent[5]=5

FIND-SET(1) recursion: FIND-SET(1) → FIND-SET(2) → FIND-SET(3) → FIND-SET(4) → returns 5

On unwind: parent[4]=5, parent[3]=5, parent[2]=5, parent[1]=5


After FIND-SET(1):

parent[1]=5, parent[2]=5, parent[3]=5, parent[4]=5, parent[5]=5

Now every node directly points to root 5 — all future FIND-SET calls take O(1)!

Combined: Union by Rank + Path Compression

Together, these two heuristics give an almost linear total cost — the best possible for this problem.

🏆 Theorem (Tarjan, 1975)
A sequence of m MAKE-SET, UNION, and FIND-SET operations on n elements, using both union by rank and path compression, has total time: O(m · α(n)) Where α(n) is the inverse Ackermann function — a function that grows INCREDIBLY slowly (α(n) ≤ 4 for all practical n). Effectively O(1) amortized per operation.

Application: Kruskal's MST

Union-Find directly enables Kruskal's algorithm:

  1. MAKE-SET(v) for all vertices v: O(V)
  2. Sort edges by weight: O(E log E)
  3. For each edge (u,v) in sorted order:
    If FIND-SET(u) ≠ FIND-SET(v) → add edge, UNION(u,v)
  4. Repeat until V−1 edges added

Total with DSU: O(E log E + E · α(V)) = O(E log E)

Topic 08
Fibonacci Heaps
8
Fibonacci Heap — Structure & Operations
Why Fibonacci Heap?
Problem with Binary Heaps in Dijkstra/Prim
In Dijkstra's algorithm using a binary min-heap, DECREASE-KEY costs O(log n). For a dense graph with E edges, total cost = O((V + E) log V).

Fibonacci Heaps reduce DECREASE-KEY to O(1) amortized — making Dijkstra/Prim run in O(E + V log V) — significantly faster for dense graphs!
What is a Fibonacci Heap?

A Fibonacci heap is a collection of heap-ordered trees with the following properties:

  • A doubly-linked circular list of tree roots (root list)
  • Each tree satisfies the min-heap property (parent ≤ children)
  • A pointer min[H] points to the node with minimum key
  • Trees are not necessarily binomial trees — they become more structured lazily
  • Each node stores: key, degree, mark (boolean), parent, child, left, right pointers
Operations & Amortized Complexity
Operation Actual Worst Case Amortized Cost Key Idea
INSERT(H, x) O(1) O(1) Just add to root list; update min if needed
MINIMUM(H) O(1) O(1) Return min[H] pointer directly
UNION(H1, H2) O(1) O(1) Concatenate root lists, update min
EXTRACT-MIN(H) O(n) O(log n) Remove min, add children to root list, CONSOLIDATE
DECREASE-KEY(H,x,k) O(n) O(1) Cut node if heap property violated; cascading cut
DELETE(H, x) O(n) O(log n) DECREASE-KEY to −∞, then EXTRACT-MIN
Potential Function Used for Fibonacci Heap Analysis
Define: Φ(H) = t(H) + 2·m(H)
where t(H) = number of trees in root list, m(H) = number of marked nodes.

This potential function is used to prove all amortized bounds above.
INSERT Operation
FIB-HEAP-INSERT(H, x):
  x.degree = 0
  x.parent = NIL
  x.child = NIL
  x.mark = FALSE
  // Add x to the root list of H
  if H.min == NIL:
    create root list containing just x
    H.min = x
  else:
    insert x into H's root list
    if x.key < H.min.key:
      H.min = x
  H.n = H.n + 1

Amortized cost: ΔΦ = +1 (one more tree). ĉᵢ = O(1) + 1 = O(1). ✔

EXTRACT-MIN Operation (key operation)
FIB-HEAP-EXTRACT-MIN(H):
  z = H.min
  if z ≠ NIL:
    // Add each child of z to root list
    for each child x of z:
      add x to H's root list
      x.parent = NIL
    remove z from H's root list
    if z == z.right:       // z was the only node
      H.min = NIL
    else:
      H.min = z.right      // temporary assignment
      CONSOLIDATE(H)       // key step!
    H.n = H.n - 1
  return z
CONSOLIDATE: Making Trees Binomial-like
After removing the min, CONSOLIDATE ensures no two trees in the root list have the same degree. It uses a array A[0..D(n)] where D(n) = ⌊log_φ n⌋ (φ = golden ratio).

For each root node, if A[degree] already has a tree of same degree, link the larger-key root under the smaller-key root, increment degree, repeat.
DECREASE-KEY (most important for graph algorithms)
FIB-HEAP-DECREASE-KEY(H, x, k):
  if k > x.key:
    error "new key is greater than current key"
  x.key = k
  y = x.parent
  if y ≠ NIL and x.key < y.key:
    CUT(H, x, y)          // remove x from y's child list
    CASCADING-CUT(H, y)   // propagate cuts upward
  if x.key < H.min.key:
    H.min = x

CUT(H, x, y):
  remove x from y's child list
  y.degree = y.degree - 1
  add x to H's root list
  x.parent = NIL
  x.mark = FALSE

CASCADING-CUT(H, y):
  z = y.parent
  if z ≠ NIL:
    if y.mark == FALSE:
      y.mark = TRUE          // first cut: just mark
    else:
      CUT(H, y, z)           // second cut: cut and propagate
      CASCADING-CUT(H, z)
Why is DECREASE-KEY O(1) amortized?
Marking mechanism: A node is "marked" when one of its children is cut. When a second child is cut, the node itself is cut (cascading cut).

The potential function Φ = t + 2m absorbs the cost of cascading cuts. Each cascading cut converts a marked node to an unmarked root (ΔΦ ≤ −1 per additional cut). The amortized cost remains O(1).
Degree Bound — Why O(log n) for EXTRACT-MIN
Degree Bound Lemma
In a Fibonacci heap with n nodes, the maximum degree of any node is D(n) = O(log n).

Specifically: D(n) ≤ ⌊log_φ n⌋ where φ = (1+√5)/2 ≈ 1.618 (golden ratio).

The sizes of Fibonacci trees grow as Fibonacci numbers — hence the name!

Since D(n) = O(log n), CONSOLIDATE visits at most O(D(n)) = O(log n) trees → EXTRACT-MIN amortized O(log n).
