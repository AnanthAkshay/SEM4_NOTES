Experiment 1

Aim

To design an Employee–Department–Project database, create tables, insert data and perform SQL operations using Oracle SQL.

Problem Statement

Consider an Employee with a social security number (SSN) working on multiple projects with definite hours for each. Each Employee belongs to a Department. Each project is associated with some domain areas such as Database, Cloud and so on. Each Employee will be assigned to some project.

Constraints

  • SSN is Primary Key of Employee.
  • DeptNo is Primary Key of Department.
  • ProjectNo is Primary Key of Project.
  • Each Employee belongs to one Department.
  • Each Employee works on one or more Projects.
  • Hours worked must be greater than 0.
  • DeptNo and ProjectNo are Foreign Keys.

ER Diagram

Schema Diagram

--------------------
DeptNo (PK)
DeptName

PROJECT
--------------------
ProjectNo (PK)
ProjectName
Domain

EMPLOYEE
--------------------
SSN (PK)
EmpName
Salary
DeptNo (FK)
ProjectNo (FK)

WORKS_ON
--------------------
SSN (FK)
ProjectNo (FK)
Hours

Create Table Statements

CREATE TABLE Department(
DeptNo NUMBER PRIMARY KEY,
DeptName VARCHAR2(30)
);

CREATE TABLE Project(
ProjectNo NUMBER PRIMARY KEY,
ProjectName VARCHAR2(30),
Domain VARCHAR2(30)
);

CREATE TABLE Employee(
SSN NUMBER PRIMARY KEY,
EmpName VARCHAR2(30),
Salary NUMBER,
DeptNo NUMBER,
ProjectNo NUMBER,
FOREIGN KEY(DeptNo)
REFERENCES Department(DeptNo),
FOREIGN KEY(ProjectNo)
REFERENCES Project(ProjectNo)
);

CREATE TABLE Works_On(
SSN NUMBER,
ProjectNo NUMBER,
Hours NUMBER,
PRIMARY KEY(SSN,ProjectNo),
FOREIGN KEY(SSN)
REFERENCES Employee(SSN),
FOREIGN KEY(ProjectNo)
REFERENCES Project(ProjectNo)
);

Experiment 2

Aim

To design and implement Supplier, Part and Supply relations and perform SQL operations.

Problem Statement

Consider the relations PART, SUPPLIER and SUPPLY. The Supplier relation holds information about suppliers. The attributes SID, SNAME and SADDR describe the supplier. The Part relation holds PID, PNAME and PCOLOR. The Supply relation contains SID and PID identifying the supplier and supplied part respectively along with Quantity.

Constraints

  • SID is Primary Key of Supplier.
  • PID is Primary Key of Part.
  • (SID,PID) is Primary Key of Supply.
  • SID in Supply references Supplier(SID).
  • PID in Supply references Part(PID).
  • Quantity must be greater than 0.
  • A supplier can supply many parts.
  • A part can be supplied by many suppliers.

Create Table Statements

CREATE TABLE Supplier(
SID NUMBER PRIMARY KEY,
SNAME VARCHAR2(30),
SADDR VARCHAR2(50)
);

CREATE TABLE Part(
PID NUMBER PRIMARY KEY,

SID NUMBER,

Quantity NUMBER,
PRIMARY KEY(SID,PID),
FOREIGN KEY(SID) REFERENCES Supplier(SID),
FOREIGN KEY(PID) REFERENCES Part(PID)

Aim

Problem Statement

Consider the relations BOAT, SAILOR and RESERVES. Boats are identified by BID, color and name. Sailors are identified by SID, name and age. Sailors can reserve any number of boats and reservation details are stored in RESERVES.

Constraints

  • BID is Primary Key of BOAT.
  • SID is Primary Key of SAILOR.
  • (SID,BID,ReserveDate) uniquely identifies a reservation.
  • SID in RESERVES references SAILOR(SID).
  • BID in RESERVES references BOAT(BID).
  • A sailor can reserve many boats.
  • A boat can be reserved by many sailors.

Experiment 4

Aim

To design and implement the Banking Database and perform SQL queries.

Problem Statement

Consider the Banking database consisting of CUSTOMER, BRANCH, ACCOUNT and TRANSACTION. A customer can have savings and current accounts. Transactions may be deposits or withdrawals.

Constraints

  • CustomerID is Primary Key of CUSTOMER.
  • BranchID is Primary Key of BRANCH.
  • AccountNo is Primary Key of ACCOUNT.
  • TransactionID is Primary Key of TRANSACTION.
  • Customer can have multiple accounts.
  • Branch can maintain multiple accounts.
  • Account belongs to one Customer and one Branch.
  • Transaction belongs to one Account.
  • AccountType can be Savings or Current.

Create Table Statements

CREATE TABLE Customer(
CustomerID NUMBER PRIMARY KEY,
CustomerName VARCHAR2(30),
City VARCHAR2(30)

CREATE TABLE Branch(

Query 1

Obtain details of customers who have both Savings and Current Account.

SELECT AVG(AccountCount)

(
SELECT COUNT(*) AccountCount
FROM Account
GROUP BY BranchID

To perform MongoDB operations on Boat and Sailor collections and implement a database trigger.

Problem Statement

Create collections and perform MongoDB operations. Write a trigger to prevent modifications to EMPLOYEE table on weekends.

Create Collections

db.Boat.insertMany([
{BID:101, BName:"Sea Queen", Color:"Red"},
{BID:102, BName:"Ocean Star", Color:"Blue"},
{BID:103, BName:"Wave Rider", Color:"Red"}
]);

db.Sailor.insertMany([
{SID:1, SailorName:"Rahul", Boats:[101,102]},
{SID:2, SailorName:"Ananth", Boats:[101]},
{SID:3, SailorName:"Sneha", Boats:[103]}
]);

Query 1

Obtain the number of boats reserved by sailor Rahul.

db.Sailor.aggregate([
{$match:{SailorName:"Rahul"}},
{
$project:{
SailorName:1,
BoatCount:{$size:"$Boats"}
}
}
]);

Query 2

Retrieve boats of color Red.

db.Boat.find(
{Color:"Red"}
);

Trigger Program

Raise an error if EMPLOYEE table is modified on Saturday or Sunday.

CREATE OR REPLACE TRIGGER trg_emp_weekend
BEFORE INSERT OR UPDATE OR DELETE
ON Employee
FOR EACH ROW
BEGIN

IF TO_CHAR(SYSDATE,'DAY')
IN ('SATURDAY','SUNDAY')
THEN

RAISE_APPLICATION_ERROR(
-20001,
'Modification Not Allowed On Weekend'
);

END IF;

END;
/

Expected Output

ORA-20001:
Modification Not Allowed On Weekend

Result

MongoDB operations and trigger execution were implemented successfully.

Experiment 11

Aim

To perform MongoDB operations on Customer and Branch collections and demonstrate cursor usage in PL/SQL.

Problem Statement

Create Customer and Branch collections using MongoDB and perform the required operations. Use a cursor to copy contents from one table to another.

Create Collections

db.Branch.insertMany([
{BranchID:101, BranchName:"SBI Main"},
{BranchID:102, BranchName:"SBI City"}
]);

db.Customer.insertMany([
{
CustomerID:1,
CustomerName:"Rahul",
BranchID:101,
Accounts:[1001,1002]
},
{
CustomerID:2,
CustomerName:"Sneha",
BranchID:102,
Accounts:[1003]
}
]);

Query 1

Find Branch Name for a given Branch_ID.

db.Branch.find(
{BranchID:101},
{_id:0,BranchName:1}
);

Query 2

List total number of accounts for each customer.

db.Customer.aggregate([
{
$project:{
CustomerName:1,
TotalAccounts:{
$size:"$Accounts"
}
}
}
]);

PL/SQL Program Using Cursor

Copy contents of one table to another table.

CREATE TABLE Customer_Backup(
CustomerID NUMBER,
CustomerName VARCHAR2(30)
);

DECLARE

CURSOR c1 IS
SELECT CustomerID,
CustomerName
FROM Customer;

v_id Customer.CustomerID%TYPE;
v_name Customer.CustomerName%TYPE;

BEGIN

OPEN c1;

LOOP

FETCH c1
INTO v_id,v_name;

EXIT WHEN c1%NOTFOUND;

INSERT INTO Customer_Backup
VALUES(v_id,v_name);

END LOOP;

CLOSE c1;

COMMIT;

DBMS_OUTPUT.PUT_LINE(
'Records Copied Successfully'
);

END;
/

Expected Output

Records Copied Successfully

Result

MongoDB operations and cursor implementation were executed successfully.

Experiment 12

Aim

To perform MongoDB operations on Books and Student collections and demonstrate user-defined exception handling in PL/SQL.

Problem Statement

Create collections and perform MongoDB operations. Write a PL/SQL program that accepts two numbers and raises a user-defined exception e_bigger if the first number is larger than the second.

Create Collections

db.Books.insertMany([
{
ISBN:"123",
Title:"Database",
Author:"Korth",
Publisher:"McGrawHill"
},
{
ISBN:"124",
Title:"Operating System",
Author:"Galvin",
Publisher:"Wiley"
}
]);

db.Student.insertMany([
{
StudentID:1,
StudentName:"Rahul",
BorrowedBooks:["123"]
},
{
StudentID:2,
StudentName:"Sneha",
BorrowedBooks:["123","124"]
}
]);

Query 1

Obtain book details authored by Korth.

db.Books.find(
{Author:"Korth"}
);

Query 2

Obtain names of students who have borrowed Database books.

db.Student.aggregate([
{
$lookup:{
from:"Books",
localField:"BorrowedBooks",
foreignField:"ISBN",
as:"BookInfo"
}
},
{$unwind:"$BookInfo"},
{$match:{"BookInfo.Title":"Database"}},
{
$project:{
_id:0,
StudentName:1
}
}
]);

PL/SQL Program

User-defined Exception e_bigger

DECLARE

num1 NUMBER := 20;
num2 NUMBER := 10;

e_bigger EXCEPTION;

BEGIN

IF num1 > num2 THEN
RAISE e_bigger;
END IF;

DBMS_OUTPUT.PUT_LINE(
'First Number Is Not Larger'
);

EXCEPTION

WHEN e_bigger THEN
DBMS_OUTPUT.PUT_LINE(
'First Number Is Larger Than Second Number'
);

END;
/

Expected Output

First Number Is Larger Than Second Number

Result

MongoDB operations and user-defined exception handling were executed successfully.
