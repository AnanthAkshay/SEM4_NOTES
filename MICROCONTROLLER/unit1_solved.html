2. RISC vs. CISC Architecture & The 4 Major Design Rules
Most Important for Exam

The **RISC (Reduced Instruction Set Computer)** design philosophy forms the bedrock of modern ARM processors. It stands in contrast to the historical **CISC (Complex Instruction Set Computer)** architecture.

The 4 Major Design Rules of RISC

  1. Instructions: Reduced number of instruction classes. Every instruction is of a **fixed length** (e.g., 32 bits for ARM) to allow the pipeline to fetch subsequent instructions without complex decoding logic. Each instruction performs a simple operation that executes in a **single clock cycle**.
  2. Pipelines: Instruction processing is broken down into small stages executing in parallel. Ideally, a pipeline advances by one step per cycle, achieving an execution throughput of 1 instruction per cycle without using complex **microcode** sub-programs.
  3. Registers: RISC engines feature a large general-purpose register set. Any register can contain either data or memory addresses. These act as high-speed local memory inside the CPU.
  4. Load-Store Architecture: The processor only operates on data held in registers. It cannot perform mathematical operations directly on memory. Separate **LDR (Load)** and **STR (Store)** instructions are the exclusive means of exchanging data between the registers and external RAM.
📝 Architectural Complexity Concept In CISC, hardware is highly complex, allowing a single assembly instruction to access memory, execute math, and write back. In RISC, instruction complexity is minimized, placing greater demands on the **compiler** to synthesize complex operations using simpler instructions.
3. ARM Design Philosophy & Deviations from Pure RISC
Repeated PYQ

The standard ARM processor core does not implement a "pure" textbook RISC architecture because it is specifically designed for real-world **embedded applications** where battery constraints, memory costs, and code size are highly critical.

The 3 Core Physical Drivers of ARM Philosophy

  • Low Power Consumption: Target devices are battery-driven (phones, wearable tech). The CPU core must be physically small to minimize leakage currents and overall dynamic power.
  • High Code Density: Memory (Flash/ROM) is expensive on chip. ARM must achieve high performance with short, compact binaries.
  • Hardware Debug Support: Integrated hardware modules (like JTAG/ICE) let engineers inspect CPU registers in real time, reducing time-to-market.

How ARM Differs from "Pure" RISC (5 Major Deviations)

Deviation Feature What Pure RISC Dictates What ARM Actually Implements (The Solution)
Variable Execution Cycle Every instruction MUST execute in exactly 1 clock cycle. Multi-cycle instructions like **LDRD/STRD** (Load/Store Double) and **LDM/STM** (Load/Store Multiple) exist to optimize block transfers and speed up function entry/exit.
Inline Barrel Shifter The Arithmetic Logic Unit (ALU) operates directly on pure register values. ARM integrates a hardware **Barrel Shifter** to preprocess one register operand (shifting/rotating it) in the exact same cycle as the ALU math instruction at zero time penalty.

Enhanced DSP Instructions Only basic primitive ALU math is supported. ARM integrates specialized DSP instructions supporting fast 16x16-bit MAC (Multiply-Accumulate) operations and **saturation math** to replace dedicated hardware DSP chips.
4. Embedded Systems: Characteristics, Design, and Applications
SEE 2023, 2024

An **Embedded System** is a computerized system designed to perform a dedicated, specific function, often embedded within a larger mechanical or electrical system.

Core Characteristics of Embedded Systems

  • Single-Functioned: Executes a specific application repeatedly. Unlike a PC, it cannot be repurposed to run arbitrary software (e.g., a car engine controller only runs engine ignition logic).
  • Tightly Constrained: Must operate under strict physical limits: small size, tight cost budgets, limited power (often runs on coin cells), and constrained memory (KiloBytes).
  • Reactive and Real-Time: Must respond continuously to external inputs (sensors) and complete all mathematical calculations within strict deadlines (e.g., airbag deployment must happen within milliseconds of impact).
  • Hardware-Software Co-Design: Hardware elements (ASICs, processors) and application software must be optimized simultaneously to achieve maximum reliability.

5. Microcontroller Infrastructure: Timers, Reset Circuits, PLL, and PWM
Highly Exam-Oriented

Every microcontroller requires an operational infrastructure to handle timing, clock generation, voltage monitoring, and motor/power control.

1. Clock Generation & PLL (Phase-Locked Loops)

Microcontrollers use external quartz crystals (typically 12MHz) because of their physical stability. However, the CPU core needs high frequencies (e.g., 60MHz). A **Phase-Locked Loop (PLL)** is a closed-loop frequency-multiplier circuit that takes the low-frequency crystal clock input and multiplies it to produce a stable, high-frequency internal clock ($F_{OSC} \times M$). This provides high speeds while using cheap, low-frequency crystals on the PCB, reducing electromagnetic noise.

2. Reset Circuits & Monitoring (POR, BOR, WDT)

  • Power-On Reset (POR): When the power supply is switched on, the voltage takes time to stabilize. The POR circuit holds the MCU reset pin **LOW** until the VDD supply voltage rises above a safe threshold, preventing the CPU from executing corrupt instructions during power ramp-up.
  • Brown-Out Reset (BOR): Monitors VDD continuously. If the battery voltage dips (browns out) below a safe limit during execution, the BOR circuit forces a hardware reset to avoid memory corruption.
  • Watchdog Timer (WDT) Reset: A free-running countdown timer. Software must periodically reload (pet/feed) the WDT. If the code hangs in an infinite loop or crashes, the WDT expires and automatically triggers a system reset to self-recover.

3. Timers and Counters (The 3 Core Types)

  • Interval Timers: Use the internal crystal clock to generate precise software delays or periodic interrupts (e.g., ticking every 1ms for OS scheduling).
  • Baud Rate Generators: Timers dedicated to dividing down the CPU clock to generate standard communication rates (e.g., 9600 bps) for UART serial transmission.
  • Watchdog Timers: Dedicated safety timers that reset the microcontroller if software locks up.

4. Pulse Width Modulation (PWM) & Duty Cycle

A **Pulse Width Modulator (PWM)** is a peripheral that outputs a high-frequency square wave where the ratio of the "ON" time to the total period is adjustable. This allows digital pins to control analog systems (like LED brightness or motor speed).

$$\text{Duty Cycle (\%)} = \left( \frac{T_{ON}}{T_{ON} + T_{OFF}} \right) \times 100\% = \left( \frac{T_{ON}}{T_{\text{Total}}} \right) \times 100\%$$

For example, if a PWM wave is ON for 3ms and OFF for 3ms, $T_{\text{Total}} = 6\text{ms}$. The Duty Cycle is $\frac{3}{6} \times 100\% = 50\%$.

Q1. List and analyze the features of RISC processors that broke with traditional design techniques used in CISC based processors. [MAKEUP 2023, SEE 2023, 2024, 2025] (8 Marks)
Highly Repeated

Answer:

CISC processors were designed when memory was highly expensive and slow. To minimize program size, CISC used complex, variable-length instructions that carried out multiple memory accesses and arithmetic steps in a single assembly statement. RISC broke away from this paradigm with the following core architectural changes:

  1. Fixed 32-Bit Instruction Size: In CISC, instructions vary from 1 byte to 15 bytes, requiring highly complex instruction alignment and decode logic. RISC processors enforce a strict fixed instruction length (e.g., exactly 32 bits for ARM). This allows the CPU to fetch the next instruction before decoding the current one, enabling efficient pipelining.
  2. Single-Cycle Instruction Execution: CISC instructions take an average of 2 to 5 clock cycles (sometimes up to 100) to run because they rely on microcode sub-routines. RISC instructions are extremely simple and optimized to execute in exactly a **single clock cycle**, dramatically increasing instruction throughput.
  3. Exclusion of Direct Memory Operations (Load-Store Architecture): CISC instructions like ADD AX, [0x4000] read data from RAM, perform math, and write it back, all in a single instruction. RISC restricts mathematical instructions to operate **only on registers**. Separate, dedicated LDR (Load) and STR (Store) instructions are used exclusively to interface with RAM, isolating execution from slow memory buses.
  4. Large General-Purpose Register Bank: CISC architectures use highly dedicated, special-purpose registers (e.g., Accumulator AX, Segment Registers). RISC systems feature a large pool of symmetric, general-purpose registers (typically 16 or 32 registers), any of which can hold either data or memory addresses.
  5. Hardwired Control Unit: CISC relies on microprogramming (an internal read-only memory containing microcode steps to decode complex instructions). RISC eliminates microcode entirely, using hardwired logic gates to decode instructions instantly in a single cycle.
Boxed Conclusion: The Fundamental Paradigm Shift CISC emphasizes hardware complexity to minimize code size, while RISC shifts the burden of complexity to the compiler, which optimizes software sequences to execute simple, high-speed instructions.
Q2. List and explain the three types of timers in a microcontroller unit. [MAKEUP 2023, SEE 2023] (7 Marks)

Answer:

A typical Microcontroller Unit (MCU) contains three main classifications of timers, distinguished by their functional purpose and clock source connection:

  1. Interval Timers:
    • Working Principle: Driven directly by the system clock (often divided by a prescaler). They increment a timer register (e.g., a 16-bit or 32-bit register) at regular, known intervals.
    • Function: When the timer overflows (counts up to maximum value and resets), it triggers a hardware interrupt. This is used by the operating system to generate accurate software delays, execute real-time operating system (RTOS) ticks, or schedule periodic tasks (like reading a sensor every 10ms).
  2. Baud Rate Generators / Communication Timers:
    • Working Principle: Highly specialized timer modules that divide down the peripheral clock to produce a very precise frequency that matches standard communication speeds.
    • Function: Provides the clock source for serial communication interfaces (such as UART serial ports, I2C, or SPI). For example, it calculates and outputs the exact frequency needed to transmit data at 9600, 115200, or 1Mbps without data synchronization drift.
  3. Watchdog Timers (WDT):
    • Working Principle: An independent, free-running countdown timer driven by a separate, dedicated internal oscillator to ensure it functions even if the main system clock fails.
    • Function: Used as a safety guard. Under normal execution, the software must continuously reset (or "kick") the Watchdog counter back to its maximum value. If the microcontroller locks up (due to an infinite loop, EMI noise, or a software crash), the code fails to reset the Watchdog. The WDT then counts down to zero and automatically triggers a hardware system reset, allowing the system to self-recover without human intervention.
Summary of Timer Categories: • Interval Timer: Clocked internally for software delays & OS ticks.
• Baud Rate Generator: Clocked internally for communications timing.
• Watchdog Timer: Self-clocked safety loop to recover from system crashes.

Q4. Which are the two modes of data transfer between MCU and peripherals? Explain the general functioning of interrupts. [MAKEUP 2023, SEE 2023, 2025] (8 Marks)

Answer:

The two fundamental modes of handling data transfer between a Microcontroller Unit (MCU) and its connected peripheral modules are:

  1. Polled Mode (Polling / Programmed I/O):
    • The CPU repeatedly checks the status register of a peripheral module in an infinite loop (e.g., waiting for a UART receive flag to become 1).
    • Drawback: Extremely inefficient. The CPU wastes clock cycles doing nothing but checking status flags, leaving it unavailable to perform other calculations.
  2. Interrupt Mode:
    • The CPU initiates a process and goes back to executing its main application instructions. When the peripheral is ready with data, it asserts a hardware control line (Interrupt Request). The CPU suspends its current work, processes the transfer, and then resumes where it left off.
    • Advantage: Highly efficient. The CPU only interacts with the peripheral when active data transfer is required.

General Functioning of Interrupts (Mechanical Steps)

When an interrupt request (IRQ) is asserted by a peripheral (e.g., Timer overflow or UART char received), the processor executes the following hardware sequence:

  1. Finish Current Instruction: The CPU completes execution of the active machine instruction.
  2. Save State (Context Save): The hardware pushes the Current Program Status Register (CPSR) and the return address (Program Counter - PC) to the system stack, or saves them in dedicated link/status registers, preventing data loss.
  3. Identify Interrupt Source: The Interrupt Controller determines which peripheral asserted the interrupt and checks its priority relative to any active operations.
  4. Fetch ISR Vector Address: The CPU reads the Vector Table at a fixed address in memory to fetch the starting memory address of the corresponding **Interrupt Service Routine (ISR)**.
  5. Execute the ISR: The PC is loaded with the ISR address, and the CPU executes the user-defined software routine to handle the peripheral event.
  6. Restore Context & Return: The ISR ends with a special return instruction (like SUBS PC, LR, #4 in ARM). This pops the saved CPSR and PC registers back from the stack, allowing the CPU to resume execution of the main application code exactly where it was suspended.
Q5. List and explain three types of Reset in a typical MCU. [MAKEUP 2023] (7 Marks)

Answer:

A microcontroller must start up in a known, predictable state to ensure the program counter points to the first line of valid code. A typical MCU integrates three primary hardware reset mechanisms to handle power-up, voltage instability, and software lock-ups:

  1. Power-On Reset (POR):
    • Mechanism: Triggered when power is first applied to the microcontroller chip. The power supply VDD rails do not reach operational voltages (e.g., 3.3V) instantaneously; they ramp up over milliseconds.
    • Function: An internal RC-delay circuit holds the MCU reset pin **LOW** (active state) during this ramp-up. Once VDD rises above a safe threshold voltage ($V_{th}$), the reset signal goes HIGH, letting the CPU boot up safely. This prevents the processor from running on unstable voltages, which can cause erratic program execution.
  2. Brown-Out Reset (BOR):
    • Mechanism: Operates continuously while the system is running. It uses a precision analog comparator circuit to monitor the incoming VDD supply voltage against a fixed reference voltage.
    • Function: If the power supply drops temporarily (a "brown-out" condition, caused by battery depletion or sudden heavy motor loads), the BOR circuit detects that the voltage has slipped below safe operational limits. It immediately forces the chip into a reset state, protecting the internal flash/SRAM from corruption.
  3. Watchdog Timer (WDT) Reset:
    • Mechanism: A safety countdown timer that runs independently of the main CPU clock.
    • Function: During normal execution, the software must periodically reset (or "kick") the Watchdog counter. If the CPU crashes, hangs in an infinite loop, or stops executing code due to electrical noise, it fails to reset the Watchdog. The timer then counts down to zero and automatically triggers a system reset, allowing the system to self-recover without manual power cycling.
Comparison Summary: • POR: Protects against voltage ramp-up anomalies at startup.
• BOR: Protects against unexpected voltage drops during operation.
• WDT: Protects against software lock-ups or infinite loops.
Q6. "R in RISC is somewhat antiquated." Justify the statement. [MAKEUP 2023] (5 Marks)

Answer:

The term **RISC** stands for **Reduced Instruction Set Computer**. Historically, "Reduced" referred to a small, simple set of instruction classes (typically under 50-60 primitive instructions) to enable single-cycle hardware decoding.

However, modern RISC architectures (like ARMv7, ARMv8, or RISC-V) have evolved, and the literal interpretation of the word "Reduced" is considered antiquated for the following reasons:

  • Growing Instruction Counts: Modern RISC processors are no longer "reduced" in number. A modern ARM core features hundreds of specialized instructions, including vector processing (NEON), cryptographic acceleration, and digital signal processing (DSP) instructions.
  • Complex Mathematical Support: Early RISC designs lacked complex mathematical instructions, requiring software routines for multiplication and division. Modern RISC processors integrate dedicated hardware multipliers and floating-point units (FPUs) with complex multi-cycle instruction routines.
  • Hybrid Architectures: The line between RISC and CISC has blurred. Modern CISC processors (like Intel x86) decode complex instructions into simple, RISC-like "micro-operations" internally. Meanwhile, RISC processors use complex execution pipelines, branch prediction, and multi-cycle block memory transfers (like ARM's LDM/STM) that deviate from traditional RISC definitions.
Summary Conclusion: The "R" in RISC is antiquated because modern RISC design focuses on maintaining a Load-Store architecture and fixed instruction widths to enable efficient pipelining, rather than literally keeping the instruction count small.
Q7. Explain how the ARM instruction set differs from the pure RISC instruction set? [SEE 2023, 2025, SEE(O) 2023] (6 Marks)
Repeated PYQ

Answer:

A pure textbook RISC processor implements highly strict architectural rules to simplify hardware. The ARM core, designed specifically for power-constrained and cost-sensitive embedded systems, incorporates several **complex features** that deviate from pure RISC definitions to improve performance and code density:

  1. Variable-Cycle Block Data Transfers: Pure RISC requires every instruction to execute in exactly 1 clock cycle. ARM permits multi-cycle instructions like LDM (Load Multiple) and STM (Store Multiple). These instructions load or store up to 16 registers from/to sequential memory addresses in a single statement, improving code density and execution speed during function calls.
  2. Inline Barrel Shifter: In a pure RISC processor, shifting a register value requires a separate instruction. ARM integrates a hardware **Barrel Shifter** directly into the execution path of its data-processing instructions. This allows a register value to be shifted (e.g., shifted left by 2) and processed by the ALU in the **same clock cycle**, with zero time penalty.
  3. Thumb 16-Bit Instruction Mode: Pure RISC processors require all instructions to be a fixed length (typically 32 bits). ARM supports a secondary, compact **16-bit Thumb instruction set**. The CPU can switch dynamically between 32-bit ARM mode (for maximum performance) and 16-bit Thumb mode (to reduce code size by ~30% in memory-constrained systems).
  4. Conditional Execution of All Instructions: Unlike pure RISC, which relies on jump/branch instructions for conditional logic, almost **every 32-bit ARM instruction contains a 4-bit condition field**. The instruction is only executed if the corresponding flags in the status register match. This eliminates simple branch instructions, preventing pipeline stalls.
  5. Enhanced DSP Instructions: ARM includes specialized multi-cycle digital signal processing instructions (such as fast $16\text{-bit} \times 16\text{-bit}$ multipliers and saturation arithmetic) that deviate from traditional RISC simplicity to support media processing.
Q8. Describe the working of power on reset signal with a circuit diagram and waveform. [SEE 2023] (6 Marks)

Answer:

When power is first applied to a microcontroller, the supply voltage (VDD/VCC) does not instantly reach its stable level (e.g., 3.3V or 5V); it ramps up gradually over a few milliseconds. During this transient ramp-up, the internal digital logic gates of the CPU cannot function reliably, which can lead to erratic program execution if the CPU starts running too early.

The **Power-On Reset (POR)** circuit protects the system by holding the CPU in a reset state until the supply voltage stabilizes.

2. Detailed Working Principle

  • Voltage Ramp-Up Phase: When VCC is turned on, the capacitor $C$ is initially discharged, pulling the voltage at the RESET pin to 0V (ground level). Because the RESET pin is active-low, this holds the CPU in a reset state.
  • RC Charging Phase: Current flows through the resistor $R$ to charge the capacitor $C$. The voltage across the capacitor ($V_C$) rises exponentially according to the time constant $\tau = R \times C$, following the charging formula: $$V_{\text{RESET}}(t) = V_{CC} \left(1 - e^{-\frac{t}{RC}}\right)$$
  • Releasing Reset: As the capacitor charges, the voltage at the RESET pin eventually crosses the high-level input threshold voltage ($V_{th}$) of the MCU. The RESET pin transitions from active-low to inactive-high, releasing the CPU from the reset state. This delay gives the system oscillator and power supplies time to stabilize before the CPU executes its first instruction.
  • Discharge Diode: When power is removed, the diode $D$ allows the capacitor to discharge rapidly through the VCC line, ensuring the POR circuit is ready to trigger again if the power is cycled quickly.

Q9. List out the steps involved in the working of an interval timer. [SEE(O) 2023] (6 Marks)

Answer:

An **Interval Timer** is a peripheral that counts system clock pulses to track elapsed time. It executes the following step-by-step sequence to generate precise periodic delays or trigger software events:

  1. Timer Configuration:
    • The application software configures the Timer Control Register (TCR) to select the clock source (typically the peripheral clock, $PCLK$) and sets the mode of operation (e.g., continuous count or auto-reload mode).
  2. Set Match / Limit Value:
    • The software writes a target value to the Match Register ($MR$). This value determines the desired time interval, calculated using the formula: $$\text{Match Value} = \text{Desired Delay} \times \text{Clock Frequency}$$
  3. Prescaler Operation:
    • The clock signal passes through a Prescaler Counter ($PC$) register. The prescaler divides the input clock frequency by a configurable value (prescaler limit), allowing the timer to count at slower rates. This is useful for generating longer time delays.
  4. Timer Counter (TC) Increment:
    • With each tick from the prescaler, the main Timer Counter ($TC$) register increments by 1. This counting process runs independently in hardware, requiring no CPU intervention.
  5. Match / Overflow Detection:
    • A hardware comparator continuously compares the value of the Timer Counter ($TC$) with the target Match Register ($MR$) value.
  6. Interrupt & Action Trigger:
    • When the $TC$ value matches the $MR$ value:
      1. The hardware sets an interrupt flag in the Timer Interrupt Register (IR).
      2. An interrupt request is sent to the CPU's Interrupt Controller.
      3. If configured to do so, the Timer Counter ($TC$) is automatically reset to zero to begin the next interval (auto-reload mode).
  7. Interrupt Service Routine Execution:
    • The CPU suspends its current task and jumps to the corresponding Timer Interrupt Service Routine (ISR) to handle the timed event (e.g., toggling a GPIO pin or updating a software counter).
Q10. Why does the clock use PLL? Justify. [SEE 2024] (4 Marks)

Answer:

Microcontrollers require a stable clock signal to synchronize internal CPU operations. While high-frequency clocks (e.g., 60MHz or 100MHz) are needed for fast processing, modern microcontrollers generate this signal using a **Phase-Locked Loop (PLL)** coupled with a lower-frequency external crystal oscillator (typically 12MHz). This approach is justified by several key engineering advantages:

  1. Improved Electromagnetic Compatibility (EMC): High-frequency signals traveling over PCB traces act as miniature antennas, generating significant high-frequency electromagnetic interference (EMI). By placing a low-frequency 12MHz crystal on the board and using an on-chip PLL to multiply the frequency to 60MHz entirely within the silicon die, EMI emissions are greatly reduced.
  2. Reduced System Cost: High-frequency quartz crystals (e.g., 60MHz) are physically thin, fragile, and significantly more expensive than standard, robust low-frequency crystals (e.g., 10MHz to 12MHz). Using a PLL allows for a lower system bill of materials (BOM).
  3. Dynamic Frequency Scaling: A PLL can be configured dynamically via software. This allows the system to scale its clock frequency up during computationally intensive tasks, or down during idle periods to conserve power, enabling efficient system power management.
  4. Jitter Reduction and Phase Alignment: The PLL feedback loop filters out phase noise and jitter from the external crystal clock source, providing a highly stable, clean clock signal to the internal CPU core and high-speed peripherals.
Justification Summary: Using a PLL allows the system to run at high internal speeds while utilizing a **cheap, robust, low-frequency crystal** on the PCB, which minimizes electromagnetic interference (EMI) and system costs.
Q11. What is the relevance of duty cycle? Define the duty cycle to showcase for the 50% of its usage. [SEE 2024] (6 Marks)

Answer:

The **Duty Cycle** is the percentage of a signal's period during which the signal is active or "ON" (logic high level). It is a key parameter in Pulse Width Modulation (PWM) signals, which are used to control the average power delivered to an analog load using digital control pins.

1. Relevance of Duty Cycle

Digital outputs can only be fully ON (e.g., 3.3V) or fully OFF (0V). The duty cycle provides a way to output intermediate, average analog values. By switching a digital output high and low rapidly, the average voltage delivered to the load is directly proportional to the duty cycle:

$$V_{\text{average}} = V_{CC} \times \text{Duty Cycle}$$

This average voltage control is widely used to adjust LED brightness, control DC motor speeds, and drive analog speakers.

2. Definition & 50% Usage Case

Mathematically, the duty cycle is defined as:

$$\text{Duty Cycle (\%)} = \left(\frac{T_{ON}}{T_{ON} + T_{OFF}}\right) \times 100\% = \left(\frac{T_{ON}}{T_{\text{Total}}}\right) \times 100\%$$

For a **50% Duty Cycle** signal, the active-high time is exactly equal to the active-low time ($T_{ON} = T_{OFF}$):

$$\text{Duty Cycle} = \left(\frac{T_{ON}}{2 \cdot T_{ON}}\right) \times 100\% = 50\%$$

A **System on Chip (SoC)** integrates all the necessary electronic circuits and parts of an entire computer system—including the processor core, memory system, peripheral controllers, and analog interfaces—onto a single silicon substrate. This differs from traditional board-level designs where these components are placed as separate chips on a PCB.

Key SoC Internal Components:

  • Processor Core (CPU): The processing engine of the SoC (e.g., an ARM Cortex-M0 or ARM7TDMI core). It executes software instructions, performs mathematical calculations, and manages data flow across the chip.
  • Memory System (SRAM & Flash):
    • SRAM (Static RAM): High-speed volatile memory placed close to the CPU, used for rapid variable access and stack operations.
    • ROM/Flash: Non-volatile memory containing the primary software executable (bootloader/firmware).
  • On-Chip System Bus (Interconnect): A high-speed bus standard (such as the ARM Advanced Microcontroller Bus Architecture - **AMBA** bus) that routes data and control signals between the CPU, memory blocks, and high-performance peripherals.
  • Peripheral Modules: Digital hardware accelerators that perform dedicated tasks, saving CPU cycles:
    • GPIO Controllers: Manage input and output on the physical chip pins.
    • Timers / PWM Generators: Manage delays, count external events, and control motor outputs.
    • Serial Controllers (I2C, SPI, UART): Standard transceivers for external communications.
  • Power Management Unit (PMU): Monitors chip temperature and VDD levels, and disables clocks to unused internal modules (clock gating) or powers down sections of the silicon (power gating) to reduce battery draw during idle states.

Unit 1 Viva Voce Q&A (Quick Revision)

Use these high-yield questions for oral assessments, lab evaluations, and quick exam review:


  1. Q: What does ARM stand for originally?
    A: Originally, **Acorn RISC Machine** (developed in 1983 by Acorn Computers). Later, as a joint venture, it was renamed to **Advanced RISC Machines**.

  2. Q: Is the ARM architecture a "pure" RISC design?
    A: No. It is a hybrid RISC design that includes complex features like multi-cycle block data transfers, conditional execution of all instructions, and an inline barrel shifter to optimize code density and power consumption in embedded systems.

  3. Q: What is a Barrel Shifter?
    A: A hardware module integrated into the ARM CPU execution path that can shift or rotate one of the source operands before it is processed by the ALU, executing complex operations (like multiplying by 4) in a single cycle.

  4. Q: Why is fixed-length instruction encoding important in RISC?
    A: It simplifies the instruction fetch and decode logic, allowing the CPU pipeline to fetch the next instruction before decoding the current one, enabling parallel instruction execution.

  5. Q: Explain the purpose of a Watchdog Timer (WDT).
    A: It acts as an independent safety counter that resets the system if the software hangs or enters an infinite loop, ensuring the system can recover automatically without human intervention.

  6. Q: What is Brown-Out Reset (BOR)?
    A: An analog circuit that continuously monitors the VDD supply voltage. If the voltage drops below a safe threshold, it resets the microcontroller to prevent erratic behavior or memory corruption.

  7. Q: What is a System on Chip (SoC)?
    A: An integrated circuit that packages an entire computer system—including the processor core, memory system, peripherals, and clock generation—onto a single silicon die.

Quick Summary of Core Concepts:

  • RISC Core Philosophy: Uses simple, single-cycle instructions, a load-store architecture, and a large register set.
  • ARM Optimizations: Supports variable-cycle block memory transfers (LDM/STM), inline barrel shifting, conditional execution, and the 16-bit Thumb instruction set.
  • Embedded System Constraints: Designed for dedicated functions and must meet strict limits on physical size, cost, power consumption, and response time.
  • Microcontroller Infrastructure: Integrates Phase-Locked Loops (PLL) for internal frequency multiplication, Power-On Reset (POR) for boot stability, and Watchdog Timers (WDT) for system reliability.
