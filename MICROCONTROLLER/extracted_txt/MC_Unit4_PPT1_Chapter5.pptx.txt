5.3.1 Assembler
Directives

For each assembler, there are 'directives'.
They are specific for an assembler and are non-executable statements, which means that they don't cause any `execution' by the processor.
Directives are related solely to the assembler.
We need a few directives of the
Keil
Assembler to get started in assembly programming.

--- SLIDE 4 ---
5.3.1.1 AREA

The
“AREA”
directive instructs the assembler to assemble a new code or data section".
The above is a statement given in the user manual of
Keil

Microvi­sion
.
It implies that the assembler understands two types of information —code and data.
Data is usually stored in R/W memory (RAM) while code is in Read only memory (ROM).
The assembler requires the names of these areas of code or data.

--- SLIDE 5 ---

Typical statements that use the AREA directive are
AREA LINEAR, CODE, Read only
AREA NOTE, DATA, R/W

It is not mandatory to use the words 'Read Only' and `R/W' because by default, data is in R/W memory and code is in Read Only Memory.
Code is always in ROM, though data is also allowed to be stored there.
As a matter of fact, the R/W memory is volatile and is used only for intermediate storage of data in the course of instruction execution

--- SLIDE 6 ---
5.3.1.2 ENTRY

The ENTRY directive marks the first instruction to be executed within an application.
Because an application cannot have more than one entry point, the ENTRY directive can appear in only one of the source modules.

--- SLIDE 7 ---
5.3.1.3 END
This directive is the last line in an assembly module and it indicates that the assembler need not read
beyondthat

line.

--- SLIDE 8 ---
5.3.1.4 DCB, DCW
and
DCD
The ARM processor has a word length of 32 bits, but it can handle data of 8 bits (byte) and 16 bits (half word) also.
The
Keil
assembler, however, uses the notations of byte, word and double word for 8 bits, 16 bits and 32 bits, respectively.
The directives used are DCB for data byte, DCW for data word and DCD for data double word.
The following lines show how these directives are used.
These directives are used by the assembler to store data in ROM.

--- SLIDE 9 ---
Example
B
AG DCB 0x32, 56, Ox7E
BAG DCW Ox2234, Ox ED37, Ox9067
BOG DCD Ox DE345678,
0
x34009812
The first line says that three bytes are to be stored in contiguous loca­
tions with labels, RAG, RAG+1, and RAG+2. Recollect that each address
always corresponds to one byte of data. The second line indicates that 16
bit data is being stored in locations BAG, BAG+2 and BAG+4. The third
line states that 32 bit data is to be stored in addresses with labels BOG
and BOG+4.

--- SLIDE 10 ---
5.3.1.5
equ
The EQU directive is for equating a label to a constant.
When the label is encountered by the assembler during the process of assembly, it is replaced by its actual value.
Examples of the usage of this directive are
RAPID	EQU 65
STRT_ADDR EQU Ox84000000

--- SLIDE 13 ---
5.4
Accessing
memory
We already know that ARM is a load-store architecture.
This means that only the load and store instructions access memory directly.
There are load/store instructions with single registers, as well as with multiple registers.

--- SLIDE 14 ---
5.4.1 Single register data transfer
The word 'load' indicates that data from memory is to be moved to a register. `Store' means that data from a register is saved in memory
The format for a load/store instruction is
LDR/STR {<
cond
>}<Rd>, <addressing mode>
The operation of load/ store has a register Rd in which the data is placed. The `addressing mode' implies that an effective address is generated by address calculation.

--- SLIDE 15 ---
Example
LDR R2, [R7]
; copy into R2, the content of memory, as pointed by R7
STR R2, [R7]
; store the content of R2, into the address pointed by R7
The address of the memory location for the load/store operation is placed in a
register, called the base register. The address may be generated and put into
the base register in various calculation formats using shifting, adding offsets,
summing the contents of more registers etc.

--- SLIDE 18 ---
5.4.2 Loading/Storing data of different lengths
Data to be loaded or stored may be in bytes, half words (16 bits) or words (32 bits).
Data may be signed or unsigned, as well.
To make this explicit, the load and store instructions may be appended with the characters, B for byte, H for half word and S for signed.

5.4.3 Pre Indexing, Post Indexing and Write Back
Consider the Instruction
STR R0, [R7,#2] and LDR R0,[R7,ROR #4]
In the first instruction, it calculates the effective address as R7=R7+2.
In the second instruction, it calculates the address as R7=R7 ROR #4.

--- SLIDE 25 ---
What is the content of R7 after the execution of previous instruction?

The content of R7 remains the same as it was before the instruction execution.
Means the address calculation before, no change in R7

--- SLIDE 26 ---
Write Back(!):
If it necessary to save the effective address into the base registers,
Instruction should have the concept of “ Write Back”.
Means the instruction need to have with the sign “ !”.
Write back instruction is:
STR R0, [R7,#2]!    and    LDR R0,[R7,ROR #4]!

--- SLIDE 29 ---
5.4.4 Post Indexing
In this mode, the effective address calculation  is done after the execution of the specific instruction.
Thus, write back is inherently implied.
Take the case of the instruction LDR R2, [R7], #2
Here the data pointed by the content of R7 is first copied to R2.
After that, the content of R7 (which is the base register) is changed to R7 +2.

This is the mode when an immediate data is used as an operand.
Consider the instruction
MOV R1, #10
; move data 10 to R1
ADD R4, R2, #3
; Add 3 to the content of R2, and save the sum in R4
These instructions seems to be ok. But there is an unseen issues involved

--- SLIDE 31 ---
What is the biggest constant that can be used in the immediate mode?
All instructions of ARM are to have same size 32 bits
If an immediate data is to be included, it must fit in the 32-Bit size allocated for a data processing instruction.
Means the larger sizes of constants cannot be used in immediate data.

Space for literal pool
is:
After the END directive, so that it can be stored in ROM in the space after the code.
If the program is large and the pseudo instruction for it is far away from the end of the program, the literal pool may be beyond the range of +/-4KB.
In such cases a directive LTORG(Origin of literal pool) is used.
This directive may be included in the program to specify where we want the literal pool to be.
Placing LTORG in this place gives a warning message ‘Literal pool in executable area’.

--- SLIDE 42 ---
Literal pool are to be place in location in such a way that the processor does not consider them as instructions.
They are best placed after unconditional branch instructions.

5.4.6 Read Only and Read/Write Memory
We know that ROM is for code and RAM is for temporary storage of data.
It is important to realize that data in RAM is accessed using instructions of the processor
while data is placed in ROM using assembler directives like DCD, DCB etc.
From ROM data can be brought to RAM by
fisrt
loading it to registers using Load (LDR) instructions
Later store them using STR instructions

Block data transfer using multiple registers:
This ISA allows multiple registers to be loaded from contiguous memory locations, with the use of just one instructions.
Similarly ,the content of Multiple registers may be saved into consecutive locations in memory. Such instructions are referred to as multiple load/store instructions.
LDM {
cond
}address-mode Rn{!},
reg
-list{^}
Cond:  is an optional condition
address-mode: specifies how the memory is sequenced.
Rn: is the base register for the load operation.
! : Specifies base register write back
i.e
the address in the base register is updated after the transfer.(if the base register is in the register list then no need to specify write back)
Reg
-list: List of symbolic register names and register ranges enclosed in braces.There must be at least one register in the list.
^ :This is not to be used in the user/system mode. It is meant for use in the privileged mode
.
