--- SLIDE 14 ---
VPB divider
Volume Parameter Block(VPB)
Usually, peripherals do not work at the high frequency that the core operates at.
So the core clock is generally slowed down to one half or one fourth for use by peripherals.
The default condition at reset is for the VPB bus to run at one quarter speed.
The VPB divider determines the relationship between the processor core clock CCLK and the peripheral clock PCLK.
Another reason to do the frequency division is to reduce power dissipation.

--- SLIDE 16 ---
Low power modes
The LPC214x supports two low power modes

Idle mode
Power-down mode.
In idle mode, instruction execution is suspended until either a Reset or interrupt occurs.
Peripherals can continue to operate are during Idle mode and may generate interrupts to cause the processor to resume execution.
This mode eliminates power used by the processor itself, memory systems and related controllers and internal buses.
In power-down mode, the oscillator is shut down and the chip receives no internal clocks.
The processor state and registers, peripheral registers and internal SRAM values are preserved throughout this mode and the logic levels of chip pins remain unchanged.
This state can be exited and normal operation can be resumed by Reset or interrupt.
Chip power consumption is nearly zero.

Wake up timer
If the processor has gone to any of the low power modes, it will be awakened by a stimuli like an interrupt or reset signal.
When wake up occurs, code execution for the required application should start.
The function of the wakeup timer is to monitor the crystal oscillator to ensure that it is safe to begin code execution
Once a clock is detected wakeup timer counts 4096 clocks.
When the onboard modules initialization is complete, the processor is allowed to execute instructions.
The function of the wakeup timer is to produce a standard amount of delay.

IPOIN register
Port pins that are configured to perform only digital functions.
It will give the logic value of the pin irrespective of the pin whether the pin is an input or output, and as GPIO or an alternate digital function.
If a pin has an analog function as one of its options , the pin state cannot be read if the analog configuration is selected.
Selecting the pin as an analog input disconnects the digital features of the pin .In that case , the pin value read in the IOPIN register is not valid.
It is possible to write to the IOPIN register and then it stores the value in the port output register, bypassing the need to use both IOSET and IOCLR registers to obtain entire written value.
This feature should be used carefully in an application since it affects the entire port.
The IOPIN register may be used to write a value in the IO port register. But it cannot be used for toggling individual pin outputs.

6.1.5.2 Timers
The LPC214x family has two Timer/Counter units – Timer 0 and Timer 1, both of which are identical in features.
It is designed to count cycles of the peripheral clock (PCLK) or an externally-supplied clock.
In the PCLK unit is timer and in external clock unit is counter.
The timer module can optionally generate interrupts or perform other actions at specified time values, based on four match registers.
It also includes four capture inputs to trap the timer value when an input signal transitions, optionally generating an interrupt.

--- SLIDE 41 ---
Operation as an interval timer
Each timer is 32-bit Timer/Counter with a programmable 32-bit
Prescaler
.
The steps are as follows:
A number is loaded into a ‘Timer Count’ register (TC)
There is a match register into which another number is loaded
The Timer Count Register is given a Count Enable (CE) signal and then it starts counting up, once per cycle of PCLK
The TC register value increases, and when it becomes equal to the number in the match register, we say that a ‘match’ occurs.
The event that follows the ‘match’ can be predecided by bit settings in the match control register(MCR).
The possibilities are
Stop Timer: Generate interrupt if operating in the interrupt mode
Reset timer count register Generate interrupt if operating in the interrupt mode
Continuous operation with optional interrupt generation on match

Vectored Interrupt Controller
The Vectored Interrupt Controller (VIC) takes 32 interrupt request inputs and
programmably
assigns them into three categories – FIQ, Vectored IRQ and non-vectored IRQ.
FIQ requests have the highest priority. If more than one request is assigned to FIQ, the VIC does the
ORing
of the requests to produce FIQ signal to the processor.
Vector IRQ have the middle priority, but only 16 of the 32 requests can be assigned to this category. Any of the 32 requests can be assigned to any of the 16 vectored IRQ slots, among which slot 0 has the highest priority and slot 15 has lowest priority.
Non-vectored IRQ have the lowest priority
The VIC performs
ORing
of the requests from all the vectored and non vectored IRQ’s to produce the IRQ signal to the ARM processor.

--- SLIDE 75 ---
Serial data transmission and reception
The mechanism employed in serial data transmission and reception:
Inside the MCU, all data communication is done in parallel.
Data is moved around as either 32, 16 or 8 bits.
Thus, when data is to be transmitted or received serially, there is a parallel to serial (and vice versa) conversion involved.
For transmission, the data from a buffer register is converted to serial form, framed by adding the start, stop and parity bits and sent on the
TxD
pin.
In reception ,the bits received are kept in a buffer (named the hold register),de-framed, parallelized and moved as one byte to the CPU.
Reception and transmission are done at a rate commonly known as the baud rate.
There is a baud rate generator inside.
Baud rate can be decided by a calculation depending on the value of certain numbers in the UART registers.
The UART can work in the polled mode or in the interrupt mode.

Figure below shows the conceptual view of the UART operation.
In transmission, there is a Transmit FIFO in which the bytes to be transmitted are stored.
The 8-bit register Transmit Hold Register(THR) is the top byte of the UART transmit FIFO.
The top byte is the newest character in the Transmit FIFO and can be written via the bus interface.
The LSB represents the first bit to be transmitted.
From THR, the data is framed and serialized.
The TSR (Transmit Shift Register) does the serialization of data, and sends it out, bit by bit on the
TxD
pin.

--- SLIDE 82 ---
UART0 transmit holding register (U0THR)
This is an 8-bit register and part of the transmit buffer.
It is the top most byte of this buffer, and new characters are to be loaded into this register for being transmitted.
The data to be transmitted is written into this ‘write only’ register.
82

--- SLIDE 83 ---
UART0 FIFO control registers(U0FCR)
This is a 8-bit register
Bit 0: E: This bit must be set for enabling the Tx and Rx FIFOs
Bit 1: Rx FIFO Reset: This must be set, to clear all bytes in UART0 RX FIFO and reset the pointer logic. This bit is self-clearing.
Bit 2: Tx FIFO Reset: This must be set to clear all bytes in UART0 Tx FIFO and reset the pointer logic. This bit is self-clearing.
Bit 7 and 6: Rx trigger level: these two bits determine how many receiver FIFO characters must be written before an interrupt is activated
83

--- SLIDE 84 ---
UART0 line control register (U0LCR)
The U0LCR is an 8-bit register which determines the format of the data character that is to be transmitted or received.
The bits used here are:
Bit 1: 0: These two bits have been chosen to be ‘11’ to indicate 8-bit character length.
Bit 2: This is made ‘0’ to select one stop bit.
Bit 7: This is the Divisor Latch Access Bit (DLAB) and is set, to enable the use of divisor latch.
Other bits of this register pertain to parity and break control.
These have been disabled by making these bits to be ‘0’.
Thus we have U0LCR = 1000 0011 = 0x83
84
