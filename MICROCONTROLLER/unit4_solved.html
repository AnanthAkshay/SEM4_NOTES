📖 Core Theory & Syllabus Foundations

1. Single Register Memory Access (LDR / STR) Indexing Modes
Core Tracing Rules

ARM is a Load-Store architecture. The processor cannot perform operations on variables directly in memory; it must load them into registers first, perform the operations, and write the results back. The primary instructions used for this are **LDR (Load Register)** and **STR (Store Register)**.

Understanding the 3 Offset Indexing Modes

Indexing Mode Instruction Syntax Example Effective Target Address Base Register ($Rn$) Update Rule
Offset Indexing LDR R0, [R1, #0x04] Address = $R1 + 4$ Unchanged. $R1$ retains its original value after the transfer.
Pre-Indexed LDR R0, [R1, #0x04]! Address = $R1 + 4$ **Updated** (Written back). $R1$ is updated with the calculated address ($R1 + 4$) due to the `!` suffix.
Post-Indexed LDR R0, [R1], #0x04 Address = $R1$ **Updated** (Post-increment). The transfer occurs at the address in $R1$. Afterward, $R1$ is incremented by 4 ($R1 = R1 + 4$).
2. Block Data Transfer (LDM / STM) Stack Models
Repeated PYQ

**LDM (Load Multiple)** and **STM (Store Multiple)** instructions transfer blocks of data between a group of registers and sequential memory locations. These are widely used to push and pop registers to and from the system stack during subroutine calls.

The 4 Addressing Modes for LDM/STM:

  • IA (Increment After): The address increments after each register transfer. This is the default mode.
  • IB (Increment Before): The address increments before each register transfer, so no data is written to the initial address in the base register.
  • DA (Decrement After): The address decrements after each register transfer.
  • DB (Decrement Before): The address decrements before each register transfer.

Stack Operations Mapping

ARM uses a **Full Descending Stack** by default. Pushing registers to the stack is implemented using STMDB (Store Multiple Decrement Before), and popping registers is implemented using LDMIA (Load Multiple Increment After):

STMFD SP!, {R0-R5, LR}   ; Equivalent to STMDB: Push registers and link register to stack
LDMFD SP!, {R0-R5, PC}   ; Equivalent to LDMIA: Pop registers and return by loading LR into PC
3. LPC2148 Microcontroller: Features and Internal Bus Topology
SEE 2023, 2024, 2025

The **LPC2148** is a popular microcontroller chip based on a 16-bit/32-bit ARM7TDMI-S CPU core, manufactured by NXP Semiconductors. It integrates a wide range of peripheral interfaces, making it ideal for embedded system designs.

Key Features of the LPC2148:

  • Processor Core: 16-bit/32-bit ARM7TDMI-S CPU executing at up to 60 MHz.
  • On-Chip Memory: Includes **512 KB of High-Speed Flash ROM** (program storage) and **32 KB of SRAM** (variable and stack storage).
  • USB 2.0 Device Controller: Full-speed USB interface with 2 KB of dedicated endpoint RAM.
  • Dual ADCs: Two 10-bit Analog-to-Digital Converters (ADCs) providing a total of 14 analog input channels.
  • 10-bit DAC: Digital-to-Analog Converter (DAC) to output analog voltage waveforms.
  • Double UARTs: Two independent serial ports (UART0 and UART1) with fractional baud rate generators.
  • Fast I/O pins: Up to 45 GPIO pins, capable of fast switching.

Q1. Tracing Indexing: Trace memory loading from register offset LDR/STR. [SEE 2024, 2025] (6 Marks)
Highly Repeated

Problem Statement:

Given the initial register contents:
R6 = 0x44001100, R2 = 0x00000004, R1 = 0x11111111, and R3 = 0x00000000.
Trace the execution of each of the following instructions sequentially, calculating the effective target memory address and the final contents of $R6$, $R2$, and $R3$:

  1. LDR R2, [R6, #0x56]!
  2. STR R1, [R6, R2]!
  3. LDR R3, [R6, R2, LSL #4]

Step-by-Step Tracing Solution:

  1. Instruction 1: LDR R2, [R6, #0x56]!
    • Mechanism: This is **Pre-Indexed addressing with Write-back** (indicated by the `!`).
    • Address Calculation: The effective target address is the base register plus the immediate offset: $$\text{Target Address} = R6 + \text{0x56} = \text{0x44001100} + \text{0x56} = \text{0x44001156}$$
    • Operation: The processor loads the 32-bit word stored at memory location 0x44001156 into register $R2$.
    • Write-back Update: Because of the `!` suffix, the calculated address is written back to the base register $R6$: $$R6 = \text{0x44001156}$$
    • Final State 1: R6 = 0x44001156, R2 = [Value from 0x44001156]

  2. Instruction 2: STR R1, [R6, R2]!
    • Mechanism: This is **Pre-Indexed register offset addressing with Write-back**.
    • Address Calculation: Using the updated value $R6 = \text{0x44001156}$ from step 1, and assuming $R2$ now holds the value loaded in step 1 (let's assume $R2 = \text{0x04}$ for calculations as per the SEE question details): $$\text{Target Address} = R6 + R2 = \text{0x44001156} + \text{0x04} = \text{0x4400115A}$$
    • Operation: The processor stores the 32-bit word in register $R1$ ($\text{0x11111111}$) into memory location 0x4400115A.
    • Write-back Update: The calculated address is written back to $R6$: $$R6 = \text{0x4400115A}$$
    • Final State 2: R6 = 0x4400115A, Memory[0x4400115A] = 0x11111111

  3. Instruction 3: LDR R3, [R6, R2, LSL #4]
    • Mechanism: This is **Register offset with scaled register shift addressing** (without write-back).
    • Address Calculation: Using the updated base $R6 = \text{0x4400115A}$ and offset $R2 = \text{0x04}$:
      • First, shift the value in $R2$ left by 4 bits: $$R2 \ll 4 = \text{0x04} \ll 4 = \text{0x40} = 64_{10}$$
      • The target address is the base plus this shifted offset: $$\text{Target Address} = R6 + (R2 \ll 4) = \text{0x4400115A} + \text{0x40} = \text{0x4400119A}$$
    • Operation: The processor loads the 32-bit word stored at memory location 0x4400119A into register $R3$.
    • Write-back Update: $R6$ remains unchanged at 0x4400115A because there is no `!` suffix.
    • Final State 3: R6 = 0x4400115A, R3 = [Value from 0x4400119A]
Q2. Tracing Stack Transfers: Detail execution steps for STMDB and LDMIA instructions. [SEE 2025] (8 Marks)
Instruction Execution Steps

Problem Statement:

List the exact hardware execution steps performed by the processor for the following instructions:

  1. STMDB R1!, {R7, R2-R4} given that $R1 = \text{0x44000078}$.
  2. LDMIA R7!, {R0-R5}.

Step-by-Step Execution Tracing:

1. STMDB R1!, {R7, R2-R4} (Store Multiple Decrement Before)

This instruction writes the values of the registers in the list ($R2, R3, R4, R7$) to memory starting at the base address in $R1$.
The **DB (Decrement Before)** suffix means the address is decremented by 4 bytes **before** each register transfer.

Given the base address $R1 = \text{0x44000078}$, and a register list containing **4 registers** (total transfer size = 16 bytes):

  1. Step 1: $R1$ is decremented by 4: $$\text{Address} = \text{0x44000078} - 4 = \text{0x44000074}$$ The value of register **R7** (highest register in the list) is stored at memory location 0x44000074.
  2. Step 2: The address is decremented by 4: $$\text{Address} = \text{0x44000074} - 4 = \text{0x44000070}$$ The value of register **R4** is stored at memory location 0x44000070.
  3. Step 3: The address is decremented by 4: $$\text{Address} = \text{0x44000070} - 4 = \text{0x4400006C}$$ The value of register **R3** is stored at memory location 0x4400006C.
  4. Step 4: The address is decremented by 4: $$\text{Address} = \text{0x4400006C} - 4 = \text{0x44000068}$$ The value of register **R2** (lowest register in the list) is stored at memory location 0x44000068.
  5. Step 5 (Write-back Update): Because of the `!` suffix, the final decremented address is written back to the base register $R1$: $$R1 = \text{0x44000068}$$

Note: During block transfers, registers are always stored in memory such that the lowest-numbered register is placed at the lowest memory address, regardless of the order they are written in the instruction list.

2. LDMIA R7!, {R0-R5} (Load Multiple Increment After)

This instruction loads values from sequential memory locations starting at the base address in $R7$ into the registers in the list ($R0, R1, R2, R3, R4, R5$).
The **IA (Increment After)** suffix means the address increments by 4 bytes **after** each register transfer.

Given a register list containing **6 registers** (total transfer size = 24 bytes) and a base address starting at $R7$:

  1. Step 1: The 32-bit word at the current address in $R7$ is loaded into register **R0** (lowest register). Afterward, the address is incremented: $$\text{Address} = R7 \quad \text{then} \quad \text{Address} = R7 + 4$$
  2. Step 2: The word at address $R7 + 4$ is loaded into **R1**. The address increments to $R7 + 8$.
  3. Step 3: The word at address $R7 + 8$ is loaded into **R2**. The address increments to $R7 + 12$.
  4. Step 4: The word at address $R7 + 12$ is loaded into **R3**. The address increments to $R7 + 16$.
  5. Step 5: The word at address $R7 + 16$ is loaded into **R4**. The address increments to $R7 + 20$.
  6. Step 6: The word at address $R7 + 20$ is loaded into **R5**. The address increments to $R7 + 24$.
  7. Step 7 (Write-back Update): Because of the `!` suffix, the final incremented address is written back to $R7$: $$R7 = R7 + 24$$
Q3. Write an ARM C program to transmit strings over UART1 for LPC2148. [MAKEUP 2023, SEE 2023, 2024, 2025] (10 Marks)
Highly Repeated Program

Problem Statement:

Write a complete Embedded C program for the LPC2148 microcontroller to transmit a string (e.g., "I LOVE ISE" or "MICROCONTROLLERS") serially to a PC at a standard speed (baud rate) of **9600 bps** using the **UART1** serial port interface.

Embedded C Implementation:

#include <lpc214x.h>

// Function prototypes
void UART1_Init(void);
void UART1_SendChar(char ch);
void UART1_SendString(char* str);
void delay_ms(unsigned int ms);

int main(void) {
    // Initialize the UART1 serial port peripheral
    UART1_Init();
    
    while(1) {
        // Transmit the string serially
        UART1_SendString("I LOVE ISE\r\n");
        
        // Wait 1 second before transmitting again
        delay_ms(1000);
    }
}

void UART1_Init(void) {
    // 1. Configure the TXD1 and RXD1 serial pins on PORT0
    // PINSEL0 bits 17:16 set to 01 (configures Pin P0.8 as TXD1)
    // PINSEL0 bits 19:18 set to 01 (configures Pin P0.9 as RXD1)
    PINSEL0 |= 0x00050000;
    
    // 2. Set the data format and enable access to Divisor Latches
    // U1LCR Bit 0-1 = 11 (8-bit data length)
    // U1LCR Bit 2 = 0 (1 stop bit)
    // U1LCR Bit 3 = 0 (No parity)
    // U1LCR Bit 7 = 1 (DLAB = 1, enables divisor latch access)
    U1LCR = 0x83;
    
    // 3. Configure the Baud Rate to 9600 bps
    // For a Peripheral Clock (PCLK) of 15 MHz:
    // Divisor = PCLK / (16 * BaudRate) = 15,000,000 / (16 * 9600) = 97.65 ≈ 98 (0x62)
    // DLL holds lower 8 bits (0x62), DLM holds upper 8 bits (0x00)
    U1DLL = 0x62;
    U1DLM = 0x00;
    
    // 4. Disable access to Divisor Latches
    // U1LCR Bit 7 = 0 (DLAB = 0)
    U1LCR = 0x03;
    
    // 5. Enable and clear the transmit/receive FIFOs
    U1FCR = 0x07;
}

void UART1_SendChar(char ch) {
    // Wait until the Transmit Holding Register (THR) is empty
    // U1LSR Bit 5 (THRE) will be 1 when ready to transmit
    while (!(U1LSR & 0x20));
    
    // Load the character into the Transmit Holding Register
    U1THR = ch;
}

void UART1_SendString(char* str) {
    // Transmit each character in the string until the null terminator is reached
    while (*str) {
        UART1_SendChar(*str++);
    }
}

void delay_ms(unsigned int ms) {
    unsigned int i, j;
    for (i = 0; i < ms; i++) {
        for (j = 0; j < 10000; j++) {
            // Software delay loop
            __asm("NOP");
        }
    }
}

Detailed Line-by-Line Explanation:

  • #include <lpc214x.h>: Includes the hardware header file containing the register definitions and memory addresses for the LPC2148 microcontroller peripherals.
  • PINSEL0 |= 0x00050000;: Configures the multi-function pins P0.8 and P0.9 to act as TXD1 (transmit) and RXD1 (receive) lines for UART1.
  • U1LCR = 0x83;: Sets the **Line Control Register**. Enabling DLAB (bit 7 = 1) is necessary before writing to the divisor latch registers (DLL and DLM) to set the baud rate.
  • U1DLL = 0x62; U1DLM = 0x00;: Sets the baud rate generator divisor. A divisor value of $98$ ($\text{0x0062}$) scales a 15 MHz peripheral clock to produce a 9600 bps serial clock.
  • U1LCR = 0x03;: Clears the DLAB bit (bit 7 = 0) to lock the baud rate setting and allow normal transmit and receive operations through the UART buffer registers.
  • while (!(U1LSR & 0x20));: Polls the **Line Status Register (LSR)**. Bit 5 (THRE) remains 0 while data is being transmitted. The loop blocks until the register is empty and ready to accept the next character.
  • U1THR = ch;: Writes the character byte into the **Transmit Holding Register (THR)**, which initiates the physical serial transmission.
Q4. Write ARM Assembly Language Program to generate Fibonacci series. [SEE 2024, 2025] (8 Marks)
Repeated Program

Problem Statement:

Write an ARM7 Assembly Language Program (ALP) to generate the first 10 terms of the Fibonacci series (excluding the first term 0) and store the results in sequential memory locations starting at address 0x40000000.

ARM7 Assembly Program:

      AREA FIB_PROG, CODE, READONLY
      ENTRY

      MOV R0, #10             ; Initialize loop counter to generate 10 terms
      LDR R1, =0x40000000     ; Load destination base memory pointer in RAM
      
      MOV R2, #0              ; R2 holds the first Fibonacci term (F0 = 0)
      MOV R3, #1              ; R3 holds the second Fibonacci term (F1 = 1)
      
      ; Store the first active term (1) at the starting memory location
      STRB R3, [R1], #1       ; Store byte and post-increment memory pointer
      SUB R0, R0, #1          ; Decrement loop counter since first term is stored

LOOP  ADD R4, R2, R3          ; Calculate next Fibonacci term: Fn = Fn-1 + Fn-2
      STRB R4, [R1], #1       ; Store the term in memory and post-increment pointer
      
      MOV R2, R3              ; Shift terms: Fn-2 becomes Fn-1
      MOV R3, R4              ; Shift terms: Fn-1 becomes Fn
      
      SUBS R0, R0, #1         ; Decrement loop counter and update ALU flags
      BNE LOOP                ; Repeat loop if counter is not zero

STOP  B STOP                  ; Infinite loop to end execution
      END

Detailed Line-by-Line Explanation:

  • AREA FIB_PROG, CODE, READONLY: Assembler directive defining a new, read-only block of code named `FIB_PROG`.
  • ENTRY: Directs the assembler and debugger to mark this point as the first instruction to be executed by the CPU.
  • LDR R1, =0x40000000: Loads the base RAM address 0x40000000 into register $R1$, which serves as our memory write pointer.
  • STRB R3, [R1], #1: Stores the byte value in $R3$ into the memory address pointed to by $R1$, then increments the address pointer $R1$ by 1 byte (post-indexed offset).
  • ADD R4, R2, R3: Calculates the next term in the Fibonacci series by adding the previous two terms ($R2$ and $R3$) and storing the result in $R4$.
  • SUBS R0, R0, #1: Decrements the loop counter in $R0$ by 1 and updates the CPSR status flags.
  • BNE LOOP: If the Zero flag (Z) is 0 (indicating $R0 \neq 0$), the processor branches back to the `LOOP` label to calculate the next term.
Q5. Write an ALP to find the average of 10 numbers stored starting from "SOURCE" in ROM. [MAKEUP 2023, SEE(O) 2023] (10 Marks)
Repeated Program

Problem Statement:

Write an ARM7 Assembly Language Program (ALP) to read ten 16-bit unsigned integers stored in program ROM starting at address label SOURCE, calculate their average, and store the result in register R4.

ARM7 Assembly Program:

      AREA AVG_PROG, CODE, READONLY
      ENTRY

      MOV R0, #10             ; Set loop counter to 10
      LDR R1, =SOURCE         ; Point R1 to the start of the ROM data table
      MOV R2, #0              ; R2 will accumulate the sum (accumulator = 0)

LOOP  LDRH R3, [R1], #2       ; Load an unsigned half-word (16-bit) and increment pointer by 2
      ADD R2, R2, R3          ; Add the loaded value to the sum accumulator
      SUBS R0, R0, #1         ; Decrement the loop counter
      BNE LOOP                ; Repeat if counter is not zero

      ; Calculate the average: Average = Sum / 10
      ; Using division via successive subtraction: R2 (Sum) / R5 (10)
      MOV R4, #0              ; R4 will store the quotient (Average)
      MOV R5, #10             ; Divisor = 10

DIV   SUBS R2, R2, R5         ; Subtract divisor from the sum accumulator
      ADDPL R4, R4, #1        ; Increment quotient if result is positive or zero (PL suffix)
      BPL DIV                 ; Repeat subtraction if result is positive or zero

STOP  B STOP                  ; Infinite loop to end execution

      ; Read-only data table in ROM
SOURCE DCW 100, 250, 450, 600, 750, 900, 150, 300, 50, 800
      END

Detailed Line-by-Line Explanation:

  • LDRH R3, [R1], #2: Loads a 16-bit half-word from the memory location pointed to by $R1$ into $R3$, zero-extending it to 32 bits. The pointer $R1$ is then incremented by 2 bytes to point to the next half-word.
  • ADD R2, R2, R3: Accumulates the sum of the loaded integers in register $R2$.
  • SUBS R2, R2, R5: Subtracts the divisor ($10$) from the accumulated sum, updating the status flags.
  • ADDPL R4, R4, #1: The `PL` (Plus / Positive) suffix executes this instruction only if the N flag is 0 (indicating the result of the subtraction was positive or zero). It increments our quotient (representing the average) by 1.
  • DCW 100, 250, ...: The `DCW` (Define Constant Half-Word) directive reserves sequential 16-bit memory allocations in the flash ROM to store the data table.
Q6. List and explain Registers used in LPC2148 timer/counter units in the polled mode. [SEE 2025] (6 Marks)
Recent PYQ

Answer:

The LPC2148 microcontroller integrates two independent 32-bit Timer/Counter units (Timer0 and Timer1). In polled mode, the software configures these units and polls their status flags to measure time or count events without using interrupts. The key registers used in this configuration are:

  1. Timer Counter (TxTC):
    • A 32-bit register that increments automatically on each tick of the peripheral clock ($PCLK$, after division by the prescaler). It holds the current active timer count.
  2. Prescale Register (TxPR):
    • A 32-bit register that defines the maximum value for the Prescale Counter (PC). It controls the division of the input clock: the Timer Counter (TC) increments once every $TxPR + 1$ cycles of PCLK.
  3. Timer Control Register (TxTCR):
    • Controls the operational state of the timer:
      • Bit 0 (Counter Enable): Set to 1 to enable the timer and prescaler counters; cleared to 0 to pause them.
      • Bit 1 (Counter Reset): Set to 1 to force-clear the Timer Counter and Prescale Counter registers to zero.
  4. Match Registers (TxMR0 – TxMR3):
    • Four independent 32-bit registers. The software writes target values to these registers to define the desired time intervals or delays. The hardware continuously compares these values with the Timer Counter (TC) register.
  5. Match Control Register (TxMCR):
    • Configures the action to take when a Match Register value matches the Timer Counter (TC) value. Each match register has three control bits:
      • Interrupt (I) Bit: Set to 1 to trigger an interrupt request on a match.
      • Reset (R) Bit: Set to 1 to automatically reset the Timer Counter (TC) to zero on a match.
      • Stop (S) Bit: Set to 1 to automatically disable the timer on a match.
  6. Interrupt Register (TxIR):
    • Contains interrupt status flags for matches and external captures. In polled mode, the software continuously polls this register to detect when a match event occurs (e.g., checking if bit 0 is 1 to detect a Match0 event). Writing a 1 to a set bit clears it.

Program 6: ALP to convert BCD number to binary.

Objective: Convert a Binary Coded Decimal (BCD) number (e.g., 0x00000127 representing BCD 127) into its equivalent binary (hex) representation (which is $127_{10} = ext{0x7F}$).

      AREA PROG15, CODE, READONLY
RADIX            RN 0  ; R0 stores radix multiplier (10)
LOWERNIBBLEMASK  RN 10 ; Mask for lower 4 bits (0x0F)
UPPERNIBBLEMASK  RN 11 ; Mask for upper 4 bits (0xF0)
LOWERNIBBLE      RN 3  ; Extracted lower nibble
UPPERNIBBLE      RN 4  ; Extracted upper nibble
RESULT           RN 5  ; Accumulates binary result
NUMBYTES         RN 6  ; Counter for bytes to process
BYTE             RN 2  ; Current active byte
      
      ENTRY
      MOV RADIX, #10
      MOV LOWERNIBBLEMASK, #0x0F
      MOV UPPERNIBBLEMASK, #0xF0
      MOV RESULT, #0
      MOV NUMBYTES, #4        ; Process 4 bytes of data
      LDR R1, =NUMBER         ; ROM data address
      ADD R1, R1, NUMBYTES    ; Point to the last byte (little endian offset)
      SUB R1, R1, #1
      
LOOP  LDRB BYTE, [R1]         ; Load byte
      SUB R1, R1, #1          ; Decrement memory pointer
      AND LOWERNIBBLE, BYTE, LOWERNIBBLEMASK ; Extract lower nibble
      AND UPPERNIBBLE, BYTE, UPPERNIBBLEMASK ; Extract upper nibble
      LSR UPPERNIBBLE, #4     ; Shift upper nibble right to get integer value
      
      ; Perform multiplication and accumulation: RESULT = (RESULT * 10) + UPPERNIBBLE
      MLA RESULT, RADIX, RESULT, UPPERNIBBLE
      ; RESULT = (RESULT * 10) + LOWERNIBBLE
      MLA RESULT, RADIX, RESULT, LOWERNIBBLE
      
      SUBS NUMBYTES, NUMBYTES, #1
      BNE LOOP
      
STOP  B STOP
NUMBER DCD 0x00000127         ; BCD representation of 127
      END

Program 7: ALP to find nCr combination (without order).

Objective: Calculate the combination value $^nC_r = rac{n!}{r! \cdot (n-r)!}$ using subroutines for factorials and successive division.

      AREA PROG17, CODE, READONLY
DIVIDEND  RN 1
DIVISOR   RN 2
QUOTIENT  RN 3
REMAINDER RN 4
N         RN 10
R         RN 11
NDR       RN 12
      
      ENTRY
      LDR R5, =0x40000000     ; RAM address to store result
      MOV N, #6               ; n = 6
      MOV R, #3               ; r = 3 (compute 6C3)
      SUB NDR, N, R           ; NDR = n - r = 3
      
      MOV DIVIDEND, N         ; Calculate n! (6!)
      BL FACT
      MOV N, DIVISOR          ; Save n! result in register N
      
      MOV DIVIDEND, R         ; Calculate r! (3!)
      BL FACT
      MOV R, DIVISOR          ; Save r! in register R
      
      MOV DIVIDEND, NDR       ; Calculate (n-r)! (3!)
      BL FACT                 ; Result in DIVISOR
      
      ; Calculate denominator: Denom = r! * (n-r)!
      MUL DIVISOR, R, DIVISOR
      MOV DIVIDEND, N         ; Numerator = n!
      BL DIV                  ; Perform division
      
      STR QUOTIENT, [R5]      ; Save result to RAM
STOP  B STOP
      
FACT  MOV DIVISOR, #1
LOOP2 MUL DIVISOR, DIVIDEND, DIVISOR ; Multiply
      SUBS DIVIDEND, DIVIDEND, #1
      BNE LOOP2
      BX LR
      
DIV   MOV QUOTIENT, #0
LOOP3 SUBS DIVIDEND, DIVIDEND, DIVISOR
      ADDPL QUOTIENT, QUOTIENT, #1
      BPL LOOP3
      ADDMI REMAINDER, DIVIDEND, DIVISOR
      BX LR
      END

Unit 4 Viva Voce Q&A (Quick Revision)

Use these high-yield questions for oral assessments, lab evaluations, and quick exam review:


  1. Q: What is the purpose of the exclamation mark `!` in ARM memory instructions?
    A: It specifies **Write-back**. It updates the base address register with the newly calculated effective memory address, eliminating the need for a separate instruction to increment the address pointer.

  2. Q: Explain the difference between LDRB and LDRH.
    A: LDRB loads a single **8-bit byte** from memory and zero-extends it to 32 bits in the destination register. LDRH loads a **16-bit half-word** and zero-extends it.

  3. Q: How do you configure a GPIO pin on the LPC2148 to act as an output?
    A: By setting the corresponding pin bits in the **IODIR0** (or IODIR1) register to 1. Setting a bit to 0 configures the pin as an input.

  4. Q: What are the primary registers used to control the GPIO pins on the LPC2148?
    A:
    • **IODIR**: Sets the pin direction (0 = Input, 1 = Output).
    • **IOSET**: Writes a 1 to drive configured output pins high (3.3V).
    • **IOCLR**: Writes a 1 to drive configured output pins low (0V).
    • **IOPIN**: Used to read the digital state of the physical pins.

  5. Q: How do you clear a pending timer interrupt flag in the LPC2148?
    A: By writing a **1** to the corresponding flag bit in the Timer Interrupt Register (**TxIR**). Writing a 0 has no effect.
