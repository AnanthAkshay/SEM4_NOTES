1. Serial vs. Parallel Communication & On-Board Protocols (I2C, SPI, UART)
Highly Exam-Oriented

Microcontrollers must exchange data with peripheral sensors and other ICs. This is handled via **Serial** or **Parallel** communication.

  • Parallel Communication: Transfers multiple data bits (e.g., 8, 16, or 32 bits) simultaneously over a wide bundle of physical lines.
    Drawback: Requires massive I/O pin counts, suffers from wire crosstalk, and becomes highly complex over long PCB traces.
  • Serial Communication: Transfers data sequentially, 1 bit at a time, over a single physical line.
    Advantage: Saves CPU pins, minimizes wire track complexity, and is robust over longer distances.

2. Direct Memory Access (DMA) Typical Architecture & Functioning
Repeated PYQ

Normally, transferring data from a peripheral (e.g., UART receive buffer) to memory (SRAM) requires the CPU to execute a loop reading the peripheral register and writing it to RAM. This wastes CPU cycles. **Direct Memory Access (DMA)** is a specialized hardware controller that bypasses the CPU, transferring data directly between memory and peripherals.

ARM CPU Core (Idle / Running Math)
SYSTEM INTERCONNECT BUS (Released by CPU)
DMA CONTROLLER (Controls Bus Transfer)
UART / ADC Register → DMA Channel → SRAM Buffer
Direct Memory Access System Bus Routing Block

How a DMA Transfer Works (Step-by-Step):

  1. Configuration: The CPU configures the DMA channel, setting the **Source Address** (e.g., UART RX register), the **Destination Address** (starting address of an SRAM array), the **Transfer Count** (e.g., 256 bytes), and the trigger event.
  2. DMA Request: The CPU goes back to running its main application. When a byte arrives at the UART, the UART peripheral asserts a hardware **DMA Request** signal to the DMA controller.
  3. Bus Acquisition: The DMA controller sends a **Hold Request** to the CPU, asking for control of the system bus. The CPU completes its current bus cycle, releases the address and data buses, and returns a **Hold Acknowledge** to the DMA.
  4. Direct Transfer: The DMA controller places the UART register address on the bus, reads the byte, increments its internal destination pointer, and writes the byte directly to SRAM. This is done in 1-2 clock cycles without CPU interaction.
  5. Interrupt on Completion: The DMA decrements its transfer count. Once the count reaches zero, the DMA releases the system bus back to the CPU and asserts an interrupt to notify the CPU that the entire 256-byte data block has been successfully transferred.
3. Semiconductor Memory, SRAM Architectural Cycles & Timing Diagrams
SEE 2023, 2024, 2025

Semiconductor memory is classified into **Volatile** (SRAM, DRAM) and **Non-Volatile** (Flash, EEPROM, ROM). **Static RAM (SRAM)** uses a 6-transistor cell structure to store each bit of data, making it extremely fast because it does not require periodic charging cycles like DRAM.

SRAM Control Pins:

  • $\overline{CS}$ / $\overline{CE}$ (Chip Select / Chip Enable): Active-low signal to enable the SRAM chip.
  • $\overline{OE}$ (Output Enable): Active-low signal to enable the read buffer, placing data on the bus.
  • $\overline{WE}$ (Write Enable): Active-low signal to enable write logic, writing data into the memory cell.

Asynchronous SRAM Cycle Mechanics

  1. Read Cycle:
    • The CPU places the target memory address on the **Address Bus**.
    • The CPU asserts the active-low Chip Select ($\overline{CS} = 0$) to enable the chip, and Output Enable ($\overline{OE} = 0$) to open the data buffers. The Write Enable pin remains high ($\overline{WE} = 1$).
    • The internal SRAM logic decodes the address, accesses the memory cell, and places the stored byte on the **Data Bus** after a specified access delay ($t_{AA}$).
  2. Write Cycle:
    • The CPU places the destination address on the Address Bus and the write data on the Data Bus.
    • The CPU asserts $\overline{CS} = 0$ to enable the chip, and $\overline{WE} = 0$ to trigger a write operation. Output Enable remains inactive ($\overline{OE} = 1$).
    • The data on the bus is latched and written into the memory cells at the target address. The write cycle concludes when $\overline{WE}$ transitions back to 1.
4. Low Power Systems, Thermal Design Power (TDP) & AMBA Bus Architecture
Important Concepts

Designing Low Power Systems & TDP

Embedded systems must minimize thermal output and preserve battery life. **Thermal Design Power (TDP)** is the maximum amount of heat (measured in Watts) that the CPU and system components can generate under worst-case workloads, which the thermal dissipation system (heatsinks/cooling) is designed to handle.

Power consumption in CMOS digital systems is defined by the formula:

$$P = C \cdot V_{DD}^2 \cdot f + I_{\text{leakage}} \cdot V_{DD}$$

Where $C$ is load capacitance, $V_{DD}$ is supply voltage, $f$ is operating clock frequency, and $I_{\text{leakage}}$ is the leakage current. To reduce power consumption, systems use **dynamic voltage and frequency scaling (DVFS)**, shutting down clock trees to inactive peripheral blocks (clock gating) and powering off unused silicon segments (power gating).

ARM Advanced Microcontroller Bus Architecture (AMBA)

The AMBA system standardizes on-chip communication, splitting the SoC bus infrastructure into two main levels based on performance requirements:

  • AHB (Advanced High-Performance Bus): A high-bandwidth system bus designed to connect high-performance modules (like the ARM CPU, DMA controllers, and on-chip SRAM/Flash). It supports pipelined operations, split transactions, and wide bus widths.
  • APB (Advanced Peripheral Bus): A simpler, low-power bus designed to connect slower peripherals (like GPIO, UART, Timers, and Watchdog). The APB is connected to the AHB via an **AHB-to-APB Bridge**, which isolates high-speed system operations from slower peripheral traffic to minimize overall power consumption.
5. Software Environment, Endianness, Data Alignment & Memory Banks
Repeated PYQ

1. Embedded Software Development Environment

  • Code Editor: A text editor with syntax highlighting for writing source code (C or Assembly).
  • Cross Compiler: A compiler that runs on a development host machine (e.g., an x86 Windows PC) but generates machine code for a different target processor (e.g., an ARM Cortex-M0).
  • Debugger: Allows software developers to step through code execution, inspect register contents, and set breakpoints on the target hardware.
  • GUI (Graphical User Interface): Integrates the editor, compiler, and debugger into a single application (like Keil $\mu$Vision).

3. Data Alignment & Memory Banks

A 32-bit processor performs memory accesses in aligned 4-byte boundaries. **Aligned Data Access** means a 32-bit word is stored at a memory address that is a multiple of 4 (e.g., 0x4000, 0x4004). If data is **misaligned** (e.g., a 32-bit word is stored at 0x4001), the processor must perform **two separate memory read cycles** to fetch the word and stitch it together, which degrades execution speed.

To support byte, half-word, and word accesses in a single cycle, memory is organized into **Memory Banks**. A 32-bit memory space is split into **4 parallel byte-wide banks**. The processor uses byte-lane selection pins to read or write specific bytes without affecting adjacent data.

Q1. Discuss with appropriate diagram that illustrates the use of DMA controllers on most advanced MCUs. [MAKEUP 2023, SEE 2023, SEE(O) 2023] (8 Marks)
Repeated PYQ

Answer:

A **Direct Memory Access (DMA)** controller is a specialized hardware unit that allows peripheral modules to transfer data directly to or from the system RAM without CPU intervention. This is essential in high-performance microcontrollers because it frees the CPU core to perform complex mathematical calculations or enter low-power sleep modes while data is being transferred in the background.

ARM Core CPU (Calculates in Background)
←→ SYSTEM AHB INTERCONNECT BUS ←→
DMA Controller (Handles Bus Transfers)
Source: Peripheral (ADC/UART) → Destination: SRAM Buffers
System-on-Chip (SoC) DMA Bus Routing Topology

Working Principle of DMA Controller:

  1. Channel Initialization: The CPU configures the DMA controller by setting the **Source Register** (e.g., ADC data register), the **Destination Register** (e.g., SRAM array buffer), the **Block Size** (number of transfers), and the transfer direction.
  2. DMA Request: The CPU resumes running its main program loop. When the peripheral has data ready (e.g., the ADC completes a sample conversion), it asserts a hardware **DMA Request (DREQ)** line to the DMA Controller.
  3. Bus Masters Arbitration: The DMA controller sends a **Hold Request (HRQ)** to the CPU. The CPU completes its current bus access, releases control of the Address and Data buses, and returns a **Hold Acknowledge (HLDA)** signal. The DMA controller is now the master of the system bus.
  4. Data Transfer: The DMA controller automatically transfers data from the source peripheral address directly to the target destination RAM address. It then increments the destination address pointer and decrements the internal block counter.
  5. CPU Notification: Once the block counter reaches zero, the DMA controller releases the system bus back to the CPU and asserts an **Interrupt Request (IRQ)** to notify the CPU that the entire data block has been transferred and is ready for processing.
Q2. Discuss on the use of memory banks for a 16-bit & 32-bit processor. [MAKEUP 2023, SEE(O) 2023, SEE 2024] (6 Marks)
Repeated PYQ

Answer:

In microcontrollers, memory systems must handle variable data sizes: a byte (8 bits), a half-word (16 bits), or a word (32 bits). To read or write these different data sizes in a single clock cycle without affecting adjacent data, the memory architecture is organized into **Memory Banks**.

Memory is organized into parallel, byte-wide physical blocks (banks), each with its own write-enable and chip-select control lines.

1. Memory Banks in a 16-Bit Processor

A 16-bit processor has a 16-bit wide data bus. Its memory system is split into **2 parallel, byte-wide memory banks**:

  • Even Bank (Bank 0): Connected to the lower half of the data bus ($D_{7}-D_{0}$). It contains all bytes stored at **even memory addresses** (e.g., 0x00, 0x02, 0x04). Activated by the active-low signal $\overline{BLE}$ (Byte Low Enable) or $A_0 = 0$.
  • Odd Bank (Bank 1): Connected to the upper half of the data bus ($D_{15}-D_{8}$). It contains all bytes stored at **odd memory addresses** (e.g., 0x01, 0x03, 0x05). Activated by the active-low signal $\overline{BHE}$ (Byte High Enable).

This allows the processor to read or write a single 8-bit byte from either bank, or a 16-bit half-word from both banks simultaneously in a single clock cycle, provided the 16-bit word starts at an even address (aligned access).

2. Memory Banks in a 32-Bit Processor

A 32-bit processor (like ARM7TDMI) has a 32-bit wide data bus. Its memory system is split into **4 parallel, byte-wide memory banks**:

  • Bank 0: Connected to data lines $D_{7}-D_{0}$ (handles addresses ending in binary `00`).
  • Bank 1: Connected to data lines $D_{15}-D_{8}$ (handles addresses ending in binary `01`).
  • Bank 2: Connected to data lines $D_{23}-D_{16}$ (handles addresses ending in binary `10`).
  • Bank 3: Connected to data lines $D_{31}-D_{24}$ (handles addresses ending in binary `11`).

The processor uses four byte-select pins ($\overline{WBE_0}$ to $\overline{WBE_3}$) to enable specific banks. This allows it to read or write an 8-bit byte, a 16-bit half-word, or a 32-bit word in a single clock cycle, as long as the memory accesses are properly aligned.

Q3. Solve numerical binary arithmetic to find set flags (N, Z, C, V) for a 16-bit processor. [MAKEUP 2023, SEE 2024] (8 Marks)
Highly Analytical

Problem Statement:

For a 16-bit processor, calculate the status of the flags **N (Negative)**, **Z (Zero)**, **C (Carry)**, and **V (Overflow)** after executing each of the following operations:

  1. Subtract 0xFE45 from 0x0978.
  2. Compare A and B where $A = \text{0x9987}$ and $B = \text{0x9978}$.
  3. Add 0x6789 and 0x1234.
  4. Add 0xEF39 and 0xCD34.

Detailed Step-by-Step Solutions:

1. Subtract 0xFE45 from 0x0978 ($R = A - B$)

We are performing: $\text{0x0978} - \text{0xFE45}$.
First, represent both values in 16-bit binary:

  • $A = \text{0x0978} = \text{0000 1001 0111 1000}_2$
  • $B = \text{0xFE45} = \text{1111 1110 0100 0101}_2$

Subtraction is performed by adding the 2's complement of $B$ to $A$ ($A + \overline{B} + 1$):

  • $1\text{'s complement of } B = \text{0000 0001 1011 1010}_2$
  • $2\text{'s complement of } B = \text{0000 0001 1011 1011}_2 \quad (\text{0x01BB})$

Now perform the addition ($A + 2\text{'s complement of } B$):

  0000 1001 0111 1000  (0x0978)
+ 0000 0001 1011 1011  (0x01BB)
-------------------
  0000 1011 0011 0011  (0x0B33)

Flag Evaluation:

  • N (Negative Flag): The MSB of the result is `0`. So, the result is positive. **N = 0**.
  • Z (Zero Flag): The 16-bit result ($\text{0x0B33}$) is non-zero. **Z = 0**.
  • C (Carry/Borrow Flag): During addition, no carry-out occurred from the MSB ($C_{\text{out}} = 0$). In ARM/RISC processors, the Carry flag is inverted during subtraction ($C = \overline{C_{\text{out}}}$), indicating a borrow was required. **C = 0**.
  • V (Overflow Flag): Overflow occurs in subtraction if we subtract a negative number from a positive number and get a negative result. Here, $A$ is positive ($\text{MSB}=0$), $B$ is negative ($\text{MSB}=1$), and the result is positive ($\text{MSB}=0$). The sign is correct, so no signed overflow occurred. **V = 0**.

2. Compare A and B where $A = \text{0x9987}$ and $B = \text{0x9978}$

A comparison instruction performs subtraction ($A - B$) to update the status flags, but discards the arithmetic result.
Convert both values to binary:

  • $A = \text{0x9987} = \text{1001 1001 1000 0111}_2$
  • $B = \text{0x9978} = \text{1001 1001 0111 1000}_2$

Find the 2's complement of $B$:

  • $1\text{'s complement of } B = \text{0110 0110 1000 0111}_2$
  • $2\text{'s complement of } B = \text{0110 0110 1000 1000}_2 \quad (\text{0x6688})$

Perform the addition ($A + 2\text{'s complement of } B$):

  1001 1001 1000 0111  (0x9987)
+ 0110 0110 1000 1000  (0x6688)
-------------------
(1)0000 0000 0000 1111  (0x000F)  → Carry Out = 1

Flag Evaluation:

  • N: The MSB of the result is `0`. **N = 0**.
  • Z: The result is non-zero ($\text{0x000F}$). **Z = 0**.
  • C: A carry-out occurred from the MSB ($C_{\text{out}} = 1$), which means no borrow was required ($C = \overline{C_{\text{out}}} = 1$). **C = 1**.
  • V: Subtracting two numbers of the same sign ($A$ and $B$ are both negative, $\text{MSB}=1$) cannot result in a signed overflow. **V = 0**.

3. Add 0x6789 and 0x1234

Convert both values to binary:

  • $A = \text{0x6789} = \text{0110 0111 1000 1001}_2$
  • $B = \text{0x1234} = \text{0001 0010 0011 0100}_2$

Perform the addition:

  0110 0111 1000 1001  (0x6789)
+ 0001 0010 0011 0100  (0x1234)
-------------------
  0111 1001 1011 1101  (0x79BD)

Flag Evaluation:

  • N: The MSB of the result is `0`. **N = 0**.
  • Z: The result is non-zero. **Z = 0**.
  • C: No carry-out occurred from the MSB. **C = 0**.
  • V: We added two positive numbers ($A$ and $B$ both have $\text{MSB}=0$) and got a positive result ($\text{MSB}=0$). No signed overflow occurred. **V = 0**.

4. Add 0xEF39 and 0xCD34

Convert both values to binary:

  • $A = \text{0xEF39} = \text{1110 1111 0011 1001}_2$
  • $B = \text{0xCD34} = \text{1100 1101 0011 0100}_2$

Perform the addition:

  1110 1111 0011 1001  (0xEF39)
+ 1100 1101 0011 0100  (0xCD34)
-------------------
(1)1011 1100 0110 1101  (0xBC6D)  → Carry Out = 1

Flag Evaluation:

  • N: The MSB of the 16-bit result is `1`. **N = 1**.
  • Z: The result is non-zero. **Z = 0**.
  • C: A carry-out occurred from the MSB. **C = 1**.
  • V: We added two negative numbers ($A$ and $B$ both have $\text{MSB}=1$) and got a negative result ($\text{MSB}=1$). No signed overflow occurred. **V = 0**.
Boxed Summary of Results: 1. 0x0978 - 0xFE45 → N=0, Z=0, C=0, V=0
2. Compare 0x9987, 0x9978 → N=0, Z=0, C=1, V=0
3. 0x6789 + 0x1234 → N=0, Z=0, C=0, V=0
4. 0xEF39 + 0xCD34 → N=1, Z=0, C=1, V=0
Q4. Differentiate between Inter-Integrated Circuit (I2C) and Serial Peripheral Interface (SPI) buses. [SEE 2023, 2024, 2025] (8 Marks)
Highly Repeated

Answer:

Both I2C and SPI are synchronous, on-board serial communication protocols used to connect microcontrollers with external peripheral chips (like sensors, EEPROMs, and LCDs). They differ significantly in hardware complexity, communication speed, and networking capability:

Comparison Feature I2C (Inter-Integrated Circuit) SPI (Serial Peripheral Interface)
Number of Wires **2 wires** (SDA, SCL). Offers a simple PCB footprint. **4 wires** (MOSI, MISO, SCK, CS). Requires more PCB routing space.
Signal Pins SDA (Serial Data Line) & SCL (Serial Clock Line). MOSI (Master Out Slave In), MISO (Master In Slave Out), SCK (Clock), and CS/SS (Chip Select).
Maximum Transfer Speed Slower. Typically 100kbps (Standard) to 400kbps (Fast Mode). Some newer modes support up to 3.4Mbps. Extremely fast. Typically 10Mbps to 50Mbps or higher, limited only by the maximum clock rate of the hardware.
Device Addressing **Software Addressing**: Uses a 7-bit or 10-bit address sent over the SDA line to select the target slave device. **Hardware Addressing**: Uses individual, physical Chip Select (CS) lines for each slave device.
Master/Slave Setup Supports multi-master and multi-slave configurations. Includes bus arbitration logic. Supports a single master, multi-slave configuration. Multi-master networks are highly complex.
Duplex Mode Half-duplex (data is transmitted and received sequentially over the same SDA line). Full-duplex (data is transmitted and received simultaneously over separate MOSI and MISO lines).
Hardware Connection Uses open-drain outputs, requiring external pull-up resistors on both signal lines. Uses push-pull outputs, requiring no external pull-up resistors.
Boxed Conclusion: • Choose I2C when pin count is limited and you need to connect multiple slow peripherals.
• Choose SPI when high data transfer rates are required (e.g., SD cards, graphical displays).
Q5. Explain the current program state of an ARM7TDMI if the CPSR had the value 0xF00000D3. [SEE 2023] (7 Marks)
CPSR Bit-Mapping

Answer:

The **CPSR (Current Program Status Register)** in an ARM7 processor contains status flags, interrupt disable control bits, and processor execution state bits.

Given the 32-bit register value: $\text{0xF00000D3}$, we first convert the hex value to binary:

Hex:       F        0        0        0        0        0        D        3
Binary:  1111    0000    0000    0000    0000    0000    1101    0011

We analyze the register bits from MSB (Bit 31) to LSB (Bit 0) to determine the processor state:

1. Status Flags (Bits 31-28 - Upper Nibble 1111)

  • Bit 31 (N - Negative Flag) = 1: The result of the last ALU operation was negative.
  • Bit 30 (Z - Zero Flag) = 1: The result of the last ALU operation was zero.
  • Bit 29 (C - Carry Flag) = 1: The last ALU operation generated an unsigned carry-out or did not require a borrow.
  • Bit 28 (V - Overflow Flag) = 1: The last ALU operation caused a signed overflow.

2. Interrupt and State Control Bits (Lower Byte 0xD3 = 1101 0011)

  • Bit 7 (I - IRQ Disable) = 1: Normal hardware interrupts (IRQ) are **disabled** (masked).
  • Bit 6 (F - FIQ Disable) = 1: Fast interrupts (FIQ) are **disabled** (masked).
  • Bit 5 (T - Thumb State) = 0: The processor is executing in 32-bit **ARM State** (if $T=1$, it would be in 16-bit Thumb state).

3. Processor Mode Bits (Bits 4-0 = 10011)

The lower 5 bits define the current operating mode of the ARM7 processor. The binary value is $10011_2 = 19_{10} = \text{0x13}$.
In the ARM register mapping system, the mode value $\text{0x13}$ corresponds to **Supervisor Mode (SVC)**.

CPSR Decode Summary (0xF00000D3): • **ALU Flags**: All set (N=1, Z=1, C=1, V=1).
• **Interrupts**: Both IRQ and FIQ are disabled.
• **State**: The processor is in 32-bit **ARM Execution State** ($T=0$).
• **Mode**: The processor is running in **Supervisor Mode (SVC)**.

Unit 2 Viva Voce Q&A (Quick Revision)

Use these high-yield questions for oral assessments, lab evaluations, and quick exam review:


  1. Q: Why are I2C pins open-drain?
    A: Open-drain pins can pull a signal line to ground (0V) but cannot drive it high. Pull-up resistors are used to pull the lines high. This design prevents short circuits (bus contention) if two master devices attempt to drive the bus to opposite logic levels simultaneously.

  2. Q: What is a Full-Duplex communication interface?
    A: It allows devices to transmit and receive data simultaneously over separate physical lines (e.g., SPI's MOSI and MISO lines), unlike half-duplex (I2C) which can only transmit or receive at any given moment.

  3. Q: What is the purpose of the CPSR register in ARM?
    A: It tracks the execution state of the processor, containing condition code flags (N, Z, C, V), interrupt disable bits (I, F), the active execution state (ARM/Thumb), and the current processor operating mode.

  4. Q: How does a stack operate in ARM?
    A: ARM uses a **Full Descending Stack** by default. The Stack Pointer (SP) points to the last occupied memory location, and decrements (descends) toward lower memory addresses as new data is pushed onto the stack.

  5. Q: What is the difference between Big Endian and Little Endian formats?
    A: In Big Endian, the most significant byte (MSB) of a word is stored at the lowest memory address. In Little Endian, the least significant byte (LSB) is stored at the lowest memory address.
