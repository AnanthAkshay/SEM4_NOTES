Introduction & Features of SQL

📖 Definition

SQL (Structured Query Language): A standardized, declarative database query language used to define database structures, manipulate tables, specify integrity constraints, and query relational records. It is based on **Tuple Relational Calculus** and **Relational Algebra**.

⚡ Key Features of SQL

  • Declarative Paradigm: The user specifies *what* data to retrieve, leaving the DBMS query optimizer to determine *how* to physically search disks.
  • Comprehensive Standard: Combines DDL, DML, DCL, and TCL in a single syntax engine.
  • Dynamic Schemas: Allows modifying, dropping, or adding columns dynamically without locking the table.
  • Granular Security Permissions: Restricts user operations using SQL views and table permissions.
2

The 4 Primary SQL Language Categories

🗂️ Detailed Category Matrix

Category Purpose Core Commands Example Syntax
DDL (Data Definition Language) Defines, alters, and drops physical database schemas and structures. `CREATE`, `ALTER`, `DROP`, `TRUNCATE` `CREATE TABLE Student (...);`
DML (Data Manipulation Language) Retrieves, inserts, updates, and deletes records. `SELECT`, `INSERT`, `UPDATE`, `DELETE` `SELECT * FROM Student;`
DCL (Data Control Language) Manages granular security access permissions. `GRANT`, `REVOKE` `GRANT SELECT ON Student TO Manager;`
TCL (Transaction Control Language) Manages execution scopes of DML transactions. `COMMIT`, `ROLLBACK`, `SAVEPOINT` `ROLLBACK;`

    USN VARCHAR(10) PRIMARY KEY,

Attribute Constraints

🔒 Core Column Constraints Mapped

  • NOT NULL: Enforces that a column cannot accept NULL values (e.g., `Name VARCHAR(50) NOT NULL`).
  • UNIQUE: Enforces that all values in a column are distinct. Unlike PRIMARY KEY, a UNIQUE column **can accept a single NULL value**.
  • CHECK: Specifies a boolean condition that every row inserted into the table must satisfy. 
    Salary DECIMAL(10,2) CHECK (Salary > 15000.00)
  • DEFAULT: Automatically populates the column with a specified fallback value if the user does not provide one during insertion.
6

Key Constraints in SQL

🔑 SQL Key Implementations

  • Primary Key (PK): Uniquely identifies rows. Automatically enforces both `UNIQUE` and `NOT NULL` constraints. 
    USN VARCHAR(10) PRIMARY KEY
  • Composite Primary Key: A primary key made of multiple attributes. Must be defined at the **table level** rather than the column level: 
    CREATE TABLE Enrollments (
    USN VARCHAR(10),
    CourseID VARCHAR(10),
    Grade CHAR(1),
    PRIMARY KEY (USN, CourseID)
);
  • Foreign Key (FK): Creates a referential link to a primary key in another table. 
    DeptID INT REFERENCES Department(DeptNo)

Referential Integrity Actions Mapped

🔄 Parent-Child Referential Options

If a record in a parent table is deleted or updated while referencing records exist in the child table, the DBMS can handle the violation using one of the following referential actions:

  • ON DELETE RESTRICT (Default): Blocks the delete operation on the parent row.
  • ON DELETE CASCADE: Automatically deletes all referencing child rows when the parent row is deleted.
  • ON DELETE SET NULL: Automatically sets the child foreign key columns to NULL when the parent row is deleted.

Syntax Code:

FOREIGN KEY (DeptID) REFERENCES Department(DeptNo)
    ON DELETE SET NULL
    ON UPDATE CASCADE

ALTER TABLE Command Schema Operations

🛠️ 6 Core Schema Modification Operations

  1. Add Column: Inserts a new attribute column into the existing table schema. 
    ALTER TABLE Student ADD Phone VARCHAR(15);
  2. Modify Column Type: Changes the data type or constraint rules of an existing column. 
    ALTER TABLE Student ALTER COLUMN Name VARCHAR(100);
  3. Drop Column: Removes an attribute column and all its stored values from the table schema. 
    ALTER TABLE Student DROP COLUMN Phone;
  4. Add Constraint: Applies a new key or integrity constraint to the table. 
    ALTER TABLE Student ADD CONSTRAINT check_gpa CHECK (GPA >= 0.0);
  5. Drop Constraint: Removes an existing constraint from the table schema. 
    ALTER TABLE Student DROP CONSTRAINT check_gpa;
9

DROP TABLE & DATABASE Rules

⚠️ DROP vs. TRUNCATE Operations

  • DROP TABLE: Permanently deletes the table structure, all its stored rows, and all its metadata from the system catalog. 
    DROP TABLE Student;
  • TRUNCATE TABLE: Deletes all rows inside the table but **preserves the table structure and schema headers** in the catalog. 
    TRUNCATE TABLE Student;

The SELECT-FROM-WHERE Query Structure

📖 Definition

The standard SQL data retrieval construct maps conceptually directly to Relational Algebra unary operations:

`SELECT ` $A_1, A_2, \dots$ ` FROM ` $R_1, R_2$ ` WHERE ` $\langle \text{condition} \rangle \equiv \pi_{A_1, A_2}(\sigma_{\text{condition}}(R_1 \times R_2))$

🔄 Logical Execution Pipeline

When you execute a query, the SQL engine processes clauses in a specific logical order rather than the order they are written:

[ Step 1: FROM ]  ===> Identifies input source tables and performs Cartesian Product / Joins
[ Step 2: WHERE ] ===> Filters tuples horizontally based on conditions
[ Step 3: SELECT] ===> Filters columns vertically (Projection) and computes aliases

Aliasing (Table & Column AS Keyword)

🏷️ Code Implementations

  • Column Alias: Renames the header of the returned result set for readability. 
    SELECT FName AS FirstName, LName AS LastName FROM EMPLOYEE;
  • Table Alias: Creates a shorthand alias for a table name. Crucially needed for self-joins or queries referencing multiple tables with matching column names: 
    SELECT e.FName, d.DeptName 
FROM EMPLOYEE AS e, DEPARTMENT AS d 
WHERE e.DeptNo = d.DeptNo;

Pattern Matching (LIKE & Wildcards)

🔍 Wildcard Characters

  • Percent sign (`%`): Matches **zero or more** characters.
  • Underscore (`_`): Matches **exactly one** character.
  • LIKE: Returns TRUE if the value matches the pattern.
  • NOT LIKE: Returns TRUE if the value does not match the pattern.

Pattern Examples:

Pattern CodeMeaningMatching Example
`LIKE 'A%'`Starts with the uppercase letter 'A'.'Akshay', 'Ananth'
`LIKE '%n'`Ends with the lowercase letter 'n'.'John', 'Ananth'
`LIKE '%ABC%'`Contains the substring 'ABC' anywhere in the value.'XYZABC123'
`LIKE '_a%'`Contains 'a' as the second character.'Rahul', 'Kabir'

Arithmetic Operators & ORDER BY Sorting

🧮 Math & Sorting Implementations

Part C — Complex Queries & Subqueries

NULL & Three-Valued Logic (IS NULL, IS NOT NULL)

⚠️ CRITICAL EXAM POINT: Testing for NULL

You cannot use standard equality operators to check for NULL values (e.g., `Salary = NULL` is invalid and always evaluates to **UNKNOWN**). Instead, you must use the special **`IS NULL`** and **`IS NOT NULL`** operators:

SELECT FName FROM EMPLOYEE WHERE SuperSSN IS NULL;
15

Nested Subqueries (IN, ANY, ALL, Correlated)

🧬 Set Predicate Operators Mapped

  • IN: Evaluates to TRUE if the column value exists in the set returned by the nested subquery. 
    SELECT FName FROM EMPLOYEE WHERE SSN IN (SELECT ESSN FROM WORKS_ON);
  • ANY / SOME: Evaluates to TRUE if the comparison is TRUE for **at least one** value in the subquery's result set: 
    SELECT FName FROM EMPLOYEE WHERE Salary > ANY (SELECT Salary FROM EMPLOYEE WHERE DeptNo = 5);
  • ALL: Evaluates to TRUE if the comparison is TRUE for **all** values in the subquery's result set: 
    SELECT FName FROM EMPLOYEE WHERE Salary > ALL (SELECT Salary FROM EMPLOYEE WHERE DeptNo = 5);
16

EXISTS & UNIQUE Subquery Operations

1. EXISTS Operator Highly Repeated

Definition: A boolean operator used to check if a subquery returns **at least one row**. If the subquery yields one or more matching rows, `EXISTS` evaluates to TRUE; if it yields zero rows, it evaluates to FALSE.

Correlated Subquery Example: Find employees who work on at least one project.

SELECT e.FName, e.LName 
FROM EMPLOYEE AS e 
WHERE EXISTS (
    SELECT * 
    FROM WORKS_ON AS w 
    WHERE w.ESSN = e.SSN
);

2. UNIQUE Operator

Evaluates to TRUE if the subquery returns no duplicate rows (i.e., all returned tuples are unique).

17

Joins in SQL (Inner, Left, Right, Full, Self, Cross)

🧩 SQL Join Types Mapped

1. INNER JOIN (Standard Match)

Returns rows only when there is a match in both tables based on the join condition.

SELECT e.FName, d.DeptName 
FROM EMPLOYEE AS e 
INNER JOIN DEPARTMENT AS d ON e.DeptNo = d.DeptNo;

2. LEFT OUTER JOIN

Returns all rows from the left table, plus matching rows from the right table. Missing values in right table columns are filled with NULLs.

SELECT e.FName, d.DeptName 
FROM EMPLOYEE AS e 
LEFT JOIN DEPARTMENT AS d ON e.DeptNo = d.DeptNo;

3. RIGHT OUTER JOIN

Returns all rows from the right table, plus matching rows from the left table. Missing values in left table columns are filled with NULLs.

SELECT e.FName, d.DeptName 
FROM EMPLOYEE AS e 
RIGHT JOIN DEPARTMENT AS d ON e.DeptNo = d.DeptNo;

4. SELF JOIN

Joins a table to itself. Requires using unique aliases for each instance of the table. Useful for hierarchical records.

Example: Find the name of each employee and the name of their direct supervisor.

SELECT emp.FName AS EmpName, mgr.FName AS MgrName 
FROM EMPLOYEE AS emp 
LEFT JOIN EMPLOYEE AS mgr ON emp.SuperSSN = mgr.SSN;

Aggregate Functions: COUNT, SUM, AVG, MIN, MAX

📊 Aggregate Operation Code Examples

Aggregate functions perform a calculation on a set of values in a column, returning a single value. They **ignore NULL values** except for `COUNT(*)`:

SELECT 
    COUNT(*) AS TotalEmployees,
    SUM(Salary) AS TotalSalaries,
    AVG(Salary) AS AverageSalary,
    MIN(Salary) AS MinimumSalary,
    MAX(Salary) AS MaximumSalary 
FROM EMPLOYEE;

GROUP BY & HAVING Filtering Clauses

⚠️ CRITICAL REQUIREMENT: GROUP BY Select Constraint

When using a `GROUP BY` clause, **every column in the SELECT list must either**:

  1. Be explicitly specified as a grouping attribute in the `GROUP BY` clause, or
  2. Be enclosed inside an aggregate function (e.g., `SUM()`, `AVG()`).

Violating this rule throws a syntax compilation error.

⚙️ HAVING vs. WHERE Clause Comparison

Understanding where to filter rows vs. where to filter grouped results is critical:

Parameter WHERE Clause HAVING Clause
Logical Purpose Filters individual **row tuples** before logical grouping occurs. Filters **grouped sets** after the GROUP BY execution.
Aggregation Support Cannot contain aggregate functions (e.g., `WHERE SUM(Salary) > 10` is invalid). Enforces filter predicates containing aggregate functions.
Execution Phase Processed **before** the `GROUP BY` operation. Processed **after** the `GROUP BY` operation.

📝 Complete Code Example

List departments with more than 5 employees earning over 30,000, and show the department ID and total employees.

SELECT DeptNo, COUNT(SSN) AS NumEmps
FROM EMPLOYEE
WHERE Salary > 30000.00            -- row filter
GROUP BY DeptNo
HAVING COUNT(SSN) > 5;            -- group filter

INSERT Command Operations

    INSERT INTO HonorRollStudents (USN, Name, GPA)

Q1. Discuss all attribute constraints supported in SQL. 10 Marks

Answer: Refer to Section 5. Constraints are rules enforced on data columns to ensure data integrity: 1. `NOT NULL`: Column cannot hold NULL values. 2. `UNIQUE`: Ensures all column values are unique. 3. `CHECK`: Validates that data satisfies a boolean predicate. 4. `DEFAULT`: Provides a default fallback value. 5. `PRIMARY KEY`: Unique row identifier (enforces UNIQUE + NOT NULL). 6. `FOREIGN KEY`: Enforces referential integrity links.

Q2. Explain the difference between WHERE and HAVING clauses. 5 Marks

Answer: Refer to the comparison table in Section 19. The **WHERE clause** is used to filter rows **before** any grouping occurs and cannot contain aggregate functions. The **HAVING clause** is used to filter grouped sets **after** the `GROUP BY` clause has been processed and typically filters on aggregated values (e.g., `HAVING AVG(Salary) > 50000`).

Q3. Explain the EXISTS operator in SQL with an example. 5 Marks

Answer: Refer to Section 16. `EXISTS` is a boolean operator that evaluates to TRUE if a nested subquery returns one or more rows. It does not return actual records; instead, it optimizes search processes by terminating early as soon as a match is found. It is commonly used in correlated subqueries.

🧠 Common Exam & Query Mistakes

  • Checking for NULL using equal sign: Writing `WHERE Salary = NULL` (Incorrect) instead of **`WHERE Salary IS NULL`** (Correct).
