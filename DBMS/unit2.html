Relational Model Core Concepts & Domains

📖 Definitions

Relational Model: First proposed by Dr. E.F. Codd of IBM in 1970, it represents the database as a collection of mathematically structured relations (informally called **tables**). Each relation consists of a set of attributes (columns) and tuples (rows).

Domain ($D$): A set of atomic (indivisible) values. Each attribute in a relation must derive its values from a specific pre-defined domain. It has a data type and a specific format (e.g., `Phone_No` is a 10-digit numeric string).

Tuple ($t$): An ordered list of values representing a single real-world record in the table. An $n$-tuple contains $n$ values.

📐 Mathematical Definition of a Relation

A relation schema $R(A_1, A_2, \dots, A_n)$ is made up of a relation name $R$ and a list of attributes $A_i$. A relation state (or relation instance) $r(R)$ is a mathematical subset of the **Cartesian Product** of the domains of its attributes:

$r(R) \subseteq \text{dom}(A_1) \times \text{dom}(A_2) \times \dots \times \text{dom}(A_n)$

This means if we take every possible combination of values from each attribute's domain, the active database table will contain a small subset of those combinations at any given instant.

The 6 Primary Characteristics of Relations VTU Repeated

⚙️ Key Structural Characteristics

  1. Ordering of Tuples in a Relation: A relation is defined as a mathematical set of tuples. In mathematics, sets do not have a defined order. Therefore, the order in which rows are stored or retrieved does not affect the logical meaning of the relation.
  2. Ordering of Values within a Tuple: An $n$-tuple is an ordered list of $n$ values. However, at the logical level, because every attribute value is explicitly bound to an attribute column name, the physical order of columns is irrelevant.
  3. Values in a Tuple must be Atomic: Every cell in a relation must contain exactly one single indivisible value. Multi-valued composite fields or nested tables are strictly prohibited (this property corresponds to **First Normal Form (1NF)**).
  4. No Duplicate Tuples: By definition, a mathematical set contains unique elements. Hence, no two tuples in a relation instance can have identical values for all attributes.
  5. Attribute Names are Unique: Within a single relation schema $R$, no two attribute columns can share the same name.
  6. Domain Integrity: Every value in a column must strictly belong to the domain associated with that attribute.

The 4 Core Relational Model Constraints Highly Important

1. Domain Constraint

Rule: The value of each attribute $A$ in a tuple must be an atomic value from the domain $\text{dom}(A)$ associated with that attribute. This includes data types, sizes, ranges, and formats.

Example: `GPA` has domain `DECIMAL(3,2)` with range `0.00` to `10.00`.

Violation: Inserting a row where `GPA = 11.50` or `GPA = 'A+'` violates the domain constraint. The DBMS rejects the operation, throwing a type mismatch error.

2. Key Constraint (Super Key & Candidate Key uniqueness)

Rule: No two distinct tuples in any relation state $r(R)$ can have identical values for their **Candidate Key** attributes. The primary key uniquely identifies each record.

Example: In a table `STUDENT`, `USN` is chosen as the Primary Key.

Violation: Attempting to insert a new student with `USN = '1MS24IS001'` when a student with that USN already exists in the table. The DBMS blocks the transaction, raising a **Unique Key Constraint Violation**.

3. Entity Integrity Constraint

Rule: No attribute that is a member of the primary key of a relation schema $R$ can hold a **NULL** value in any tuple of any relation state $r(R)$.

Purpose: Primary keys identify individual records. If a primary key attribute is allowed to be NULL, the database cannot identify or reference that specific row.

Violation: Inserting `STUDENT(USN = NULL, Name = 'Akshay', GPA = 9.8)` violates this constraint. The DBMS halts the operation, throwing an **Entity Integrity / NOT NULL Constraint Violation**.

4. Referential Integrity Constraint (Foreign Key rules)

Rule: Used to maintain consistency between tuples in two relations (the referencing relation $R_1$ and the referenced relation $R_2$). A foreign key value in $R_1$ **must** either:

  1. Match a valid primary key value of some tuple in $R_2$, or
  2. Be entirely **NULL** (unless marked `NOT NULL` explicitly by business rules).
 Referencing Relation: STUDENT                 Referenced Relation: DEPARTMENT
+------------------------------------+        +------------------------------+
| USN        | Name     | DeptID (FK)| ======▶| DeptID (PK)| DeptName        |
+------------+----------+------------+        +------------+-----------------+
| 1MS24IS001 | Akshay   |   10       |        |   10       | Info Science    |

Violation: Attempting to insert a student with `DeptID = 99` when no department with `DeptID = 99` exists in the `DEPARTMENT` table. The DBMS blocks this operation, throwing a **Referential Integrity / Foreign Key Violation**.

NULL Values in Relations & Three-Valued Logic

❓ Semantic Meanings of NULL

In relational databases, a **NULL** value represents a placeholder indicating that a value is missing or unknown. It can represent three distinct scenarios:

  • Value Exists but is Unknown: The student has a phone number, but it has not been recorded yet.
  • Value is Not Applicable: The attribute does not apply to this record (e.g., `Spouse_Name` for an unmarried employee).
  • Value is Withheld: The customer refuses to provide their email address.

📊 Three-Valued Logic (3VL)

Because database comparisons can involve NULL, SQL uses Three-Valued Logic, yielding three truth values: **TRUE**, **FALSE**, and **UNKNOWN**. Comparisons with NULL (e.g., `Age = NULL` or `Age > 21` when Age is NULL) evaluate to **UNKNOWN**:

Operand A Operand B AND OR NOT A
TRUE UNKNOWN UNKNOWN TRUE FALSE
FALSE UNKNOWN FALSE UNKNOWN TRUE
UNKNOWN UNKNOWN UNKNOWN UNKNOWN UNKNOWN

Update Operations & Constraint Violations

⚡ Transaction Constraints Violations & DBMS Remediation

When database update operations (`INSERT`, `DELETE`, `UPDATE`) occur, they can violate the integrity constraints of the database. The DBMS handles these violations based on pre-defined referential actions:

Update Operation Possible Constraint Violations Standard DBMS Recovery Solutions
INSERT Domain, Key, Entity Integrity, Referential Integrity **REJECT:** DBMS blocks the insertion and rollbacks the transaction.
DELETE Referential Integrity (if parent row is deleted while referenced) 1. **RESTRICT (Default):** Rejects the delete operation.
2. **CASCADE:** Deletes all referencing child rows automatically.
3. **SET NULL:** Sets child foreign keys to NULL.
4. **SET DEFAULT:** Sets child foreign keys to default values.
UPDATE Domain, Key, Entity Integrity, Referential Integrity **CASCADE / SET NULL:** Updates matching foreign key values in child rows, or blocks the operation if it violates primary key uniqueness.

🛠️ Example SQL Referential Actions Syntax

CREATE TABLE Student (
    USN VARCHAR(10) PRIMARY KEY,
    Name VARCHAR(50) NOT NULL,
    DeptID INT,
    FOREIGN KEY (DeptID) REFERENCES Department(DeptID)
        ON DELETE CASCADE
        ON UPDATE CASCADE
);

If a department is deleted from the `Department` table, all students belonging to that department will be automatically deleted (**ON DELETE CASCADE**). If a department's ID is changed, the students' department IDs will be updated automatically (**ON UPDATE CASCADE**).

Database Transactions: Commits and Rollbacks

📖 Definition

A Transaction is a single logical unit of database processing that performs a sequence of operations (reads and writes). It must execute in its entirety or not at all, adhering to ACID properties.

🔄 Commit vs. Rollback Scenarios

  • COMMIT: Permanently saves all transaction updates to the physical storage disk. Once a transaction is committed, its changes cannot be undone.
  • ROLLBACK: Undoes all changes made during the current transaction, returning the database to its last consistent state before the transaction started. This is used if a constraint violation or system crash occurs mid-transaction.

Unary Operations: SELECT (σ) & PROJECT (π)

SELECT Operator ($\sigma$) Core Operator

Mathematical Definition: Used to select a subset of tuples from a relation that satisfy a specific selection condition. It acts as a **horizontal filter**.

Syntax: $\sigma_{\langle \text{condition} \rangle}(R)$

Boolean Operators: Conditions can be combined using **AND** ($\land$), **OR** ($\lor$), and **NOT** ($\neg$). Comparison operators include $=, \neq, <, \leq, >, \geq$.

Input Relation: EMPLOYEE

SSNNameDeptIDSalary
E01Akshay1095000
E02Ananth2098000
E03Rahul1075000

Example Query: Find all employees in Dept 10 with a salary greater than 80,000.

Algebraic Expression: $\sigma_{\text{DeptID} = 10 \land \text{Salary} > 80000}(\text{EMPLOYEE})$

Result Table:

SSNNameDeptIDSalary
E01Akshay1095000

PROJECT Operator ($\pi$) Core Operator

Mathematical Definition: Used to select a subset of columns (attributes) from a relation, discarding the remaining columns. It acts as a **vertical filter**.

Syntax: $\pi_{\langle \text{attribute list} \rangle}(R)$

⚠️ CRITICAL EXAM POINT: Duplicate Removal

Because relational algebra is based on mathematical set theory, **duplicate tuples are strictly removed** from the output of a PROJECT operation. In SQL, duplicates are retained by default unless the `DISTINCT` keyword is explicitly specified.

Example Query: List all unique department IDs of working employees.

Algebraic Expression: $\pi_{\text{DeptID}}(\text{EMPLOYEE})$

Intermediate State (before duplicate removal): `[10]`, `[20]`, `[10]`

Final Result Table (duplicates removed):

DeptID
10

Relational Algebra Set Operations (Union, Intersect, Difference, Product)

⚠️ CRITICAL REQUIREMENT: Union Compatibility

For binary set operations—**UNION** ($\cup$), **INTERSECTION** ($\cap$), and **SET DIFFERENCE** ($-$)—to be performed, the two input relations $R$ and $S$ must be **Union Compatible**:

  1. They must have the exact same number of attributes (columns).
  2. The domain of corresponding attributes must be identical (i.e., the data type of the $i$-th column of $R$ must match the $i$-th column of $S$).

Set Operations Overview

  • UNION ($R \cup S$): Combines all tuples from both relations, automatically removing duplicate rows.
  • INTERSECTION ($R \cap S$): Returns only the tuples that exist in both relations $R$ and $S$.
  • SET DIFFERENCE ($R - S$): Returns tuples that exist in relation $R$ but not in relation $S$. This operation is **not commutative** ($R - S \neq S - R$).
  • CARTESIAN PRODUCT ($R \times S$): Combines every tuple of relation $R$ with every tuple of relation $S$. If $R$ has $n_1$ tuples and $S$ has $n_2$ tuples, the result relation has $n_1 \times n_2$ tuples.

Binary Operations: Theta Join, Equi Join, & Natural Join

1. Theta Join ($\bowtie_\theta$)

Definition: General join operation that combines related tuples from two relations based on a general join condition $\theta$.

Syntax: $R \bowtie_{\theta} S$ where $\theta$ is a boolean expression of the form $A_i \, \text{op} \, B_j$ (op can be $=, \neq, <, >, \text{etc.}$).

2. Equi Join ($\bowtie_{=}$)

Definition: A special type of Theta Join where the join condition uses **only the equality operator** ($=$).

Syntax: $R \bowtie_{R.A = S.B} S$

3. Natural Join ($\bowtie$) Highly Repeated

Definition: A special type of Equi Join that automatically joins two relations on **all columns that share the same name**. Crucially, it automatically **removes duplicate join columns** in the output relation.

Syntax: $R \bowtie S$

Input Relation R:

USNNameDeptID
S01Akshay10
S02Ananth20

Input Relation S:

DeptIDDeptName
10IS
20CS

Algebraic Expression: $R \bowtie S$

Result Table:

USNNameDeptIDDeptName
S01Akshay10IS
S02Ananth20CS

*Notice that `DeptID` appears only once in the final result table.*

Outer Joins (Left, Right, and Full)

🧩 Hiding Missing Info with NULLs

In standard inner joins, if a tuple in one relation does not have a matching tuple in the other relation, that tuple is discarded from the result. **Outer Joins** preserve these unmatched tuples, filling the missing columns with **NULL** values:

  • Left Outer Join ($R \rtimes S$): Preserves **all tuples from the left relation** $R$. If there are no matching tuples in the right relation $S$, the columns of $S$ are filled with NULLs.
  • Right Outer Join ($R \ltimes S$): Preserves **all tuples from the right relation** $S$, filling missing left relation columns with NULLs.
  • Full Outer Join ($R \text{ ⟗ } S$): Preserves **all tuples from both relations**, filling missing columns on either side with NULLs.

The Division Operation (÷) Deep Dive VTU 10-Mark Favorite

📖 Definition

The Division Operation ($R \div S$) is used to solve queries that contain the keyword **"for all"** or **"for every"** (e.g., finding employees who work on *all* projects controlled by a department).

If $R(X, Y)$ and $S(Y)$ are two relations, the result of $R \div S$ is a relation $T(X)$ that contains all values of $X$ that are paired with **every single value** of $Y$ in relation $R$.

📐 Why is Division Difficult?

Division is a derived operator. It is not a fundamental operator in relational algebra and must be expressed using other basic operators (SELECT, PROJECT, Cartesian Product, and Set Difference):

$R \div S \equiv \pi_X(R) - \pi_X((\pi_X(R) \times S) - R)$

Step-by-step breakdown of this equivalence:

  1. $\pi_X(R) \times S$: Generates all possible combinations of $X$ values with $S$ values.
  2. $(\pi_X(R) \times S) - R$: Finds the combinations that **do not exist** in the actual relation $R$ (i.e., finding which $X$ values are *missing* a pairing with some $Y$ value).
  3. $\pi_X(\dots)$: Collects the $X$ values that have missing pairings.
  4. $\pi_X(R) - \dots$: Subtracts the incomplete $X$ values from the set of all $X$ values, leaving only the $X$ values that are paired with **all** $Y$ values.

Additional Operations: RENAME, ASSIGNMENT, & AGGREGATE

1. RENAME Operator ($\rho$)

Used to rename the attributes of a relation, or the relation itself. Useful for self-joins.

Syntax: $\rho_{S(B_1, B_2, \dots, B_n)}(R)$ (renames relation $R$ to $S$, and its attributes to $B_i$).

2. ASSIGNMENT Operator ($\leftarrow$)

Allows breaking down complex, nested relational algebra queries into smaller, sequential steps by assigning intermediate results to temporary relation variables (similar to programming variables).

Syntax: $\text{TEMP\_REL} \leftarrow \sigma_{\text{DeptID} = 10}(R)$

3. AGGREGATE & GROUPING Operator ($\Im$) Core Operation

Used to perform aggregate calculations (SUM, AVG, COUNT, MIN, MAX) on columns, optionally grouping rows by specific attributes.

Syntax: $_{\langle \text{grouping attributes} \rangle}\Im_{\langle \text{function list} \rangle}(R)$

Example Query: Find the average salary of employees in each department.

Algebraic Expression: $_{\text{DeptID}}\Im_{\text{AVERAGE}(\text{Salary})}(\text{EMPLOYEE})$

The 7-Step ER-to-Relational Mapping Algorithm 10 Marks guaranteed

📝 Complete Conversion Algorithm

  1. Step 1: Mapping of Regular Strong Entity Types: Create a relation $R$ for each strong entity type $E$. Include all simple attributes of $E$ in $R$. Choose one of the key attributes of $E$ as the **Primary Key** of $R$.
  2. Step 2: Mapping of Weak Entity Types: Create a relation $R$ for each weak entity type $W$. Include all simple attributes of $W$ in $R$. Add the primary key attribute(s) of the owner strong entity type as a **Foreign Key** in $R$. The Primary Key of $R$ is the combination of `{Owner_Primary_Key, Weak_Entity_Partial_Key}`.
  3. Step 3: Mapping of Binary 1:1 Relationship Types: To map a 1:1 relationship between $S$ and $T$, choose one relation (preferably the one with **Total Participation**) and include the primary key of the other relation as a **Foreign Key** in it. Include any simple attributes of the relationship in that same relation.
  4. Step 4: Mapping of Binary 1:N Relationship Types: Identify the relation $S$ on the **N-side** of the relationship. Include the primary key of the relation $T$ (on the 1-side) as a **Foreign Key** in $S$. Any simple attributes of the relationship are also placed in $S$.
  5. Step 5: Mapping of Binary M:N Relationship Types: Create a **new relation $S$ (Relationship Table)** to represent the M:N relationship. Include the primary keys of both participating relations as **Foreign Keys** in $S$. The combination of these two foreign keys forms the composite **Primary Key** of $S$. Include any simple attributes of the M:N relationship in $S$.
  6. Step 6: Mapping of Multivalued Attributes: Create a **new relation $R$** for each multivalued attribute $A$. Include the attribute $A$ itself in $R$. Add the primary key of the parent entity as a **Foreign Key** in $R$. The composite **Primary Key** of $R$ is the combination of `{Parent_Primary_Key, Attribute_A}`.
  7. Step 7: Mapping of N-ary Relationships (N > 2): Create a **new relation $S$** to represent the relationship. Include the primary keys of all participating relations as **Foreign Keys** in $S$. The composite **Primary Key** of $S$ is the combination of these foreign keys.

Standard University Exam Solutions

Q1. Explain SELECT (σ) and PROJECT (π) unary operations in Relational Algebra. 10 Marks

Answer: Refer to Section 8 of these notes for extensive algebraic syntax and tables. SELECT extracts row tuples horizontally matching target logical predicates (e.g., $\sigma_{\text{Age}>20}(R)$). PROJECT extracts columns vertically (e.g., $\pi_{\text{Name}, \text{USN}}(R)$) and strictly deletes duplicate records from the final returned relation. This ensures set compatibility.

Q2. Explain relational integrity constraints in detail. 10 Marks

Answer: Refer to Section 4. Relational integrity constraints ensure semantic correctness of data: 1. *Domain Constraint:* Atomic column datatypes. 2. *Key Constraint:* Primary Key uniqueness. 3. *Entity Integrity:* PK cannot be NULL. 4. *Referential Integrity:* FK must match referenced PK or be NULL.

Q3. Differentiate between Entity Integrity and Referential Integrity. 5 Marks

Answer: **Entity Integrity** enforces that primary keys cannot be NULL, ensuring every row remains identifiable. **Referential Integrity** maps relationships, dictating that foreign keys must reference a valid existing primary key or be NULL, ensuring no orphaned references exist.

Q4. Explain different types of JOIN operations in relational algebra. 10 Marks

Answer: Refer to Sections 10 and 11. Joins combine matching tables: - *Theta Join:* Connects rows based on general conditions. - *Equi Join:* Joins using the equality operator. - *Natural Join:* Joins on identical column names, automatically deleting duplicate columns. - *Outer Joins:* Left, Right, Full joins preserving unmatched rows using NULL values.

Q5. Explain the DIVISION (÷) operation with an example. 10 Marks

Answer: Refer to Section 12. Used for "for all" queries. If $R(X,Y)$ is divided by $S(Y)$, the result $T(X)$ contains all $X$ values paired with every $Y$ value in $S$. The algebraic equivalence is $R \div S \equiv \pi_X(R) - \pi_X((\pi_X(R) \times S) - R)$.
