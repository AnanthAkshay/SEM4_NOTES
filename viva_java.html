EXP 1 · 3

Packages & Interfaces

Q 1 – 14
Q1What is a package in Java and why is it used?▶
A package is a namespace that groups related classes and interfaces together. It prevents naming conflicts and controls access. You declare it with package packageName; at the top of a file.

Benefits: organised code, name collision avoidance, access protection (protected and default access are package-scoped).
Example: package PayrollManagement;
Q2How do you import a class from another package?▶
Use the import keyword followed by the fully qualified name.
import PayrollManagement.Employee;   // specific class
import PayrollManagement.*;           // all classes
In the Payroll system the Company package imports from PayrollManagement.
Key point: java.lang.* is imported automatically; all others must be explicit.
Q3What is an interface in Java? How is it different from an abstract class?▶
An interface is a contract — it declares method signatures that implementing classes must provide.
  • All methods are public abstract by default (Java 7)
  • Can have default and static methods (Java 8+)
  • All fields are public static final

Key differences from abstract class:
  • A class can implement multiple interfaces but extend only one abstract class
  • Abstract classes can have constructors, state, and non-abstract methods freely
  • Interface provides 100% abstraction (pre Java 8)
In Exp 1, Payable is an interface with calculate(); FullTime, PartTime, and Intern implement it.
Q4Can a class implement multiple interfaces? Give an example.▶
Yes. Java allows multiple interface implementation to simulate multiple inheritance of type.
interface Payable  { double calculate(); }
interface Taxable  { double computeTax(); }

class FullTime extends Employee implements Payable, Taxable {
    public double calculate()  { return salary; }
    public double computeTax() { return salary * 0.3; }
}
Q5What is the difference between method overriding and method overloading?▶
  • Overriding – same method signature in a subclass; resolved at runtime (dynamic dispatch). Used for interface implementation and polymorphism.
  • Overloading – same method name but different parameter list in the same class; resolved at compile time.
In the Payroll system, each subclass overrides calculate() from Payable.
Q6What is runtime polymorphism? How does it apply to the Payroll system?▶
Runtime polymorphism means the JVM decides at runtime which overridden method to call based on the actual object type, not the reference type.
Employee[] staff = { new FullTime(...), new PartTime(...), new Intern(...) };
for (Employee e : staff) {
    // JVM calls the correct calculate() at runtime
    System.out.println(((Payable)e).calculate());
}
This is possible because FullTime, PartTime, and Intern all have different implementations of calculate().
Q7Can an interface have a constructor? Why or why not?▶
No. Interfaces cannot be instantiated directly, so constructors are meaningless. An interface defines a contract, not an object blueprint. Only classes (including abstract classes) can have constructors.
Q8What is a parameterised constructor? Why is it used in the Employee class?▶
A parameterised constructor accepts arguments to initialise an object's fields at creation time, ensuring the object is always in a valid state.
public Employee(String name, int age, double salary, String designation) {
    this.name        = name;
    this.age         = age;
    this.salary      = salary;
    this.designation = designation;
}
Subclasses call super(name, age, salary, designation) to reuse this initialisation.
Q9What is the role of the 'super' keyword when used in subclass constructors?▶
super() invokes the parent class constructor. It must be the first statement in a subclass constructor. If omitted, the compiler inserts a no-arg super() call automatically — which fails if the parent has no default constructor. 
class FullTime extends Employee {
    public FullTime(String name, int age, double salary) {
        super(name, age, salary, "Full-Time");
    }
}
Q10What is the StringManipulator interface? List the eight methods it must define.▶
StringManipulator (Exp 3) is an interface in the stringoperations package:
  1. String reverse(String input)
  2. String toUpperCase(String input)
  3. String toLowerCase(String input)
  4. String concatenate(String s1, String s2)
  5. int countVowels(String input)
  6. int wordCount(String input)
  7. (Two more student-defined methods, e.g. isPalindrome() and trim())
The class StringProcessor implements all these methods.
Q11What is a default method in a Java interface? (Java 8)▶
A default method provides a method body inside an interface so that implementing classes can inherit it without overriding. It solves backward compatibility — adding new methods to an existing interface without breaking all implementations. 
interface StringManipulator {
    default String trim(String s) { return s.trim(); }
}
Q12What is the difference between 'extends' and 'implements'?▶
  • extends — used when a class inherits another class, or an interface extends another interface. Only one class can be extended.
  • implements — used when a class promises to fulfil an interface contract. Multiple interfaces can be implemented simultaneously.
Example: class FullTime extends Employee implements Payable
Q13How are access modifiers different across packages?▶
  • public — accessible everywhere
  • protected — accessible within the same package and subclasses in other packages
  • default (no modifier) — accessible only within the same package
  • private — accessible only within the declaring class
In the Payroll system, the Company package can only access members marked public in PayrollManagement.
Q14What happens if a class declares that it implements an interface but does not implement all its methods?▶
A compile-time error occurs: "ClassName is not abstract and does not override abstract method methodName() in InterfaceName".

The only valid alternatives are:
  • Implement all abstract methods, or
  • Declare the class itself abstract
EXP 2 · 4

Exception Handling & Custom Exceptions

Q 15 – 28
Q15How do you create a custom exception in Java?▶
Extend Exception (checked) or RuntimeException (unchecked): 
class QueueOverflowException extends Exception {
    public QueueOverflowException(String msg) {
        super(msg);
    }
}
Throw it with throw new QueueOverflowException("Queue is full!");
Q16What is the difference between checked and unchecked exceptions?▶
  • Checked — subclasses of Exception (not RuntimeException). Must be declared with throws or caught in a try-catch. E.g., IOException, QueueOverflowException.
  • Unchecked — subclasses of RuntimeException. No mandatory handling. E.g., NullPointerException, ArrayIndexOutOfBoundsException.
Exam tip: Custom exceptions for Queue extend Exception, making them checked — the caller is forced to handle them.
Q17What is the difference between 'throw' and 'throws'?▶
  • throw — used inside a method body to actually raise an exception object: throw new QueueOverflowException("full");
  • throws — used in a method signature to declare that the method may throw a checked exception, passing responsibility to the caller: void enqueue(int x) throws QueueOverflowException
Q18What is Queue Overflow and Queue Underflow?▶
  • Queue Overflow — occurs when trying to enqueue an element into a full queue (rear == max–1).
  • Queue Underflow — occurs when trying to dequeue from an empty queue (front == –1).
Both are modelled as custom exceptions so the caller can handle them gracefully instead of getting a cryptic ArrayIndexOutOfBoundsException.
Q19What is the purpose of the 'finally' block?▶
The finally block executes always — whether or not an exception was thrown or caught. It is used for resource cleanup (closing files, DB connections, etc.).
Exception: finally does not execute if System.exit() is called or if the JVM crashes. 
try {
    enqueue(99);
} catch (QueueOverflowException e) {
    System.out.println(e.getMessage());
} finally {
    System.out.println("Enqueue attempt done.");
}
Q20What is a multi-catch block? (Java 7)▶
Java 7 introduced the ability to catch multiple exceptions in a single catch block using |: 
try {
    // ...
} catch (QueueOverflowException | QueueUnderflowException e) {
    System.out.println("Queue error: " + e.getMessage());
}
This reduces code duplication. The caught variable is effectively final.
Q21What custom exceptions does Exp 4 (Palindrome Checker) require?▶
Two custom exceptions:
  • InvalidInputException — thrown when the input contains non-alphabetical characters.
  • ShortStringException — thrown when the string length is less than 3.
Validation order matters: check length first, then character validity, then perform palindrome check.
Q22Can we have a try block without a catch block?▶
Yes — if a finally block is present. The syntax try { } finally { } is valid. The exception propagates up after finally executes. However, a try block with neither catch nor finally is a compile error.
Q23What is exception propagation?▶
If a method does not catch a thrown exception, it propagates up the call stack to the calling method. If no method handles it, the JVM prints the stack trace and terminates the program. This chain is called exception propagation.
Q24Can a subclass override a method and throw broader exceptions than the parent?▶
No — this would violate the Liskov Substitution Principle. A subclass override can:
  • Throw fewer or narrower checked exceptions
  • Throw no checked exceptions
  • Throw any unchecked exceptions freely
It cannot throw new or broader checked exceptions.
Q25How do you validate that a string contains only alphabetical characters in the Palindrome program?▶ 
if (!input.matches("[a-zA-Z]+")) {
    throw new InvalidInputException("Only alphabets allowed!");
}
Alternative: iterate and use Character.isLetter(ch) for each character.
Q26What is the getMessage() method and where is it defined?▶
getMessage() is defined in java.lang.Throwable, the root of all Java exceptions. It returns the detail message string passed to the exception constructor via super(msg). Used to display human-readable error information.
Q27What is the exception class hierarchy in Java?▶ 
Object
 └── Throwable
      ├── Error          (JVM-level, don't catch)
      └── Exception      (application-level)
           ├── IOException, SQLException …  (checked)
           └── RuntimeException             (unchecked)
                ├── NullPointerException
                ├── ArithmeticException
                └── …
Custom exceptions extend Exception or RuntimeException.
Q28What is the difference between Error and Exception?▶
  • Error — serious JVM-level problems that applications cannot and should not try to handle: OutOfMemoryError, StackOverflowError.
  • Exception — recoverable conditions that application code can and should handle.

String, StringBuffer & StringBuilder

Q 29 – 41
Q29What is the difference between String, StringBuffer, and StringBuilder?▶
  • String — immutable; every modification creates a new object. Thread-safe by nature.
  • StringBuffer — mutable; all methods are synchronized → thread-safe but slower.
  • StringBuilder — mutable; methods are not synchronized → faster but not thread-safe.
For the Palindrome Checker, StringBuffer is used because reverse() is a built-in method.
Q30How does StringBuffer's reverse() method work? Write the logic manually.▶
new StringBuffer(str).reverse().toString() reverses the character sequence in-place.
Manual equivalent: 
String s = "RACECAR";
StringBuilder sb = new StringBuilder();
for (int i = s.length()-1; i >= 0; i--)
    sb.append(s.charAt(i));
String reversed = sb.toString(); // "RACECAR"
Q31Why is String immutable in Java?▶
Java designers made String immutable for:
  • Security — class names, file paths, network connections use strings; mutation would be a vulnerability.
  • String pool / caching — multiple references can safely share the same object.
  • Thread safety — immutable objects are inherently safe across threads.
  • Hashcode caching — stable hashcode makes Strings safe as HashMap keys.
Q32How do you check if a character is uppercase, lowercase, or a digit in Java?▶
Use the Character utility class: 
Character.isUpperCase(ch)   // A-Z
Character.isLowerCase(ch)   // a-z
Character.isDigit(ch)       // 0-9
Character.isLetter(ch)      // any letter
Character.isLetterOrDigit(ch)
Used in Exp 5 to validate password strength.
Q33How do you mask a password in Exp 5 (keep first and last character, replace rest with '*')?▶ 
String mask(String pwd) {
    if (pwd.length() <= 2) return pwd;
    StringBuilder sb = new StringBuilder();
    sb.append(pwd.charAt(0));
    for (int i = 1; i < pwd.length()-1; i++) sb.append('*');
    sb.append(pwd.charAt(pwd.length()-1));
    return sb.toString();
}
// "Hello@1" → "H*****1"
Q34How do you count special characters in a string?▶ 
int countSpecial(String pwd) {
    int count = 0;
    for (char c : pwd.toCharArray())
        if (!Character.isLetterOrDigit(c)) count++;
    return count;
}
// Alternatively: pwd.replaceAll("[a-zA-Z0-9]", "").length()
Q35What does the String.replace() method do, and how is it used to replace vowels with '#'?▶
replace(CharSequence target, CharSequence replacement) replaces every occurrence. For vowel masking, replaceAll() with regex is cleaner: 
String masked = password.replaceAll("[aeiouAEIOU]", "#");
// "Hello@1" → "H#ll#@1"
Q36What is the String pool and how does it relate to == vs .equals()?▶
Java maintains a string pool (intern pool) for string literals. Two literals with the same value share the same object: 
String a = "hello";
String b = "hello";
a == b       // true  (same pool object)

String c = new String("hello");
a == c       // false (c is on heap, not pool)
a.equals(c)  // true  (value comparison)
Always use .equals() to compare string content, never ==.
Q37How do you count vowels in a string? (Exp 3)▶ 
int countVowels(String input) {
    int count = 0;
    for (char c : input.toLowerCase().toCharArray())
        if ("aeiou".indexOf(c) != -1) count++;
    return count;
}
Q38How do you count the number of words in a string? (Exp 3)▶ 
int wordCount(String input) {
    if (input == null || input.trim().isEmpty()) return 0;
    return input.trim().split("\\s+").length;
}
// "  hello   world  " → 2
Using \\s+ handles multiple consecutive spaces correctly.
Q39What are common StringBuffer methods used in lab programs?▶
  • append(str) — appends to end
  • insert(index, str) — inserts at position
  • delete(start, end) — removes characters
  • reverse() — reverses in-place
  • replace(start, end, str) — replaces segment
  • charAt(index) — gets character
  • length(), toString()
Q40How is a palindrome check implemented using StringBuffer?▶ 
boolean isPalindrome(String s) {
    String clean = s.toLowerCase();
    String rev   = new StringBuffer(clean).reverse().toString();
    return clean.equals(rev);
}
// "RACECAR" → reversed "racecar" == "racecar" → true
Q41What is StringBuilder's advantage over StringBuffer in single-threaded programs?▶
StringBuilder has no synchronization overhead (no synchronized keyword on its methods), making it approximately 10–15% faster in benchmarks for single-threaded use. Since lab programs are single-threaded, StringBuilder is the more efficient choice — but the syllabus specifically requires StringBuffer for the Palindrome Checker.

Collections Framework

Q 42 – 56
Q42What is the Java Collections Framework?▶
A unified architecture for representing and manipulating collections of objects. It provides:
  • Interfaces: List, Set, Queue, Map, Deque
  • Implementations: ArrayList, LinkedList, HashSet, HashMap, etc.
  • Algorithms: Collections.sort(), Collections.shuffle(), etc.
Q43What collection class is most appropriate for Exp 6 (Missed Calls)? Why?▶
A LinkedList used as a Deque (double-ended queue) is most appropriate because:
  • Calls are recalled in arrival order (FIFO)
  • The oldest call must be removed when the 4th call arrives (removeFirst())
  • New calls are added at the tail (addLast())
  • Fixed max capacity of 3 can be enforced manually
ArrayDeque is also a valid choice.
Q44What is the difference between ArrayList and LinkedList?▶
  • ArrayList — backed by a dynamic array. O(1) random access, O(n) insertion/deletion in the middle.
  • LinkedList — doubly-linked list. O(n) random access, O(1) insertion/deletion at head or tail.
Choose LinkedList when frequent insertions/deletions at both ends are needed (Exp 6). Choose ArrayList for random access (Exp 7 book list).
Q45How do you sort a List of objects by a field (e.g., book price) using Comparator?▶ 
// Java 8 lambda
books.sort(Comparator.comparingDouble(Book::getPrice));

// Traditional anonymous class
Collections.sort(books, new Comparator<Book>() {
    public int compare(Book a, Book b) {
        return Double.compare(a.getPrice(), b.getPrice());
    }
});
Exp 7 requires sorting in ascending order of price, storing the result in a new list.
Q46What is the difference between Comparable and Comparator?▶
  • Comparable — implemented by the class itself (implements Comparable<T>). Defines the natural ordering via compareTo(). Only one ordering per class.
  • Comparator — external strategy object. Allows multiple, custom orderings without modifying the class.
For books (price sort), use Comparator; you could also define natural order by title using Comparable.
Q47How do you filter a list to get all books above a given price?▶ 
// Traditional loop
List<Book> expensive = new ArrayList<>();
for (Book b : books)
    if (b.getPrice() > threshold) expensive.add(b);

// Java 8 Stream
List<Book> expensive = books.stream()
    .filter(b -> b.getPrice() > threshold)
    .collect(Collectors.toList());
Q48How do you find all books by a given author? (Exp 7)▶ 
List<Book> byAuthor = new ArrayList<>();
for (Book b : books)
    if (b.getAuthor().equalsIgnoreCase(authorName))
        byAuthor.add(b);
Using equalsIgnoreCase handles case mismatch in user input.
Q49How do you maintain a unique book ID for each book? (Exp 7)▶
Use a HashMap where the key is the book ID and the value is the Book object: 
Map<Integer, Book> bookDB = new HashMap<>();
bookDB.put(101, new Book("DBMS", "Navathe", "Pearson", 499.0));
The List stores insertion-ordered books; the Map enables O(1) lookup by ID.
Q50What is a helper class and why is it used in Exp 6?▶
A helper (model) class encapsulates data. In Exp 6, Call is the helper class: 
class Call {
    String number;
    String callerName;
    LocalTime time;
    Call(String num, String name) {
        this.number     = num;
        this.callerName = name;
        this.time       = LocalTime.now();
    }
}
It keeps the data and the collection management code separate, following Separation of Concerns.
Q51What is the Iterator interface and how is it used?▶
Iterator provides a standard way to traverse and optionally remove elements from any collection: 
Iterator<Call> it = missedCalls.iterator();
while (it.hasNext()) {
    Call c = it.next();
    if (shouldDelete(c)) it.remove();  // safe removal during iteration
}
Using it.remove() is the safe way to delete during iteration; directly calling list.remove() in a for-each loop causes ConcurrentModificationException.
Q52What is the difference between List, Set, and Map in Java?▶
  • List — ordered, allows duplicates. Index-based access. (ArrayList, LinkedList)
  • Set — unordered (usually), no duplicates. (HashSet, TreeSet)
  • Map — key-value pairs, unique keys. (HashMap, TreeMap)
Q53What is a Queue interface? What are its key methods?▶
java.util.Queue extends Collection and models a FIFO structure:
  • offer(e) / add(e) — insert at tail
  • poll() / remove() — remove from head
  • peek() / element() — inspect head without removing
The difference: offer/poll/peek return null or false on failure; add/remove/element throw exceptions.
Q54What is the Collections utility class? Name any three useful methods.▶
java.util.Collections provides static utility methods for collection manipulation:
  • Collections.sort(list) — natural sort
  • Collections.sort(list, comparator) — custom sort
  • Collections.reverse(list) — reverse in-place
  • Collections.shuffle(list) — random shuffle
  • Collections.unmodifiableList(list) — read-only wrapper
Q55What is autoboxing and how does it apply to collections?▶
Java collections can only store objects, not primitives. Autoboxing automatically converts primitives to their wrapper types and back: 
List<Integer> list = new ArrayList<>();
list.add(42);         // autoboxing: int → Integer
int x = list.get(0);  // unboxing:  Integer → int
This is relevant when storing book prices (double → Double) or queue elements.
Q56What does Collections.unmodifiableList() do and when would you use it?▶
It returns a read-only view of the list. Any attempt to add, remove, or set throws UnsupportedOperationException. Useful when a method returns a list that callers should not modify — for example, returning the sorted price list in Exp 7 to prevent accidental corruption of the master list.

Generics

Q 57 – 64
Q57What are generics in Java and why are they used?▶
Generics allow classes, interfaces, and methods to operate on a type specified at compile time. Benefits:
  • Type safety — catches type mismatches at compile time, not runtime
  • No casting — eliminates explicit casts
  • Reusability — one class works for multiple types
Stack<String> and Stack<Integer> from the same Stack<T> class.
Q58Write the skeleton of a generic Stack class. (Exp 8)▶ 
class Stack<T> {
    private Object[] data;
    private int top = -1;
    private int capacity;

    Stack(int cap) { capacity = cap; data = new Object[cap]; }

    void push(T item) {
        if (top == capacity-1) throw new RuntimeException("Stack Full");
        data[++top] = item;
    }

    @SuppressWarnings("unchecked")
    T pop() {
        if (isEmpty()) throw new RuntimeException("Stack Empty");
        return (T) data[top--];
    }

    boolean isEmpty()  { return top == -1; }
    void clear()       { top = -1; }

    void display() {
        for (int i = top; i >= 0; i--) System.out.println(data[i]);
    }
}
Q59What is type erasure in Java generics?▶
At compile time, the Java compiler replaces type parameters with Object (or their upper bound) and inserts casts where needed. At runtime, no type information about generic parameters exists in the bytecode. This is called type erasure.

Implication: you cannot do new T[] or instanceof T at runtime, which is why the generic Stack uses new Object[].
Q60What is a bounded type parameter? Give an example.▶
A bounded type parameter restricts which types can be used: 
<T extends Number>     // T must be Number or a subclass
<T extends Comparable<T>>  // T must implement Comparable
Example — a generic max method: 
static <T extends Comparable<T>> T max(T a, T b) {
    return a.compareTo(b) >= 0 ? a : b;
}
Q61What is the difference between Stack (java.util) and a user-defined generic Stack?▶
  • java.util.Stack — legacy class, extends Vector (synchronized), inherits many unrelated methods like get(int).
  • User-defined Stack<T> — clean API with only push, pop, peek, isEmpty, clear, display. Preferred in modern code.
The syllabus asks for a user-defined generic class for this reason.
Q62How do you instantiate a generic Stack for String and Integer?▶ 
Stack<String>  sStack = new Stack<>(5);
sStack.push("Hello");
sStack.push("World");

Stack<Integer> iStack = new Stack<>(5);
iStack.push(10);
iStack.push(20);
The diamond operator <> (Java 7+) infers the type from the declaration.
Q63Why can't you create an array of a generic type directly (e.g., new T[10])?▶
Due to type erasure, the JVM doesn't know T at runtime. Array creation requires a concrete runtime type. The workaround is to use new Object[10] and cast elements to T when retrieved.
Q64What is a generic method? How is it different from a generic class?▶
A generic method declares its own type parameter independent of the class: 
static <T> void printArray(T[] arr) {
    for (T item : arr) System.out.print(item + " ");
}
A generic class defines T for the whole class; all methods share it. A generic method defines T only for that method call — useful in utility/static methods.

Java Swing & GUI

Q 65 – 80
Q65What is Java Swing? How does it differ from AWT?▶
Swing is a GUI toolkit built on top of AWT as part of Java Foundation Classes (JFC).

Key differences:
  • Swing is lightweight — components are rendered by Java itself, not OS-native peers → look-and-feel is consistent across platforms.
  • AWT is heavyweight — delegates to OS-native widgets. Platform-dependent look.
  • Swing offers far more components: JTable, JTree, JOptionPane, etc.
  • AWT components start with Button; Swing with JButton.
Q66What is JFrame and how do you create a basic window?▶
JFrame is the top-level container for a Swing application — it's the window. 
JFrame frame = new JFrame("Student Info");
frame.setSize(600, 400);
frame.setDefaultCloseOperation(JFrame.EXIT_ON_CLOSE);
frame.setLayout(new FlowLayout());
// add components...
frame.setVisible(true);
setDefaultCloseOperation(EXIT_ON_CLOSE) ensures the JVM exits when the window is closed.
Q67What is ActionListener and how is it used in Swing?▶
ActionListener is a functional interface from java.awt.event. It is implemented to respond to button clicks and similar actions: 
JButton btn = new JButton("Compute");
btn.addActionListener(new ActionListener() {
    public void actionPerformed(ActionEvent e) {
        // compute CGPA
    }
});
// Java 8 lambda:
btn.addActionListener(e -> computeCGPA());
Q68What is the difference between JTextField, JTextArea, and JPasswordField?▶
  • JTextField — single-line text input.
  • JTextArea — multi-line text display/input. Used in Exp 9 to display the student collection.
  • JPasswordField — single-line, masks input with echo character (e.g., •). Used in Exp 10 for password entry.
Q69How do you show a validation error message in a Swing popup?▶ 
JOptionPane.showMessageDialog(
    frame,                        // parent component
    "Age must be a number!",      // message
    "Validation Error",           // title
    JOptionPane.ERROR_MESSAGE     // icon type
);
Icon types: ERROR_MESSAGE, WARNING_MESSAGE, INFORMATION_MESSAGE, QUESTION_MESSAGE.
Q70How is CGPA computed from four SGPAs in Exp 9?▶
CGPA is the arithmetic mean of the four semester GPAs: 
double cgpa = (sgpa1 + sgpa2 + sgpa3 + sgpa4) / 4.0;
Validation needed: each SGPA must be in the range [0.0, 10.0]. Show an error dialog if any value is out of range or not a number. 
try {
    double s = Double.parseDouble(sgpaField.getText());
    if (s < 0 || s > 10) throw new NumberFormatException();
} catch (NumberFormatException ex) {
    JOptionPane.showMessageDialog(this, "Invalid SGPA!", "Error", JOptionPane.ERROR_MESSAGE);
}
Q71How do you enable or disable a button programmatically in Swing?▶ 
computeButton.setEnabled(true);   // enable
doneButton.setEnabled(false);     // disable (greyed out)
In Exp 9, the workflow is:
  1. Initially both enabled.
  2. After "Compute" → disable Compute, enable Done.
  3. After "Done" → re-enable Compute for the next entry.
Q72What is JOptionPane.showInputDialog() and when is it used?▶
It displays a dialog that prompts the user for text input and returns the entered string (or null if cancelled). 
String userId = JOptionPane.showInputDialog(frame,
    "Enter Customer ID:", "Login", JOptionPane.QUESTION_MESSAGE);
Used in Exp 10 to get the customer ID after successful login.
Q73What is JOptionPane.showConfirmDialog() and what values can it return?▶
Displays a Yes/No/Cancel dialog: 
int result = JOptionPane.showConfirmDialog(frame,
    "Customer exists. Proceed?", "Confirm", JOptionPane.YES_NO_OPTION);
Return values:
  • JOptionPane.YES_OPTION (0)
  • JOptionPane.NO_OPTION (1)
  • JOptionPane.CANCEL_OPTION (2)
  • JOptionPane.CLOSED_OPTION (-1) — dialog closed without selection
Q74What is JOptionPane.showOptionDialog()? How is it used for discounts in Exp 10?▶
It creates a fully custom dialog with user-defined button labels: 
String[] discounts = {"10% - Regular", "20% - Member", "30% - Premium"};
int choice = JOptionPane.showOptionDialog(
    frame,
    "Select Discount Type:",
    "Discount Options",
    JOptionPane.DEFAULT_OPTION,
    JOptionPane.QUESTION_MESSAGE,
    null,
    discounts,
    discounts[0]

Q75What is a Layout Manager in Swing? Name three commonly used ones.▶
A Layout Manager controls how components are positioned and sized within a container.
  • FlowLayout — components placed left-to-right, top-to-bottom. Default for JPanel.
  • BorderLayout — five regions: North, South, East, West, Center. Default for JFrame's content pane.
  • GridLayout — equal-sized cells in rows and columns.
  • GridBagLayout — most flexible; full control over cell size and position.
Q76What is the Event Dispatch Thread (EDT) in Swing?▶
Swing is single-threaded. All GUI creation and updates must happen on the Event Dispatch Thread (EDT). Use SwingUtilities.invokeLater(): 
SwingUtilities.invokeLater(() -> {
    new StudentForm().setVisible(true);
});
Updating UI components from other threads causes intermittent bugs and race conditions.

Q79What is the difference between JDialog and JOptionPane?▶
  • JOptionPane — static factory methods for standard dialogs (message, input, confirm, option). Fastest way to show simple dialogs.
  • JDialog — a full-featured dialog window you build from scratch. Used when JOptionPane is not sufficient (custom layout, multiple input fields, etc.).
JOptionPane internally creates a JDialog to render itself.
Q80What does setDefaultCloseOperation(JFrame.EXIT_ON_CLOSE) do? What are the other options?▶
It specifies what happens when the user clicks the window's close (X) button:
  • EXIT_ON_CLOSE — calls System.exit(0); terminates the JVM.
  • DISPOSE_ON_CLOSE — disposes only this window; JVM continues if other windows exist.
  • HIDE_ON_CLOSE — hides the window but keeps it in memory.
  • DO_NOTHING_ON_CLOSE — no automatic action; handle manually with WindowListener.
