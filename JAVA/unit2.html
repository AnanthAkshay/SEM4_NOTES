String Constructors & String Constant Pool (SCP)

📖 Definition

In Java, a String is a non-primitive object encapsulated by the final class java.lang.String. Strings represent an immutable sequence of characters. Once a String object is instantiated in the JVM heap, its character sequence cannot be dynamically modified.

🏗️ String Literal vs. new Keyword (Memory Isolation)

The JVM manages String memory allocation in two completely different locations depending on instantiation styles:

  • String Literal (String s = "Java";): Allocates memory directly within the String Constant Pool (SCP)—a dedicated memory region inside the JVM's Heap (relocated to Heap from PermGen in Java 7). Before allocation, the JVM checks the pool. If a matching string literal is found, it simply returns the reference address, saving CPU cycles and memory. If not found, a new literal object is created in the SCP.
  • new Operator (String s = new String("Java");): Bypasses the pool check. It **always allocates a brand new object** on the general non-pool Heap. It also puts the literal in the SCP if not already present. This results in **two objects being created** in memory if the literal isn't already pooled!

Memory Comparison Demo:

String s1 = "Hello";                  // Reference to SCP object
String s2 = "Hello";                  // Reuses same reference from SCP
String s3 = new String("Hello");      // Allocates new Heap object

System.out.println(s1 == s2);          // true (Points to identical SCP memory address)
System.out.println(s1 == s3);          // false (s3 is a different Heap object)

⚡ The intern() Method: Bypassing Heap Allocations

The intern() method is a native call that allows dynamically adding a standard Heap String into the String Constant Pool at runtime:

How intern() Works
When s.intern() is called, the JVM searches the SCP. If a string with identical content is already pooled, the JVM returns the address of that pooled version. If the string is not present in the pool, the current string object is registered in the pool, and its reference is returned. 
String h = new String("MSRIT");
String p = "MSRIT";
String i = h.intern(); // Returns the canonical pooled reference

System.out.println(h == p); // false (heap vs pool references)
System.out.println(p == i); // true (both point to SCP resource!)

🛠️ Useful String Constructors

String s = new String();                         // Empty string
char[] chars = {'a', 'b', 'c'};
String s2 = new String(chars);                   // "abc"
String s3 = new String(chars, 1, 2);             // "bc" (char[], startOffset, length)
byte[] bytes = {65, 66, 67};
String s4 = new String(bytes);                   // "ABC" (using ASCII values)

String Immutability & Custom Immutable Classes

MSRIT CIE-1

🛑 Rationale Behind String Immutability

  1. String Pool Optimization: Since multiple String variables point to a single literal in the pool, mutability would cause "side-effect corruption" (e.g. changing s1's value would silently alter s2's reference data).
  2. Security & Sandboxing: Java classloaders, file system pathways, and network credentials rely heavily on Strings. If Strings were mutable, an attacker could manipulate parameters post-validation, bypassing security checks.
  3. Safe Concurrency (Thread Safety): Because String data cannot be changed, String objects are inherently thread-safe. They can be shared among threads without synchronization locks or risk of race conditions.
  4. Map Key Optimization (Caching Hash): The hash code of a String is cached immediately during construction (saved in the private field hash). This guarantees high performance when used as keys in HashMap, as the hash calculation runs only once.

🧱 Design Patterns: The 5 Strict Rules of Immutability

To design a completely custom immutable class in Java, you must adhere strictly to these 5 compiler and runtime rules:

  • 1. Final Class: Declare the class as final to prevent subclassing (subclasses could override getters and introduce mutable behaviors).
  • 2. Private and Final Fields: Declare all instance variables as private final to ensure encapsulation and guarantee single-assignment initialization.
  • 3. Zero Mutators: Do not write any setter (mutator) methods.
  • 4. Constructor Defensive Copying: If instance variables point to **mutable objects** (like java.util.Date or collections), perform a **deep clone/defensive copy** of parameter arguments inside the constructor. Do not assign parameter references directly.
  • 5. Getter Defensive Copying: In getter methods, return **cloned copies** of mutable fields rather than returning actual reference handles. This keeps the internal state protected from external modification.

💻 Complete Custom Immutable Class Template

Demonstrates deep copying and defensive cloning to guarantee immutability even when handling mutable objects like dates.

import java.util.Date;

public final class ImmutableStudent { // Rule 1: Final Class
    private final String name;         // Rule 2: Private final variables
    private final int rollNumber;
    private final Date joiningDate;    // Mutable object field

    public ImmutableStudent(String name, int rollNumber, Date joiningDate) {
        this.name = name;
        this.rollNumber = rollNumber;
        // Rule 4: Constructor Defensive Copying for mutable objects
        if (joiningDate != null) {
            this.joiningDate = new Date(joiningDate.getTime());
        } else {
            this.joiningDate = null;
        }
    }

    public String getName() { return name; }
    public int getRollNumber() { return rollNumber; }

    public Date getJoiningDate() {
        // Rule 5: Getter Defensive Copying. Avoid returning reference to direct field.
        if (joiningDate != null) {
            return new Date(joiningDate.getTime());
        }
        return null;
    }
}

Character Extraction

📖 Introduction

Java provides several methods to **extract characters** from a String object. Since Strings are character arrays internally, these methods let you pull out individual characters or ranges of characters.

🔍 Extraction Methods

  • charAt(int index) — Returns a single character at the specified 0-based index. Throws StringIndexOutOfBoundsException if index is out of range.
  • getChars(int srcBegin, int srcEnd, char[] dst, int dstBegin) — Copies characters from the string into a destination character array. srcEnd is exclusive.
  • toCharArray() — Converts the entire string into a new character array and returns it.
String s = "Advanced Java";

// charAt() — extract single character
char c = s.charAt(0);            // 'A'
char d = s.charAt(9);            // 'J'

// getChars() — extract range into char array
char[] buf = new char[4];
s.getChars(9, 13, buf, 0);     // buf = {'J','a','v','a'}

// toCharArray() — entire string to char[]
char[] all = s.toCharArray();    // {'A','d','v','a','n','c','e','d',' ','J','a','v','a'}

Changing Case of Characters

📖 Introduction

Java provides two methods to change the case of all characters in a string. Since Strings are immutable, these methods return a **new String** — the original remains unchanged.

🔠 Case Methods

  • toUpperCase() — Returns a new string with all characters converted to UPPERCASE.
  • toLowerCase() — Returns a new string with all characters converted to lowercase.
String s = "Hello World";
String upper = s.toUpperCase();  // "HELLO WORLD"
String lower = s.toLowerCase();  // "hello world"

// Original string s is unchanged (immutability!)
System.out.println(s);          // "Hello World" (no change)
💡 Exam Tip

These methods are locale-sensitive. You can pass a Locale parameter for internationalization: s.toUpperCase(Locale.ENGLISH). However, for exam purposes the default no-argument version is sufficient.

Joining Strings

📖 Introduction

Java provides multiple ways to **concatenate (join)** strings together. Understanding all approaches is important for both exams and practical code.

🔗 Three Ways to Join Strings

  1. The + operator: Simplest way. Compiler internally uses StringBuilder for efficiency. E.g., "Hello" + " " + "World" → "Hello World".
  2. concat(String str) method: Appends the specified string to the end. E.g., "Hello".concat(" World") → "Hello World". Returns a new String.
  3. String.join(delimiter, elements) (Java 8+): Joins multiple strings with a delimiter. E.g., String.join("-", "2025", "05", "29") → "2025-05-29".
// Method 1: + operator
String s1 = "Hello" + " " + "World";     // "Hello World"

// Method 2: concat()
String s2 = "Hello".concat(" World");     // "Hello World"

// Method 3: String.join() — joins with a delimiter
String date = String.join("-", "2025", "05", "29");   // "2025-05-29"
String csv  = String.join(", ", "Java", "Python", "C++"); // "Java, Python, C++"
⚠️ Concat vs + Operator

concat() throws NullPointerException if you call it on a null reference. The + operator converts null to the string "null" automatically. E.g., null + "hi" → "nullhi".

Searching Strings

📖 Introduction

Java's String class provides methods to **search for characters or substrings** within a string. All search methods return an int index (0-based) or -1 if not found.

🔎 Search Methods

  • indexOf(char ch) — Returns index of the first occurrence of the character.
  • indexOf(String str) — Returns index of first occurrence of the substring.
  • indexOf(char ch, int fromIndex) — Starts searching from the given index.
  • lastIndexOf(char ch) — Returns index of the last occurrence of the character.
  • lastIndexOf(String str) — Returns index of the last occurrence of the substring.
  • contains(CharSequence s) — Returns true if the string contains the specified sequence.
  • startsWith(String prefix) — Returns true if string starts with the given prefix.
  • endsWith(String suffix) — Returns true if string ends with the given suffix.
String s = "Java Programming Java";

s.indexOf('a');               // 1 (first 'a')
s.indexOf("Java");             // 0 (first "Java")
s.indexOf("Java", 1);          // 17 (second "Java", search from index 1)
s.lastIndexOf('a');           // 20 (last 'a')
s.lastIndexOf("Java");         // 17 (last "Java")
s.contains("Program");         // true
s.startsWith("Java");          // true
s.endsWith("Java");            // true
s.indexOf("Python");           // -1 (not found)

Modifying Strings & Unicode API Nuances

📖 Introduction

Because Strings are immutable, **every modification method is a non-destructive reader**. They do not change the state of the original object on the heap; instead, they compute the modification and yield a brand-new String object reference. The original remains unchanged.

✏️ String Modification Methods

  • substring(int beginIndex, int endIndex) Index Mechanics: Returns a slice of the string from beginIndex (inclusive) to endIndex (exclusive). The length of the returned substring is always endIndex - beginIndex. If parameters are negative or endIndex > length(), it throws StringIndexOutOfBoundsException.
  • split(String regex, int limit) Controls: Splits the string around matches of the regular expression. The optional limit parameter dictates the pattern application count:
    • limit > 0: The pattern is applied at most limit - 1 times, and the array's length will not be greater than the limit.
    • limit = 0: Trailing empty strings are discarded.
    • limit < 0: The pattern is applied as many times as possible, and the array can have any length, including trailing empty strings.
  • replace() vs. replaceAll() / replaceFirst():
    • replace(CharSequence target, CharSequence replacement): Performs a direct literal match-and-replace. It does **not** evaluate regular expressions, making it highly efficient for plain text.
    • replaceAll(String regex, String replacement): Evaluates the target string as a **regular expression** and replaces all matching sequences.
    • replaceFirst(String regex, String replacement): Evaluates the target as a regex but only replaces the first match.

⚖️ Trim vs. Strip: The Java 11 Unicode Evolution

Java supports two methods for removing trailing/leading whitespaces, which handle characters differently:

Specification trim() (Legacy Java 1.0) strip() (Modern Java 11+)
Whitespace Check Checks strictly if character codepoint is <= U+0020 (space character, tab, newline). Unicode-aware. Uses Character.isWhitespace(codepoint) to evaluate.
Unicode Whitespaces (e.g. \u2000 to \u200A) Ignored. Legacy trim cannot remove Unicode whitespaces. Successfully removed. strip parses all Unicode spaces.

Java 11 also provides stripLeading() and stripTrailing() to target specific ends of a string, optimizing memory and string manipulation workflows.

String s = "  Hello World Hello  ";

// substring() index checks
String sub1 = "Advanced".substring(0, 3);         // "Adv" (indices 0, 1, 2)

// split() with limits
String[] parts = "a:b:c::".split(":", 0);          // parts = {"a", "b", "c"} (trailing empty discarded)
String[] partsAll = "a:b:c::".split(":", -1);        // partsAll = {"a", "b", "c", "", ""} (retains all)

// replace() vs replaceAll()
String text = "a.b.c";
System.out.println(text.replace(".", "#"));        // "a#b#c" (literal dot replaced)
System.out.println(text.replaceAll(".", "#"));     // "#####" (regex dot matches any char!)

⚠️ String Comparison Trap: == vs .equals()

• The **`==` operator** compares **memory references (addresses)** — whether both variables point to the exact same object in memory.
• The **`equals()` method** compares the **actual content** inside the string objects.
E.g. `String s1 = new String("A"); String s2 = new String("A");` here `s1 == s2` is `false`, but `s1.equals(s2)` is `true`.

Data Conversions

📖 Introduction

Java provides multiple utility methods to convert between **Strings and primitive data types**. These conversions are essential for parsing user input, processing files, and formatted output.

🔄 String → Primitive (Parsing)

  • Integer.parseInt(String s) — Converts a string to an int. Throws NumberFormatException if invalid.
  • Double.parseDouble(String s) — Converts string to double.
  • Float.parseFloat(String s) — Converts string to float.
  • Long.parseLong(String s) — Converts string to long.
  • Boolean.parseBoolean(String s) — Returns true only if string is "true" (case insensitive).

🔄 Primitive → String

  • String.valueOf(int/double/boolean/char[]) — Static method that converts any primitive type to its String representation.
  • Integer.toString(int n) — Converts int to String.
  • "" + value — Concatenating with empty string converts any value to String.
// String to Primitive (Parsing)
int a = Integer.parseInt("42");          // 42
double b = Double.parseDouble("3.14");  // 3.14
boolean c = Boolean.parseBoolean("true"); // true

// Primitive to String
String s1 = String.valueOf(42);         // "42"
String s2 = Integer.toString(42);       // "42"
String s3 = "" + 3.14;                 // "3.14"
String s4 = String.valueOf(true);      // "true"

// char[] to String and back
char[] arr = {'J', 'a', 'v', 'a'};
String s5 = new String(arr);            // "Java"
String s6 = String.valueOf(arr);        // "Java"
⚠️ NumberFormatException Trap

Integer.parseInt("12.5") throws NumberFormatException because "12.5" is not a valid integer. Use Double.parseDouble() for decimal values. Similarly, Integer.parseInt("abc") throws the same exception.

StringBuffer Class & Dynamic Reallocation Mechanics

MSRIT SEE '24
📖 Definition

A StringBuffer represents a mutable, thread-safe sequence of characters. Unlike String, it can dynamically grow, shrink, and modify its internal character arrays in-place without creating orphaned garbage objects. All its major structural methods are **synchronized**, ensuring safe access across multiple concurrent threads.

📈 Default Capacity & Dynamic Capacity Growth Formula

A StringBuffer manages memory using an internal character array (char[] value). It allocates memory dynamically according to these strict JVM rules:

  • Default Initial Capacity: If instantiated using the empty constructor (new StringBuffer()), it initializes with a default buffer capacity of 16 characters.
  • String-based Capacity: If instantiated with a string argument (new StringBuffer("Hello")), it allocates an initial capacity of 16 + length of the string (e.g. 16 + 5 = 21 characters).
  • Dynamic Growth Formula: When appending characters that exceed the current buffer limit, the JVM reallocates a larger contiguous character array on the heap. The dynamic capacity growth formula used is:
    newCapacity = (oldCapacity * 2) + 2
    Why this formula? This amortized growth strategy ensures that a zero or small capacity buffer scales up exponentially, minimizing expensive array-copying cycles (System.arraycopy()) while balancing heap memory footprints.
⭐ Comparative Matrix: String vs StringBuffer vs StringBuilder
Feature Specification String Class StringBuffer Class (Java 1.0) StringBuilder Class (Java 5+)
Immutability Immutable (Read-only on SCP/Heap) Mutable (Modifiable in-place) Mutable (Modifiable in-place)
Thread Safety Thread-Safe (Implicit via immutability) Thread-Safe (All methods synchronized) Not Thread-Safe (No synchronization overhead)
Performance Speed Slow (Frequent garbage object heap allocations) Medium (Safe, but introduces sync lock overhead) Fastest (High-speed single-threaded processing)
Storage Pool String Constant Pool (SCP) & Heap General Heap only General Heap only

🛠️ Core StringBuffer Operations

StringBuffer sb = new StringBuffer("Hello"); // Init capacity: 16+5 = 21
sb.append(" World");                               // sb is now "Hello World" (mutated in-place)
sb.insert(6, "Java ");                             // "Hello Java World" (insert at offset index)
sb.reverse();                                      // Reverses the characters in-place
sb.delete(0, 5);                                   // Deletes range of characters

Type Wrappers, Autoboxing & Caching Traps

📖 Definitions

Type Wrappers: Standard classes in the java.lang package (e.g. Integer, Double, Character, Boolean) that wrap primitive data types in objects, enabling them to participate in Object-based frameworks like Collections (ArrayList, HashMap).

Autoboxing: The automatic compilation conversion that the Java compiler inserts to convert primitive types into their matching wrapper objects (e.g., converting int to Integer via Integer.valueOf()).

Unboxing: The automatic compilation conversion from wrapper objects back to primitive types (e.g., converting Integer to int via intValue()).

🚨 The Integer Cache Gotcha (-128 to 127)

To optimize CPU cycle and memory efficiency, Java internally caches Integer object instances for a specific range of values: between -128 and 127 (governed by Integer.IntegerCache).

How Caching Leads to Reference Errors
When autoboxing converts primitive integers in the cached range (e.g. Integer x = 100;), it calls Integer.valueOf(100) which returns a pre-allocated pooled reference from the internal cache. However, values **outside the [-128, 127] boundary** bypass the cache and allocate a brand new object on the Heap every single time. 
Integer a = 127;
Integer b = 127;
System.out.println(a == b); // true (Both point to the same cached pool object!)

Integer c = 128;
Integer d = 128;
System.out.println(c == d); // false (Values > 127 bypass cache, creating separate Heap objects!)
System.out.println(c.equals(d)); // true (Always use .equals() for content-based comparison)

Lambda Expressions (SAM & Compilation Mechanics)

MSRIT SEE '25
📖 Definition

Introduced in Java 8, a Lambda Expression is an anonymous (nameless, classless) block of executable statements. It implements a **Functional Interface** directly, facilitating functional programming architectures in Java by treating code/behaviors as method arguments.

🔑 Functional Target: Single Abstract Method (SAM)

A lambda expression cannot exist in isolation; it strictly requires a **Functional Interface** as its target type. A functional interface is any interface that declares **exactly one abstract method** (SAM). It can declare any number of default or static methods, but it must contain only one abstract signature.

⚡ Under the Hood: Compiling Mechanics & indy

Unlike other OOP concepts, the Java compiler does **not** compile lambda expressions into standard anonymous inner classes. Doing so would generate a distinct .class file on disk for every single lambda, bloating classloader footprints and slowing startup execution times.

The invokedynamic (indy) Pipeline
Instead, Java compiles lambdas using the invokedynamic (indy) instruction introduced in Java 7. At runtime, the JVM uses the static bootstrap helper LambdaMetafactory.metafactory() to dynamically construct a call site, generating a highly optimized, lightweight dynamic class definition directly in memory.

📈 Compiler Type Inference & Variable Capture Rules

  • Target Type Inference: Because the lambda is assigned directly to a functional interface type, the compiler automatically infers the parameter list types. You do not need to write explicit parameter types (e.g. (a, b) -> a + b instead of (int a, int b) -> a + b). This is known as **target typing**.
  • Effectively Final Enclosure: A lambda expression can access local variables residing in its enclosing outer block. However, the compiler enforces that captured local variables **must be final or effectively final** (meaning they are not declared final, but their value is never modified after initial assignment). 
    int factor = 2; // Effectively final (not modified)
NumericFunc f = (n) -> n * factor; // Legal capture
// factor = 3; // ERROR! Modifying this breaks effectively final constraint for lambda capture.
    Why this restriction? Stack variables reside on the thread stack and are destroyed when the method exits. However, the lambda instance resides on the Heap and may outlive the stack frame (e.g., in concurrent executions). The JVM handles this by creating a **copied value** of the variable for the lambda. If the stack variable could change, the two copies would lose sync.

⚡ Lambda Syntax

The syntax has three parts: **parameters**, the **arrow operator (`->`)**, and the **body expression/block**.

// Single Parameter syntax
(parameter) -> expression

// Multiple Parameters with blocks (Block Lambda)
(p1, p2) -> {
    statements;
    return val;
}

Block Lambda Expressions

📖 Introduction

A **Block Lambda** is a lambda expression that contains **multiple statements** enclosed in braces { }. Unlike single-expression lambdas, block lambdas require an explicit return statement (if the functional interface method returns a value). They are used when the lambda body needs more than one line of logic.

⚔️ Single Expression vs Block Lambda

// Single-expression lambda (implicit return)
(a, b) -> a + b

// Block lambda (explicit return required)
(a, b) -> {
    int sum = a + b;
    System.out.println("Sum is: " + sum);
    return sum;
}

💻 Block Lambda — Factorial Calculator

Probable 5M 
// Functional Interface
interface NumericFunc {
    int func(int n);
}

public class BlockLambdaDemo {
    public static void main(String[] args) {

        // Block lambda to compute factorial
        NumericFunc factorial = (n) -> {
            int result = 1;
            for (int i = 1; i <= n; i++)
                result = result * i;
            return result;  // explicit return REQUIRED in block lambda
        };

        System.out.println("Factorial of 5: " + factorial.func(5));
        System.out.println("Factorial of 3: " + factorial.func(3));
    }
}
📺 Output
Factorial of 5: 120
Factorial of 3: 6
💡 Key Rule

In a block lambda, if the interface method returns a value, you must use return. In a single-expression lambda, the return is implicit. If the method returns void, no return is needed in either case.

Functional Interfaces & Built-in Java APIs

📖 Definition

A Functional Interface is an interface containing **exactly one abstract method** (Single Abstract Method or SAM). It may declare multiple static or default methods, but only one abstract signature. It is annotated with @FunctionalInterface, which informs the compiler to generate an error if a developer accidentally attempts to add a second abstract method.

🛡️ Built-in Functional Interfaces (java.util.function)

Java 8 introduced a comprehensive suite of pre-packaged functional interfaces to cover standard operations:

Functional Interface Functional Method Signature Operation Purpose Practical Lambda Example
Predicate<T> boolean test(T t) Evaluates a logical condition on an input argument and returns a boolean value. Predicate<String> isLong = s -> s.length() > 5;
Consumer<T> void accept(T t) Accepts an argument, executes a custom side-effect action, and returns nothing. Consumer<String> print = s -> System.out.println(s);
Supplier<T> T get() Accepts zero arguments and produces/returns an object instance of type T. Supplier<Double> rand = () -> Math.random();
Function<T, R> R apply(T t) Accepts an argument of type T, transforms/maps it, and yields a result of type R. Function<String, Integer> parse = s -> Integer.parseInt(s);
💡 Classic Examples in Legacy Java API

• Runnable (contains only void run())
• Callable (contains only V call() throws Exception)
• Comparator (contains only int compare(T o1, T o2))

The Java Thread Model & Lifecycle

MSRIT CIE-2
📖 Definition

A Thread is a lightweight, independent path of execution inside a running program. In Java, multithreading facilitates concurrent execution by spawning multiple threads that share a single common memory heap region (reducing context-switching memory overhead compared to process-level multi-tasking).

🔄 Strict Thread State Lifecycle Diagram

A Java thread is governed by the JVM and OS schedulers, transiting through 6 highly structured states (defined in the enum Thread.State):

               [ NEW ]  (Thread created via 'new Thread()')
                  │
                  │  t.start()
                  ▼
             [ RUNNABLE ] ◀──────────────┐  (Ready/Waiting for CPU time)
               │      ▲                  │
  Scheduler    │      │                  │  - notify() / notifyAll()
  grants CPU   │      │  CPU relinquishes│  - Thread sleep expires
  time slice   ▼      │  control         │  - Lock acquired
             [ RUNNING ] ────────────────┴──┐
               │                            │
               │                            │ - Object.wait()
               │ - Accessing locked block   │ - Thread.join()
               │ - I/O wait                 │ - Thread.sleep(ms)
               ▼                            ▼
          [ BLOCKED ]               [ WAITING / TIMED_WAIT ]
      (Waiting for Monitor lock)    (Sleeping or waiting on conditions)
               │                            │
               └──────────────┬─────────────┘
                              │
                              │ run() exits (or uncaught Exception)
                              ▼
                        [ TERMINATED ]  (Thread completes, dead)

Lifecycle Transition Mechanisms:

  1. NEW: Instantiated but start() not called. Occupies no CPU cycles.
  2. RUNNABLE: Ready for execution. The OS Thread Scheduler decides when the thread transits to RUNNING via time-slicing.
  3. BLOCKED: Suspended while waiting to acquire an **intrinsic monitor lock** held by another thread (e.g. entering a synchronized block).
  4. WAITING: Parked indefinitely due to wait() or join(). Wakes up only when notified.
  5. TIMED_WAITING: Parked for a designated period (e.g., Thread.sleep(1000)). Automatically returns to RUNNABLE when timer expires.
  6. TERMINATED: Finished executing its run() block. Cannot be restarted. Calling start() again throws IllegalThreadStateException.

⚙️ Thread Scheduling, Priorities & Context Switching

  • Context Switching vs. CPU Time-Slicing: Multithreading is often an illusion on single/multi-core CPUs. The OS scheduler allocates brief "time slices" (quantum) to each thread. A **Context Switch** occurs when the CPU saves the state of the active thread (program counter, registers) and loads the state of another thread. High context switching frequency creates system overhead.
  • Thread Priorities: Java supports priority-based preemption. You can assign priorities from Thread.MIN_PRIORITY (1) to Thread.MAX_PRIORITY (10), defaulting to Thread.NORM_PRIORITY (5).
    ⚠️ Platform Dependency Gotcha: Thread priorities are merely "hints" to the host OS. Some operating systems ignore priorities completely or map them differently, meaning your code must never rely on thread priorities for correct execution logic.

🧵 The Main Thread

When a Java program boots, the JVM automatically spawns the **Main Thread** to execute the main() method. It is the root from which all worker/child threads are created. You can access and configure the main thread using static APIs:

Thread t = Thread.currentThread();
System.out.println("Current thread: " + t.getName()); // "main"
t.setPriority(Thread.MAX_PRIORITY);

Thread Synchronization (Monitors & Lock Levels)

MSRIT SEE '24
📖 Definition

Thread Synchronization is an access control mechanism that prevents concurrent operations from corrupting shared mutable state. It guarantees that only one thread can execute a critical section at any given moment, eliminating **race conditions** (data corruption arising from unsynchronized, interleaved execution paths).

🔒 Monitors & Intrinsic Locks (Mutexes)

In Java, synchronization is built around internal entities known as intrinsic locks or monitors. Every single object instantiated in the JVM Heap has an associated monitor lock automatically mapped to it.
When a thread attempts to enter a synchronized method or block, it must first **acquire the object's monitor lock**. If the lock is already held by another thread, the requesting thread is forced to pause execution and enter the BLOCKED state until the holding thread yields the lock.

⚔️ Instance-Level Locks vs. Class-Level Locks

Depending on the synchronization target, the JVM distinguishes between two separate scope-locking layers:

Lock Layer Syntax Context Monitor Lock Target Execution Boundaries
Instance-Level Lock (Object Lock) Non-static synchronized method or synchronized(this) block. Lock is bound to that **specific object instance** on the heap. Different threads can execute synchronized methods on **different object instances** concurrently. Only concurrent access to the *same* instance is blocked.
Class-Level Lock (Static Lock) Static synchronized method or synchronized(MyClass.class) block. Lock is bound to the **Class object** loaded in JVM memory. Strictly blocks **all threads** from executing any static synchronized sections of that class across all instances globally.

🛡️ Two Methods of Synchronization

Java achieves synchronization using monitors (locks) via the synchronized keyword in two contexts:

  1. Synchronized Methods: Declares the entire method scope as locked. It automatically acquires the object's monitor upon entry and releases it upon method completion (normal or exceptional return). 
    synchronized void display(String msg) {
    // Only one thread can execute this method at a time
}
  2. Synchronized Statements (Blocks): Restricts locking to a precise, granular block of statements inside a method. This is far more efficient as it minimizes the critical section size, preventing unnecessary thread stalling. 
    void printData() {
    synchronized(this) {
        // Only one thread can execute this block at a time
    }
}

Inter-Thread Communication & Spurious Wakeups

MSRIT SEE '25
📖 Definition

Inter-Thread Communication is a cooperative signaling architecture allowing synchronized threads to coordinate and exchange state status without CPU-heavy polling (wasteful busy-wait loops). It uses wait(), notify(), and notifyAll() to suspend and resume threads cooperatively.

🔑 The Three Communication Methods

These methods are declared directly inside the root java.lang.Object class (allowing every object to serve as a lock queue target). Crucial Compiler Rule: They **must only be called from within a synchronized context** (method or block), otherwise the JVM throws a runtime IllegalMonitorStateException.

  • wait(): Forces the calling thread to instantly **release its monitor lock atomically** and go to sleep in the object's wait set. It remains suspended until another thread calls notify() or notifyAll() on the same object monitor.
  • notify(): Wakes up a single arbitrary thread waiting on that object's monitor. The woken thread moves back to the RUNNABLE queue but must re-acquire the monitor lock before resuming.
  • notifyAll(): Wakes up all threads waiting on that object's monitor. This is highly recommended over notify() to prevent deadlocks from lost signals.

🚨 The Spurious Wakeup Gotcha: The Golden Loop Check Rule

A waiting thread can occasionally wake up from its wait() state without any explicit notification or interrupt signal. This is a hardware/OS-level optimization side-effect known as a **Spurious Wakeup**.

The Golden Rule of wait()
To guarantee correct program state and prevent spurious wakeups from executing invalid code, you **must always call wait() inside a conditional while-loop**, NEVER a simple if statement!

Correct Condition Check Pattern:

synchronized(lockObj) {
    // ALWAYS check condition inside a loop!
    while (!conditionRealized) {
        lockObj.wait(); // Releases lock, sleeps, and re-checks condition upon wakeup
    }
    // Safe to perform critical operations here
}

Why? If you used an if block, a spurious wakeup would bypass the condition validation and execute subsequent logic even if the condition is still false, leading to index out-of-bounds, null pointers, or direct data corruption.

💡 Why are wait/notify in Object and not in Thread?

Because monitor locks in Java are associated with **Objects**, not individual threads. Since every Java object contains a header capable of acting as a monitor lock, these methods naturally reside in the Object base class to manage object-level lock queues.

Safe Thread Control

📖 Definition

Historically, Java used the suspend(), resume(), and stop() methods of the Thread class to control execution. However, these methods are **deprecated** and must not be used because they are highly unsafe and easily cause **deadlocks**.

🚨 The Deadlock Risk of Deprecated Methods

  • suspend(): Pauses thread execution. **Crucial Gotcha:** The suspended thread keeps all its locks! If the thread holding a lock is suspended, no other thread can ever acquire that lock, causing permanent deadlocks.
  • stop(): Abruptly terminates the thread. This instantly releases all its locks, which can leave shared objects in an inconsistent or corrupted state.

🛡️ Modern, Safe Thread Control Pattern

The correct, modern approach is to use **boolean flags** inside the thread to determine its status. The thread checks these flags periodically, and suspends itself cleanly using wait() or terminates by returning from the run() method:

class SafeThread implements Runnable {
    boolean suspendFlag = false;
    boolean stopFlag = false;

    public synchronized void run() {
        while (!stopFlag) {
            synchronized(this) {
                while (suspendFlag) {
                    wait(); // Safe suspension
                }
            }
        }
    }
    
    public synchronized void mysuspend() { suspendFlag = true; }
    public synchronized void myresume() { suspendFlag = false; notify(); }
    public synchronized void mystop() { stopFlag = true; suspendFlag = false; notify(); }
}

Top 10 Viva/Interview Questions
  • What is the difference between String and StringBuffer? String is immutable (any operation creates a new object). StringBuffer is mutable (modifies in-place) and thread-safe (synchronized methods).
  • What is the String Constant Pool (SCP)? A special memory zone inside the Java Heap designed to store unique string literals, optimizing memory reuse and reducing allocations.
  • What is autoboxing and unboxing? Autoboxing is the automatic translation of primitive values to wrapper classes (e.g. `int` to `Integer`). Unboxing is the reverse (wrapper class to primitive).
  • What is a functional interface? An interface with exactly one abstract method. It acts as the contract signature for Lambda Expressions.
  • What is the purpose of the `@FunctionalInterface` annotation? It tells the compiler to verify that the annotated interface has exactly one abstract method, returning a compilation error if not.
  • How does multithreading improve performance? By allowing concurrent executions of tasks, preventing CPU blocking (e.g. while waiting for I/O operations), and efficiently sharing JVM process memory.
  • What is the difference between Runnable and Thread? Runnable is an interface containing only `run()`. Thread is a concrete class implementing Runnable. Implementing Runnable is preferred because it leaves the class free to inherit from another class.
  • What does the join() method do? It blocks the executing thread (usually the main thread) until the target thread completely finishes its task.
  • Does start() execute synchronously? No. Calling `start()` registers the thread with the OS/JVM scheduler and returns immediately. The thread runs asynchronously when scheduled.
  • What is thread synchronization? A mechanism to prevent multiple threads from accessing shared resources concurrently (race condition), using `synchronized` blocks or methods.
