What is Swing?

📖 Definition

Swing is a lightweight, platform-independent GUI toolkit in Java used to create window-based applications. It is part of Java Foundation Classes (JFC) and is built on top of AWT.

🔑 Key Points

  • Swing classes are in the javax.swing package
  • Swing components are lightweight (don't depend on native OS)
  • Follows MVC (Model-View-Controller) architecture
  • Supports pluggable look and feel — change appearance without changing code
  • All Swing components start with "J" → JFrame, JButton, JLabel, etc.
  • Swing is NOT thread-safe (use SwingUtilities for thread safety)

🌳 Class Hierarchy

java.lang.Object
  └── java.awt.Component
        └── java.awt.Container
              ├── javax.swing.JComponent
              │     ├── JButton
              │     ├── JLabel
              │     ├── JTextField
              │     └── JPanel
              └── java.awt.Window
                    └── java.awt.Frame
                          └── javax.swing.JFrame
💡 Exam Tip

If asked "Why Swing over AWT?" — Answer: Lightweight, platform-independent, more components, pluggable look & feel, MVC support.

📐 Swing MVC Architecture

Swing uses a modified Model-View-Controller (MVC) architecture. Unlike classic MVC where all three components are isolated, Swing uses a Delegated/Component UI Design:

  • Model (State): Represents the data and state of the component (e.g., ButtonModel tracks clicked/enabled states, Document holds text for JTextField).
  • View & Controller (UI Delegate): Swing merges the View and Controller into a single, unified object called a UI Delegate (extending ComponentUI). This delegate renders the component to the screen and intercepts mouse/keyboard events.

This allows Swing to support its famous Pluggable Look and Feel (PLAF). You can change the visual style (View/Controller delegate) at runtime without altering the underlying data structures (Model).

🧵 Event Dispatch Thread (EDT) & Thread Safety

A fundamental rule of Swing development is: Swing components are NOT thread-safe. If multiple threads attempt to edit GUI elements simultaneously, race conditions, visual glitches, or deadlocks will occur.

The Single-Threaded Rule
All GUI-interacting code—including component creation, modifications, layouts, and rendering—must be executed exclusively on a single thread: the Event Dispatch Thread (EDT).

To safely launch a Swing application from the main thread, or update GUI elements from a background/worker thread, you must queue the execution asynchronously on the EDT using SwingUtilities.invokeLater():

// Exam-ready safe Swing program startup template:
public static void main(String[] args) {
    SwingUtilities.invokeLater(new Runnable() {
        @Override
        public void run() {
            // Safely create and display the JFrame here
            JFrame frame = new JFrame("Thread Safe App");
            frame.setDefaultCloseOperation(JFrame.EXIT_ON_CLOSE);
            frame.setSize(300, 200);
            frame.setVisible(true);
        }
    });
}

Swing Layout Managers

MSRIT SEE '24
📖 Definition

A Layout Manager is an interface in AWT/Swing that automatically governs the positioning and sizing of components inside a container. It decodes the layout logic dynamically, ensuring components adjust gracefully when the window is resized.

📐 Core Layout Managers Tour

Swing includes five essential layout managers that you must know for the exam:

1. FlowLayout (Default for JPanel)

Arranges components in a simple, consecutive line (row) from left to right. If a row gets filled, components wrap to the next line. You can specify alignment (left, center, right) and horizontal/vertical spacing.

new FlowLayout()                           // Centered with 5px default gaps
new FlowLayout(FlowLayout.LEFT)            // Left-aligned
new FlowLayout(FlowLayout.RIGHT, 10, 20)   // Right-aligned with custom hGap/vGap

2. BorderLayout (Default for JFrame)

Divides the container into five distinct regions: NORTH, SOUTH, EAST, WEST, and CENTER. Each region can contain only one component. The Center region automatically stretches to consume all remaining space.

new BorderLayout()                         // Default constructor
new BorderLayout(10, 10)                   // Custom hGap/vGap

// Usage: Adding components to specific regions
frame.add(new JButton("Top"), BorderLayout.NORTH);
frame.add(new JButton("Middle"), BorderLayout.CENTER);

3. GridLayout

Positions components inside a rigid grid pattern of equal-sized cells (rows and columns). Each component fills its entire cell boundary. If you resize the container, cells expand proportionally.

new GridLayout(3, 2)                       // 3 rows and 2 columns
new GridLayout(4, 4, 5, 5)                 // 4x4 grid with 5px hGap/vGap

4. BoxLayout

Arranges components sequentially in a single row or single column. Unlike FlowLayout, components do not wrap. It respects the components' maximum sizes and allows alignment control.

// Constructor: requires target container and axis
new BoxLayout(panel, BoxLayout.Y_AXIS)     // Stack components vertically
new BoxLayout(panel, BoxLayout.X_AXIS)     // Align components horizontally

5. GridBagLayout (Highly Flexible)

The most flexible and complex layout manager. It places components in a grid but allows cells to have varying sizes, and components to span multiple columns or rows. Positions are configured using a companion helper object: GridBagConstraints.

GridBagLayout gridbag = new GridBagLayout();
GridBagConstraints c = new GridBagConstraints();
panel.setLayout(gridbag);

// GridBagConstraints Parameters to write in Exam:
c.gridx = 0;      // Column index (starting at 0)
c.gridy = 1;      // Row index (starting at 0)
c.gridwidth = 2;  // Number of columns to span
c.gridheight = 1; // Number of rows to span
c.weightx = 1.0;  // Horizontal space distribution ratio
c.weighty = 0.0;  // Vertical space distribution ratio
c.fill = GridBagConstraints.HORIZONTAL; // Fill constraint (HORIZONTAL, VERTICAL, BOTH, NONE)
c.insets = new Insets(5, 5, 5, 5);       // Padding margins (top, left, bottom, right)
c.anchor = GridBagConstraints.CENTER;   // Alignment inside grid cell

panel.add(button, c);

📊 Layout Managers Comparison

Layout Manager Default for Arrangement Flow Component Resizing Behaviour
FlowLayout JPanel Consecutive rows (left to right, wrapping). Keeps components at preferred size.
BorderLayout JFrame, JDialog 5 fixed regions (North, South, East, West, Center). Stretches components to fill region bounds. Center fills remainder.
GridLayout None Rigid 2D cell grid (rows × columns). Forces all components to have equal, uniform size.
BoxLayout None Single row (X_AXIS) or single column (Y_AXIS). Attempts to keep preferred size; respects max size.
GridBagLayout None Dynamic cell grid of varying heights/widths. Highly customizable via GridBagConstraints.

💡 Setting the Layout Manager

To apply a layout manager to a JFrame or JPanel, use the setLayout() method. Passing null selects Absolute Positioning, requiring you to define sizes manually via setBounds(x, y, w, h).

panel.setLayout(new GridLayout(2, 2)); // Applies grid layout
frame.setLayout(null);                 // Enables absolute positioning bounds

Event Handling

📖 Definition

Event Handling is the mechanism to control events (like button click, mouse move, key press) and decide what should happen when an event occurs.

🧩 Key Concepts

  • Event → An object that describes a state change (e.g., button clicked)
  • Event Source → The component that generates the event (e.g., JButton)
  • Event Listener → The interface that receives and handles the event (e.g., ActionListener)
  • Event Handler → The method that contains the code to execute (e.g., actionPerformed())

🔄 Event Handling Flow (Delegation Event Model)

User Action (click)
      │
      ▼
Event Source (JButton)
      │
      ├── Creates Event Object (ActionEvent)
      │
      ▼
Sends to Registered Listener (ActionListener)
      │
      ▼
Executes Handler Method → actionPerformed(ActionEvent e)

📋 Steps to Handle Events

  • Step 1: Implement the listener interface → implements ActionListener
  • Step 2: Register the component → button.addActionListener(this)
  • Step 3: Override the handler method → actionPerformed(ActionEvent e)

📊 Common Event Classes & Listeners

Event ClassListener InterfaceKey Method
ActionEventActionListeneractionPerformed(ActionEvent e)
MouseEventMouseListenermouseClicked(), mousePressed()
KeyEventKeyListenerkeyPressed(), keyReleased()
ItemEventItemListeneritemStateChanged(ItemEvent e)
WindowEventWindowListenerwindowClosing(), windowOpened()
💡 Viva Favorite

"What is Delegation Event Model?" → A model where the event source (component) delegates the event handling to a separate listener object. The source generates events, the listener handles them.

ActionListener Interface

📖 Definition

ActionListener is a functional interface in java.awt.event package used to handle action events like button clicks. It has only ONE method: public void actionPerformed(ActionEvent e)

1️⃣ Way 1: Implementing the Interface

public class MyApp extends JFrame implements ActionListener {
    JButton btn = new JButton("Click");

    MyApp() {
        btn.addActionListener(this);  // REGISTER
        add(btn);
    }

    public void actionPerformed(ActionEvent e) {
        // handle event
    }
}

2️⃣ Way 2: Anonymous Inner Class

btn.addActionListener(new ActionListener() {
    public void actionPerformed(ActionEvent e) {
        // handle event
    }
});

3️⃣ Way 3: Lambda Expression (Java 8+)

btn.addActionListener(e -> {
    // handle event
});

📋 Important ActionEvent Methods

MethodDescription
getSource()Returns the object that generated the event
getActionCommand()Returns the command string (button text)
 
// When you have multiple buttons:
public void actionPerformed(ActionEvent e) {
    if (e.getSource() == btn1) {
        // btn1 was clicked
    } else if (e.getSource() == btn2) {
        // btn2 was clicked
    }
}
💡 Viva Question

"Why is ActionListener a functional interface?" → Because it has exactly ONE abstract method (actionPerformed), so it can be used with lambda expressions.

⭐ Program 1: Even/Odd GUI Checker

🔴 PYQ — 5 marks

Logic: Take a number from JTextField → On button click → Check if even or odd → Display result in JLabel.

Imports: javax.swing.*, java.awt.event.*

import javax.swing.*;
import java.awt.event.*;

public class EvenOddChecker extends JFrame implements ActionListener {
    JTextField tf;
    JButton btn;
    JLabel resultLabel;

    EvenOddChecker() {
        setTitle("Even/Odd Checker");
        setLayout(null);

        JLabel inputLabel = new JLabel("Enter a number:");
        inputLabel.setBounds(30, 30, 150, 30);
        add(inputLabel);

        tf = new JTextField();
        tf.setBounds(180, 30, 150, 30);
        add(tf);

        btn = new JButton("Check");
        btn.setBounds(120, 80, 100, 35);
        btn.addActionListener(this);
        add(btn);

        resultLabel = new JLabel("Result will appear here");
        resultLabel.setBounds(80, 130, 250, 30);
        add(resultLabel);

        setSize(400, 250);
        setDefaultCloseOperation(JFrame.EXIT_ON_CLOSE);
        setLocationRelativeTo(null);
        setVisible(true);
    }

    public void actionPerformed(ActionEvent e) {
        String input = tf.getText();
        int num = Integer.parseInt(input);

        if (num % 2 == 0) {
            resultLabel.setText(num + " is EVEN");
        } else {
            resultLabel.setText(num + " is ODD");
        }
    }

    public static void main(String[] args) {
        new EvenOddChecker();
    }
}
📤 Output
Enter 4 → Click "Check" → Shows "4 is EVEN"
Enter 7 → Click "Check" → Shows "7 is ODD"
🎤 Expected Viva Questions
  1. What happens if user enters text instead of number? → NumberFormatException
  2. How to handle that? → Use try-catch block
  3. What is setBounds()? → Sets position (x, y) and size (width, height)
  4. Why setLayout(null)? → To use absolute positioning with setBounds()

⭐ Program 5: Swing Layout Managers Demo (Nested BorderLayout, FlowLayout, GridLayout)

MSRIT SEE '24

Logic: A single premium window combining BorderLayout (main frame) with nested FlowLayout (North) and GridLayout (Center) panels. Demonstrates dynamic component resizing and standard button-click event handling.

Imports: javax.swing.*, java.awt.*, java.awt.event.*

import javax.swing.*;
import java.awt.*;
import java.awt.event.*;

public class LayoutDemoApp extends JFrame {
    LayoutDemoApp() {
        setTitle("Swing Layout Managers Demo");
        setSize(600, 400);
        setDefaultCloseOperation(JFrame.EXIT_ON_CLOSE);
        
        // 1. Main frame uses BorderLayout with gaps
        setLayout(new BorderLayout(10, 10));
        
        // 2. North panel uses FlowLayout (flow of items row-wise)
        JPanel northPanel = new JPanel(new FlowLayout(FlowLayout.CENTER, 15, 5));
        northPanel.setBorder(BorderFactory.createTitledBorder("FlowLayout Panel (North)"));
        northPanel.add(new JButton("Flow 1"));
        northPanel.add(new JButton("Flow 2"));
        northPanel.add(new JButton("Flow 3"));
        
        // 3. Center panel uses GridLayout (equal-sized cells in a grid)
        JPanel centerPanel = new JPanel(new GridLayout(2, 2, 8, 8));
        centerPanel.setBorder(BorderFactory.createTitledBorder("GridLayout Panel (Center 2x2)"));
        centerPanel.add(new JButton("Grid Cell A"));
        centerPanel.add(new JButton("Grid Cell B"));
        centerPanel.add(new JButton("Grid Cell C"));
        centerPanel.add(new JButton("Grid Cell D"));
        
        // 4. West and East buttons for BorderLayout Demo
        JButton westBtn = new JButton("West (Border)");
        JButton eastBtn = new JButton("East (Border)");
        
        // 5. South status label
        JLabel statusLabel = new JLabel("Click any button to see layout source!", SwingConstants.CENTER);
        statusLabel.setPreferredSize(new Dimension(600, 30));
        
        // Event handler to show which button in which layout was clicked
        ActionListener btnListener = new ActionListener() {
            public void actionPerformed(ActionEvent e) {
                JButton src = (JButton) e.getSource();
                statusLabel.setText("Action Triggered! Clicked: " + src.getText());
            }
        };
        
        // Register action listener to all buttons
        for (Component c : northPanel.getComponents()) {
            if (c instanceof JButton) ((JButton) c).addActionListener(btnListener);
        }
        for (Component c : centerPanel.getComponents()) {
            if (c instanceof JButton) ((JButton) c).addActionListener(btnListener);
        }
        westBtn.addActionListener(btnListener);
        eastBtn.addActionListener(btnListener);
        
        // 6. Add components to respective BorderLayout regions
        add(northPanel, BorderLayout.NORTH);
        add(centerPanel, BorderLayout.CENTER);
        add(westBtn, BorderLayout.WEST);
        add(eastBtn, BorderLayout.EAST);
        add(statusLabel, BorderLayout.SOUTH);
        
        setLocationRelativeTo(null);
        setVisible(true);
    }

What is JDBC?

📖 Definition

JDBC (Java Database Connectivity) is a Java API that allows Java programs to connect to and interact with databases. It provides methods to query, insert, update, and delete data.

🔑 Key Points

  • JDBC is part of java.sql package
  • It is database-independent — same code works with MySQL, Oracle, PostgreSQL
  • Uses drivers to connect to specific databases
  • Follows a standard set of interfaces that database vendors implement
  • Supports SQL queries for CRUD operations
💡 Exam One-liner

"JDBC is a Java API that provides a standard interface for connecting Java applications to relational databases."

Types of JDBC Drivers

Driver Type & Name Architecture & How it Works Pros (Advantages) Cons (Disadvantages)
Type 1: JDBC-ODBC Bridge Translates JDBC calls into ODBC calls. Relies on local native ODBC drivers installed on the client machine.
  • Easy database connection check.
  • Allows access to almost any DB with an ODBC driver.
  • Slowest speed (double translation).
  • Requires ODBC installation on client.
  • Deprecated since Java 8.
Type 2: Native-API (Part-Java, Part-Native) Translates JDBC calls into database-specific client-side native API calls (e.g., Oracle OCI, MySQL C-client library).
  • Faster performance than Type 1.
  • Uses native OS optimization.
  • Requires client database libraries installed.
  • Not platform-independent.
Type 3: Network Protocol (Middleware Driver) Translates JDBC calls into a generic database-independent network protocol. A middle tier middleware server translates it to specific DB protocols.
  • No database-specific client install.
  • Middleware can handle security, logging, auditing.
  • Requires an active middleware server.
  • Extra network hop increases latency.
Type 4: Thin Driver (Pure Java Driver) ✅ Converts JDBC calls directly into vendor-specific database network protocols (sockets) in pure Java. Communicates directly with DB server.
  • Fastest performance.
  • Zero client-side installs (packaged in jar).
  • Pure Java, platform independent.
  • Driver is database-specific; must load a different jar for MySQL vs Oracle.
💡 Exam Tip

Type 4 (Thin Driver) is most commonly used and most asked! MySQL's com.mysql.cj.jdbc.Driver is Type 4. Type 1 is deprecated (removed in Java 8+).

💼 JDBC Transaction Management (ACID)

By default, JDBC connections operate in Auto-Commit Mode (con.setAutoCommit(true)), meaning each SQL statement is executed and committed to the database immediately as an isolated unit. However, real-world scenarios (like a bank transfer) require multiple statements to succeed or fail together as a single atomic transaction.

Transaction Management Workflow
To group multiple queries into a single atomic transaction:
  1. Disable Auto-Commit: con.setAutoCommit(false);
  2. Execute Operations: Perform multiple database updates.
  3. Commit Changes: If all statements execute successfully, commit them permanently: con.commit();
  4. Rollback on Failure: If any statement fails (throws SQLException), catch it and revert all modifications: con.rollback();

Here is an exam-ready, complete transaction management block illustrating a secure money transfer between accounts:

Connection con = null;
PreparedStatement withdraw = null;
PreparedStatement deposit = null;
try {
    con = DriverManager.getConnection(URL, USER, PASS);
    
    // Step 1: Turn off auto-commit
    con.setAutoCommit(false);
    
    // Step 2: Perform withdraw and deposit queries
    withdraw = con.prepareStatement("UPDATE accounts SET bal = bal - ? WHERE acc_no = ?");
    withdraw.setDouble(1, 5000.00);
    withdraw.setInt(2, 101);
    withdraw.executeUpdate();
    
    deposit = con.prepareStatement("UPDATE accounts SET bal = bal + ? WHERE acc_no = ?");
    deposit.setDouble(1, 5000.00);
    deposit.setInt(2, 102);
    deposit.executeUpdate();
    
    // Step 3: Commit both queries together
    con.commit();
    System.out.println("Transaction committed successfully!");
    
} catch (SQLException e) {
    System.out.println("Transaction failed! Rolling back changes...");
    try {
        if (con != null) {
            // Step 4: Revert all changes on exception
            con.rollback(); 
        }
    } catch (SQLException ex) {
        ex.printStackTrace();
    }
} finally {
    // Close resources safely
    try {
        if (withdraw != null) withdraw.close();
        if (deposit != null) deposit.close();
        if (con != null) con.close();
    } catch (SQLException e) {
        e.printStackTrace();
    }
}
🚨 Important

Always close in reverse order: ResultSet → Statement → Connection. Or better: use try-with-resources!

⚙️ Pre-Compilation & Security Mechanics

1. Pre-Compilation Mechanics: Under the hood, when you call con.prepareStatement(SQL), the database server parses, compiles, and optimizes the SQL query skeleton once, caching the execution plan. When you invoke setInt() or setString(), only the parameter values are passed down. The DB plugs these values directly into the cached execution plan. This eliminates compilation overhead for repeated queries, providing massive performance boosts.

2. SQL Injection Prevention: In a regular Statement, user inputs are concatenated directly into the query string, allowing malicious users to inject SQL syntax commands (e.g., entering admin' OR '1'='1 as a username to bypass authentication). In a PreparedStatement, the placeholders (?) treat the bound parameters strictly as literal data values rather than executable SQL code. Any quotes or semicolons in the input are automatically escaped by the driver, rendering the SQL injection attack completely harmless.

🔍 Complete SQL Injection Security Comparison

Scenario: Attacker inputs username as: admin' OR '1'='1
❌ Statement (Vulnerable to Attack)
Statement stmt = con.createStatement();
String sql = "SELECT * FROM users WHERE name='" + input + "'";
ResultSet rs = stmt.executeQuery(sql);

// Compiled SQL executed by Database:
SELECT * FROM users WHERE name='admin' OR '1'='1';
// Result: '1'='1' is always TRUE. 
// Attacker logs in successfully without password!
✅ PreparedStatement (Secure Prevention)
PreparedStatement pstmt = con.prepareStatement(
    "SELECT * FROM users WHERE name=?"
);

ResultSet rs = pstmt.executeQuery();

// Compiled SQL executed by Database:
SELECT * FROM users WHERE name="admin' OR '1'='1";
// Result: Database searches for a user whose 
// actual username matches that literal string. 
// Safe login check!

        Scanner sc = new Scanner(System.in);

        try {
            // Step 1: Load Driver
            Class.forName("com.mysql.cj.jdbc.Driver");

            // Step 2: Establish Connection
            Connection con = DriverManager.getConnection(
                "jdbc:mysql://localhost:3306/product_db",

            System.out.print("Enter Price: ");

            System.out.print("Enter Quantity: ");

            if (rowsInserted > 0) {
                System.out.println("Product inserted successfully!");
            }

            // Step 5: Close
            pstmt.close();
            con.close();
            sc.close();

        } catch (ClassNotFoundException e) {
            System.out.println("Driver not found: " + e.getMessage());
        } catch (SQLException e) {
            System.out.println("SQL Error: " + e.getMessage());
